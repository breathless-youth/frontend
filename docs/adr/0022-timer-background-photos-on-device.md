# 0022. 타이머 배경 사진은 기기에만 둔다

- Status: Accepted
- Date: 2026-11-10
- Relates to: [타이머 배경 설정 설계](../superpowers/specs/2026-11-10-BY-1222-timer-background-design.md), [ADR 0013](./0013-timelapse-photo-storage-exception.md), [ADR 0019](./0019-android-profile-photo-native-picker.md)

## 배경

타이머 배경은 사용자가 앨범에서 고른 사진을 싱글룸 공부 화면 뒤에 깐다. 카메라가 찍은 프레임이 아니라 사용자가 고른 사진이라 개인정보 원칙의 카메라 원본 금지 대상은 아니다. 그래도 사진에는 얼굴이나 집 안처럼 민감한 내용이 담길 수 있어서 어디에 두고 어디로 보내는지를 정해 둔다. 설정 화면과 세션 화면은 다른 웹뷰라 두 화면이 같은 사진을 읽을 수 있어야 한다.

## 결정

### 보관

- 사진은 긴 변 1920px JPEG로 줄여 기기 IndexedDB(`focusmakers-timer-background`)에만 저장하고 원본은 저장하지 않는다.
- 사진은 10장까지 담고, 사용자가 ×로 삭제하면 바로 지운다.
- 고른 배경은 이 기기의 localStorage에 저장하고 서버와 다른 기기로 보내지 않는다.
- 사진의 크기·위치 조정값은 사진과 같은 IndexedDB 레코드에 둔다.
- 타임랩스 사진처럼 iOS 웹뷰가 Blob을 믿을 만하게 보관하지 못해 ArrayBuffer로 둔다.

### 전송

- 사진은 서버와 분석 도구로 보내지 않는다. 분석 이벤트에는 담은 개수와 고른 경로만 싣는다.
- 사진을 그리는 이미지에는 세션 리플레이 차단 표식(`amp-block sentry-block`)을 붙인다.

### Android 사진 읽기

- ADR 0019의 앱 선택기 모듈에 `pickBackground()`를 더한다. 자르지 않고 긴 변 1920px JPEG(품질 80) base64와 그 크기를 돌려준다.
- 웹은 `pick-background-photo`를 보내고 앱은 같은 `id`의 `background-photo-result`로 답한다.
- 프로필 선택기만 든 옛 바이너리와 구분하려고 앱은 이 함수가 있을 때만 웹뷰 URL에 `backgroundPhotoPicker=1`을 붙인다.
- 표시가 없는 옛 Android 앱과 iOS, 브라우저는 웹 파일 입력으로 고르고 웹이 같은 크기로 줄인다.

## 검토한 대안

- 서버에 올려 기기 사이에 맞추는 방식은 민감할 수 있는 사진을 서버에 남기고, 로그인하지 않은 사용자는 쓸 수 없어 택하지 않았다.
- 원본을 그대로 저장하는 방식은 카메라 사진 한 장이 10MB를 넘어 10장이면 기기 저장 공간을 크게 쓰고 세션 화면이 읽는 데도 느려 택하지 않았다.
- 프로필 사진 메시지에 용도만 더하는 방식은 그 용도를 모르는 옛 앱이 512px 정사각형을 돌려줘 배경이 깨지므로 택하지 않았다.

## 결과

- 앱을 지우거나 웹뷰 데이터를 지우면 담은 사진도 함께 사라진다.
- 같은 계정이라도 기기마다 배경을 따로 고른다.
- 1920px JPEG의 base64는 수백 KB라 브리지 메시지 하나로 보내는 가장 큰 경우다. 실기기에서 전달 시간을 확인한다.

# 0018. 웹뷰 화면의 Liquid Glass는 웹이 선언하고 앱이 네이티브 뷰로 그린다

- Status: Accepted
- Date: 2026-10-22
- Relates to: [BY-957 웹뷰 화면에 iOS 26 Liquid Glass 적용 설계](../superpowers/specs/2026-10-22-BY-957-liquid-glass-design.md), [BY-965 세션 화면 Liquid Glass 설계](../superpowers/specs/2026-10-23-BY-965-session-liquid-glass-design.md), [ADR 0001](./0001-webview-based-study-room-architecture.md), [ADR 0015](./0015-timelapse-direct-share-local-module.md)

## 배경

iOS 26에서 시스템 Liquid Glass가 그려지는 곳은 하단 탭 바(`NativeTabs`) 하나였다. 뒤로 가기, 세그먼트, 스위치, 버튼은 모두 웹뷰 안의 HTML이라 glass를 입힐 수 없었다. WKWebView 안에서 시스템 glass를 그리는 공개 API는 없었다. WebKit의 `-apple-visual-effect`는 비공개 API `_setUseSystemAppearance`를 켜야 동작해서, 공개 API만 허용하는 App Store 심사 지침 2.5.1에 걸린다. CSS로 흉내 내려 해도 Safari가 굴절 표현에 필요한 `backdrop-filter: url()`을 지원하지 않았다. 그래서 진짜 glass는 웹뷰 밖의 네이티브 뷰로만 만들 수 있다고 판단했다.

뒤로 가기 헤더(`ScreenBackHeader`)가 스크롤을 따라 화면 밖으로 사라지는 문제도 함께 다뤘다.

## 결정

화면에 고정되는 요소는 웹뷰 위에 겹친 떠 있는 층이 그리고, 본문에 있는 요소는 그 자리에 붙인 네이티브 부품으로 바꾼다. 하단 CTA와 기간 이동 줄은 실기기 검토 뒤 사용자 결정으로 기존 웹 디자인을 유지한다. 화면 구현은 계속 `apps/web`에 있고 앱은 웹이 선언한 모양만 그린다. 앱은 누름을 받으면 `native-control-press`로 웹에 알리고, 그 뒤 동작은 웹의 처리기가 맡는다.

### 떠 있는 층

- 웹은 뒤로 가기·닫기 버튼과 가운데 제목을 `GlassChrome`으로 선언한다.
- 플래너는 제목 대신 웹의 날짜 이동 줄(`PeriodNav`)을 `center`로 넘기고, 웹이 이 줄을 두 모드 모두 위쪽 고정 줄 가운데에 그린다.
- `center`가 있는 화면에서 앱 모드의 떠 있는 층은 뒤로 버튼만 그린다.
- 앱이 `glassChrome` 표시를 붙였으면 웹은 그 자리를 비우고 `set-glass-chrome`을 보내며, 앱의 `GlassChromeOverlay`가 `@expo/ui`로 그린다.
- 화면 전환 중에 `GlassChrome`이 둘 놓일 수 있어서 웹은 요소마다 선언을 따로 두고, 하나가 사라지면 남은 쪽을 다시 보낸다.
- 표시가 없으면 웹이 같은 배치의 CSS glass 고정 바를 그린다.
- 위쪽 가장자리 흐림은 두 경우 모두 웹 CSS가 그린다.
- 하단 CTA는 떠 있는 층에 넣지 않고 모든 화면에서 기존 웹 버튼으로 그린다.

### 그 자리 부품

- 세그먼트·스위치·버튼은 `useNativeControl`로 문서 좌표, 상태, 라벨을 등록한다.
- 세그먼트는 기록 탭의 일간·주간, 랭킹의 종목과 기간, 타임랩스 설정의 영상 비율, 랭킹 기록 화면의 순위 칩에 쓴다.
- 스위치는 설정 행 스위치(`SwitchRow`)와 설정 탭의 카메라 권한 표시 토글(`PermissionToggle`)에 쓴다.
- 버튼은 홈·기록 탭의 플래너 원형 버튼, 랭킹의 메달 버튼, 수동 기록의 길이 칩에 쓴다.
- 버튼은 SF Symbol 대신 앱에 포함된 이미지 이름(`image`)을 받을 수 있어서, 플래너 원형 버튼은 웹 플래너 아이콘을 렌더한 템플릿 PNG를 `web-glass` 리소스 번들에 넣어 웹과 같은 그림을 그린다.
- 버튼은 `disabled`를 받아서 수동 기록 길이 칩이 막힌 상태를 앱 부품도 흐리게 보인다.
- 앱 모드에서 웹 원본은 자리를 유지한 채 보이지 않게 하고 스크린리더에서도 뺀다.
- 로컬 Expo 모듈 `web-glass`가 `UISegmentedControl`, `UISwitch`, glass `UIButton`을 `WKWebView.scrollView` 안의 부품 층에 문서 좌표로 붙인다.
- 부품이 스크롤뷰 안에 있어 스크롤은 네이티브가 함께 움직이고, 웹은 레이아웃이 바뀔 때만 부품 목록 전체를 다시 보낸다.
- 웹 원본이 넓혀 둔 누름 영역은 원본과 함께 숨겨지므로, 네이티브 부품은 가운데 기준 44pt 안의 누름을 받는다.
- 설정 탭의 카메라 권한 토글처럼 모양만 보이는 스위치는 누름을 받지 않고 VoiceOver에서도 빠져서, 누름과 읽기가 모두 아래 웹 행으로 간다.
- `UISwitch`는 크기를 바꿀 수 없어서 웹 자리의 끝 쪽 가장자리에 맞추고 세로만 가운데에 둔다.
- 네이티브 부품의 색은 디자인 토큰의 라이트·다크 값을, 글꼴은 Pretendard를 쓴다.

### 켜는 조건

- 앱은 iOS이고 `web-glass` 모듈이 있으며 `isLiquidGlassAvailable()`이 참일 때만 웹뷰 URL에 `glassChrome`과 `glassControls`를 붙인다.
- `glassChrome`의 값은 앱이 그릴 수 있는 고정 요소 모양의 버전이고 지금은 `1`이다.
- `glassControls`의 값은 Swift가 그리는 본문 부품 종류를 쉼표로 이은 목록이고 지금은 `segment,switch,button`이다.
- 목록 끝의 `button-style`은 부품 종류가 아니라 앱이 버튼 색 역할(`tone`), 아이콘 크기(`iconSize`), 회전 수(`turns`), 부품 흐림(`faded`), 층 테마 고정(`colorScheme`)을 그린다는 표시다.
- 앱은 같은 Swift에서 생긴 `setInlineColorScheme`이 있는 바이너리에만 `button-style`을 붙여서, 이전 Dev Client에 새 JS가 실려도 표시를 잘못 알리지 않는다.
- 웹 `useNativeControl`은 이 필드를 쓰는 부품을 `button-style`이 있을 때만 앱에 맡기고, 없으면 웹 원본을 그린다.
- 원격 웹은 구버전 앱에도 바로 배포되므로, 네이티브에 의존하는 웹 동작은 모두 이 표시가 있을 때만 켠다.
- 같은 URL을 브라우저로 열면 브리지가 없으므로 웹은 표시가 있어도 CSS로 그린다.
- 웹은 알린 버전과 목록 안의 모양과 종류만 앱에 맡기고 나머지는 CSS나 웹 원본으로 그린다(앱이 모르는 것을 보내면 웹 원본은 숨었는데 앱은 메시지를 버려서 화면에서 사라진다).
- 고정 요소에 새 모양을 더하면 앱의 `glassChrome` 버전을 올리고 웹이 그 버전을 확인한다.
- 본문 부품에 새 종류를 더하면 앱의 지원 목록(`SUPPORTED_INLINE_KINDS`)에 넣는다.
- `web-glass`에 새로 더한 네이티브 함수는 래퍼가 `?.`로 불러서, 그 함수가 없는 이전 Dev Client에서는 아무 일도 하지 않는다.
- 개발 빌드는 `apps/mobile/.env.local`에 `GLASS_CHROME_OFF=1`이 있으면 두 표시를 붙이지 않아 같은 기기에서 CSS 대체 화면을 볼 수 있다.
- production과 staging 빌드는 이 값을 무시한다.

### 메시지 처리와 숨김

- 두 층은 웹뷰마다 따로 있으므로 `RemoteWebViewHost`가 `set-glass-chrome`·`set-inline-controls`를 소비하고 화면 쪽 처리기로 넘기지 않는다(`HostConsumedType`).
- 호스트는 새 문서 세대(재시도, 렌더러 사망 복구), iOS 최상위 프레임 로드 시작, 언마운트 때 두 층을 비운다.
- 네이티브 뷰는 항상 웹보다 위에 그려지므로, 웹 시트나 대화상자가 열린 동안(`useModalOverlayOpen()`)은 웹이 알려 두 층을 모두 숨긴다.
- 페이지 전환 애니메이션 중에는 웹이 알려 그 자리 부품을 숨긴다.

### 뒤로 가기 스와이프

- 떠 있는 층은 웹뷰 밖에 있어 WKWebView의 가장자리 스와이프와 함께 밀려나지 않는다.
- 따로 처리하지 않으면 밀려 들어오는 이전 화면 위에 지금 화면의 뒤로 버튼과 제목이 남는다.
- 그래서 `web-glass`가 웹뷰의 뒤로 가기 쪽 가장자리 인식기에 대상을 붙여 진행을 알리고, 호스트가 iOS 내비게이션 바처럼 진행만큼 층을 흐리게 한다.
- 층을 스와이프와 함께 밀어내는 방식 대신 흐려지는 방식을 쓰는 것은 실기기 검토 뒤 사용자가 정했다.
- 손을 뗀 뒤 이동할지는 WebKit이 알려 주지 않아서, 호스트는 잠시 안에 이동이 오면 새 화면이 알릴 때까지 층을 내리고 오지 않으면 다시 보인다.
- 본문의 그 자리 부품은 스크롤뷰 안에 있어 스냅샷과 함께 움직인다.

### 세션 화면

- 싱글룸 세션 화면(`RoomPage`)은 문서가 스크롤되지 않는 전체 화면이라 `absolute`로 놓인 버튼도 그 자리 부품으로 바꾼다.
- 배경음, 과목, 타이머 진입, 일시정지·다시 시작, 종료 버튼을 원형 glass 버튼으로 그리고, 상태 표시 필과 과목 라벨과 타이머는 누를 수 없거나 흐름 배치라 웹으로 남긴다.
- 카메라 전환은 라이브룸과 같은 오른쪽 위 더보기 메뉴 안에 있고, 더보기 버튼과 메뉴는 웹으로 그린다.
- 더보기 메뉴가 열린 동안 웹 버튼은 `inert`로, 앱 버튼은 `disabled`로 누름을 막는다.
- 색은 웹 색을 그대로 써서 다시 시작은 `prominent`(파란 채움), 종료는 `danger`(빨간 아이콘), 켜진 배경음과 고른 과목은 `active`(강조색 아이콘)이고, 색 값은 호스트가 팔레트로 넘긴다.
- 아이콘은 SF Symbol이고 웹은 버튼 안 아이콘의 CSS 폭을 측정해 `iconSize`로 보낸다.
- SF Symbol이 같은 크기의 웹 아이콘보다 커 보여서, 실기기 검토 뒤 사용자 요청으로 종료·배경음·과목·타이머는 측정 폭의 0.82배(`iconScale`)로 보낸다.
- 같은 검토에서 하단 일시정지·종료 버튼은 웹 버튼까지 한 단계 키웠다(지름 60/72/88px, 아이콘 26/30/38px).
- 일시정지와 다시 시작은 아이콘 교체 효과로 웹 애니메이션을 대신한다.
- 간단 모드에서 일시정지를 뺀 버튼은 `faded`로 보내고, 앱은 0.2초 동안 투명도를 0으로 낮춘다.
- 투명도가 0인 뷰는 UIKit이 누름 판정에서 빼서, 숨은 동안의 누름은 아래 웹의 간단 모드 전환으로 간다.
- 동작 줄이기가 켜져 있으면 투명도는 움직임 없이 바로 바뀐다.
- 세션 루트는 `theme-dark`라 항상 다크이고, 웹은 `theme-dark` 안에 등록된 부품이 있으면 `colorScheme: "dark"`를 보내 앱이 그 웹뷰의 부품 층 전체를 다크로 그린다.
- 라이브룸 하단 조작 바는 카메라, 과목, 배경음, 나가기 버튼을 glass로 그리고, 바 배경과 오른쪽 위 더보기 버튼·메뉴는 웹으로 남긴다.
- 바가 transform 전환으로 미끄러지는 동안 웹은 매 프레임 좌표를 다시 재서 보내고, 앱 버튼은 그 좌표를 따라 바와 함께 움직인다.
- 바가 숨으면 앱 버튼도 `faded`로 흐려져, 화면 밖으로 나간 바 자리의 누름을 받지 않는다.
- 더보기 메뉴가 열린 동안 웹 바의 `pointer-events-none`은 앱 층에 닿지 않아서, 앱 버튼은 `disabled`로 막는다.
- 시트와 대화상자 안 컨트롤은 모달이 열리면 네이티브 부품을 모두 숨기는 구조라 이 방식으로 바꾸지 않는다.

## 실측 근거

iOS 26.5 시뮬레이터와 iPhone 13 mini(iOS 26)에서 스파이크로 확인했다.

| 확인한 것                                    | 결과                                                                                                |
| -------------------------------------------- | --------------------------------------------------------------------------------------------------- |
| 떠 있는 층 아래 본문이 굴절돼 보이는가       | 스크롤 중 본문 글자가 glass 가장자리에서 휘어 보였다                                                |
| 떠 있는 층의 누름이 웹에 닿는 시간           | 0~2ms                                                                                               |
| 그 자리 부품이 스크롤 중 어긋나는가          | 녹화 프레임에서 웹 글자와의 간격이 214px로 유지됐다                                                 |
| 그 자리 부품의 누름이 웹에 닿는 시간(실기기) | 스위치 2.7에서 3.0ms, 세그먼트 0.1에서 7ms                                                          |
| 단색 배경 위 그 자리 glass                   | 멈춘 화면에서는 CSS와 구분하기 어려웠지만, 사용자는 실기기에서 시스템 부품의 생김새를 가장 선호했다 |

- iOS 26.5 시뮬레이터에서 웹뷰 안 재생 중인 파일 영상과 MediaStream 영상 위에 glass 버튼을 올렸을 때 두 경우 모두 영상 색이 glass에 비쳤고, 두 번 찍은 화면의 glass 안쪽 PSNR이 파일 48.87dB, MediaStream 14.60dB로 서로 달라 영상이 바뀌는 대로 glass 색도 바뀌었다.
- 이때 MediaStream은 `canvas.captureStream()`으로 만든 스트림이라, `getUserMedia` 카메라 영상 위 glass는 실기기에서 확인한다.

## 검토한 대안

- **CSS만으로 그리기**: 네이티브 코드가 필요 없지만 Safari에 `backdrop-filter: url()`이 없어 굴절을 만들 수 없고 흐림과 반투명만 남는다.
- **WebKit `-apple-visual-effect`**: 웹 코드만으로 시스템 재질을 쓸 수 있지만 비공개 API `_setUseSystemAppearance`를 켜야 해서 심사 지침 2.5.1로 반려될 위험이 있다.
- **모두 떠 있는 층으로 그리기**: 한 방식으로 통일되지만 세그먼트를 화면에 고정하면 기록·랭킹 탭 위에 없던 고정 바가 생기고, 실기기에서 비교했을 때 사용자는 본문 자리에 놓인 시스템 부품을 더 선호했다.
- **모두 그 자리 부품으로 그리기**: 모듈 하나로 끝나지만 스크롤뷰 안 뷰는 본문과 함께 움직여서, 고정 요소는 스크롤할 때마다 위치를 다시 맞춰야 하고 그동안 늦게 따라온다.

## 실기기 검토 뒤 되돌린 것

처음 구현은 하단 CTA, 기간 이동 줄, 결과 화면의 버튼 일부까지 네이티브로 그렸다. 실기기에서 써 본 뒤 사용자가 CTA와 기간 이동 줄은 기존 웹 디자인을 유지하기로 정해서 아래 항목을 되돌렸다.

- 수동 기록, 프로필, 초대코드 공유·입력, 결과 화면의 하단 CTA를 떠 있는 층에 그리던 경로를 삭제하고 모두 기존 웹 버튼으로 되돌렸다.
- 키보드가 열리면 하단 CTA를 숨기던 처리도 이 경로와 함께 삭제했다.
- 플래너 위쪽 줄의 네이티브 날짜 캡슐을 삭제하고, 웹의 `PeriodNav`를 위쪽 고정 줄 가운데에 그리게 했다.
- 기록 탭의 달·주 이동 줄을 그리던 그 자리 부품 종류 `period`를 삭제하고 기존 웹 모양으로 되돌렸다.
- 결과 화면의 인터뷰 안내 카드 X와 타임랩스 카드의 재생·일시정지 버튼을 기존 웹 버튼으로 되돌렸다.
- 결과 화면에 네이티브 부품이 남지 않아서, 페이지 스크롤로 바꿨던 구조를 안쪽 스크롤 상자와 아래에 고정한 웹 CTA를 쓰는 dev 브랜치 구조로 되돌렸다.

## 결과와 제약

### 대체 화면

- Android, iOS 26 미만, `web-glass`가 없는 구버전 앱과 Dev Client, 브라우저에서는 고정 요소를 같은 배치의 CSS glass로 그리고 본문 요소는 기존 웹 모양을 유지한다.
- 스와이프 관찰 함수가 생기기 전에 만든 Dev Client에서는 층이 흐려지지 않을 뿐 나머지는 그대로 동작한다.
- 자르는 선 함수(`setInlineClipTop`)가 생기기 전에 만든 Dev Client에서는 본문 부품이 위쪽 줄 밑에서 잘리지 않을 뿐 나머지는 그대로 동작한다.
- `setInlineColorScheme`이 생기기 전에 만든 Dev Client에는 `button-style`이 붙지 않아 세션 버튼이 웹 모양으로 남는다.
- `prefers-reduced-transparency`가 켜져 있으면 CSS 대체가 불투명 배경을 쓴다.
- iOS 투명도 줄이기가 켜져 있으면 시스템이 네이티브 glass를 불투명하게 바꾼다.

### 그 자리 부품의 한계

- 그 자리 부품은 페이지 스크롤만 따라가므로 시트 안쪽처럼 따로 스크롤되는 영역의 컨트롤은 지원하지 않는다.
- 같은 이유로 랭킹 기록 시트 안의 순위 칩은 등록하지 않고, 같은 칩을 쓰는 랭킹 기록 화면에서만 세그먼트로 바꾼다.
- 그 자리 부품은 웹뷰 안 웹 요소보다 늘 위에 그려져서, 앱은 위쪽 고정 줄이 있으면 그 줄 아래 끝(안전 영역 아래 52pt)에서 부품 층을 잘라 줄 위로 올라간 부품을 그리지도 누르지도 않는다.
- 다른 `fixed`·`sticky` 웹 줄은 자르지 않아서, 그 줄 아래로 스크롤된 부품은 줄 위에 겹쳐 보인다.
- 화면 높이가 짧은 기기에서 수동 기록 길이 칩이 아래쪽에 붙은 저장 줄 밑으로 스크롤되면 이 겹침이 생기며, 드물게 일어난다.
- 일부만 반영하면 버린 부품의 이전 네이티브 뷰가 낡은 상태로 남으므로, 앱 파서(`webBridge.ts`)는 필드 하나만 틀려도 메시지 전체를 버린다.
- 다만 앱보다 새 웹이 보낸 값은 틀린 값으로 보지 않아서, 모르는 본문 부품 종류는 그 부품만 빼고 나머지를 그린다.
- 라벨은 40자 이하, id는 `^[a-z0-9:-]{1,64}$`, 버튼 이미지 이름은 `^[a-z0-9-]{1,32}$`, 본문 부품은 32개 이하, 세그먼트 항목은 2개에서 5개까지만 받는다.
- 버튼 SF Symbol 이름은 `^[a-z0-9.]{1,64}$`이고, 좌표는 x·y가 -10000 이상, 폭·높이가 0 이상이며 모두 100000 이하만 받는다.
- 버튼 아이콘 크기는 0 초과 64 이하, 회전 수는 0 이상의 정수, 색 역할은 `default`·`prominent`·`danger`·`active`만 받고 웹은 64를 넘는 아이콘 폭을 64로 줄여 보낸다.
- 웹은 보내기 전에 라벨을 40자로 자르고, 보낼 수 없는 부품은 등록하지 않고 웹 원본으로 그린다.
- 좌표는 측정한 뒤에야 알 수 있어서, 웹은 범위를 벗어난 부품을 그 목록에서만 빼고 나머지를 보낸다(그 부품의 웹 원본은 숨겨진 채로 남는다).
- 이 형식과 범위 상수(`NATIVE_CONTROL_ID_PATTERN`, `NATIVE_CONTROL_LABEL_MAX_LENGTH`, `NATIVE_CONTROL_IMAGE_PATTERN`, `NATIVE_CONTROL_SYSTEM_IMAGE_PATTERN`, `NATIVE_CONTROL_POSITION_MIN`, `NATIVE_CONTROL_COORDINATE_MAX`, `NATIVE_CONTROL_ICON_SIZE_MAX`, `NATIVE_BUTTON_TONES`)는 `packages/types`에 있고 웹과 앱 파서가 함께 쓴다.

### 구현 함정

- `react-native-webview`의 ref는 명령형 핸들이라 `findNodeHandle`이 실패해서, 호스트는 웹뷰를 감싼 `View`의 태그를 넘기고 Swift가 그 아래에서 `WKWebView`를 찾는다.
- JS 숫자와 불은 Swift 딕셔너리에서 `Int`·`Bool`로 바로 캐스팅되지 않아 `NSNumber`로 읽는다.
- 시뮬레이터의 합성 터치는 스크롤뷰 안 `UISwitch`에 전달되지 않아서 스위치 누름은 실기기로 확인한다.
- Swift 코드는 단위 테스트가 없어 시뮬레이터와 실기기로 검증한다.
- 부품 층은 스크롤뷰의 보이는 영역 중 자르는 선 아래만 덮도록 `contentOffset`을 관찰해 스크롤마다 자리를 옮기고, bounds 원점을 frame 원점과 같게 두어 부품 좌표는 문서 좌표 그대로 쓴다.
- 자르는 선의 안전 영역은 웹의 `env(safe-area-inset-top)`과 같은 값이 되도록 Swift가 `WKWebView`에서 읽고, 호스트는 위쪽 줄이 차지하는 52pt만 넘긴다.
- iOS 26.5 시뮬레이터의 웹뷰에는 왼쪽 가장자리 인식기가 2개 붙어 있었고 그중 1개만 켜져 있어서, 뒤로 가기 인식기는 방향과 켜짐 여부로 고른다.
- WebKit은 스와이프 제스처를 켤 때마다 인식기를 새로 만들어서, 호스트는 로드가 끝날 때와 제스처를 다시 켤 때 관찰을 다시 요청하고 모듈은 인식기가 바뀌었을 때만 대상을 다시 붙인다.
- 시뮬레이터에서 `axe`의 합성 스와이프로는 WKWebView의 뒤로 가기 제스처가 시작되지 않아서 실제 스와이프는 실기기로 확인한다.
- 부품 종류 목록 테스트가 Swift의 `case "..."` 문자열을 종류로 읽어서, 색 역할처럼 종류가 아닌 값은 문자열 `case`가 아니라 사전으로 고른다.
- `.glass()` 버튼은 `baseForegroundColor`나 `imageColorTransformer`와 상관없이 템플릿 심볼을 glass 자체 글자색으로 칠해서, Swift는 색 역할의 색을 `withTintColor(_:renderingMode: .alwaysOriginal)`로 이미지에 미리 입힌다.
- 이렇게 입힌 색도 라이트·다크 전환을 따라 바뀌고, 막힌 버튼의 아이콘은 흐리게 그려진다.
- 웹 아이콘의 등장 애니메이션이 `scale(0.6)`에서 시작해서, 웹은 `getBoundingClientRect` 대신 계산된 CSS 폭으로 아이콘 크기를 측정한다.

### 빌드와 범위

- `@expo/ui`, `expo-glass-effect`, 로컬 모듈 `web-glass`가 들어가 Dev Client와 스토어 빌드를 다시 만들어야 켜진다.
- 세션 버튼 모양은 Swift 변경이라 Dev Client와 스토어 빌드를 다시 만들어야 켜진다.
- 유리 메뉴(랭킹 기록 필터, 플래너 과목 메뉴), 시트와 대화상자 안 컨트롤과 시스템 전환은 후속 티켓에서 다룬다.

# BY-1205 백엔드 머지 후 연동 확인

현재 상태: **실서버 저장 검증 보류**. 개발 서버의 공개 API 명세를 읽었으며 실제 기록에는 저장 요청을 보내지 않았다.

## 머지와 배포

- [BE PR163](https://github.com/breathless-youth/backend/pull/163)은 dev의 `de595e58929a8366c0f3822aa4fdd4d736c4bee6`로 머지됐다.
- [Deploy dev run90](https://github.com/breathless-youth/backend/actions/runs/42500928596)은 SSM 명령 전송 성공 후 완료 대기 단계에서 실패했다. 머지 성공과 실제 서버 반영은 별도로 판단한다.
- 기존 QA 앱의 API origin과 개발 환경 설정이 일치함을 확인하고, 인증 없는 `GET /v3/api-docs`를 호출했다. HTTP200이지만 `EDIT_RANGES`, `pieces`, `revision`이 없다. 이 서버에서 새 저장 계약을 사용할 수 있다는 근거가 없다.
- 원본 응답은 비공개 임시 경로에 보관했고, [공개 가능한 명세 확인 결과](by-1205-minute-record-edit/backend-integration.json)에는 주소·인증 정보·계정 데이터를 넣지 않았다.

## 프론트엔드 보완

`SUBJECT`로 기존 빈칸을 포함해 넓게 칠한 뒤 양끝의 실제 기록을 삭제하면, 최종 변경 목록에 빈칸만 대상으로 하는 과목 변경이 남았다. BE는 모든 범위가 실제 조각에 겹치는지 먼저 확인하므로 이 경우 부모의 전체 저장이 STALE_RECORD로 거절된다.

범위 정규화 뒤 원본 조각과 겹치지 않는 변경을 제거하고, 실제 전송하는 범위에 최대100개 제한을 적용했다. 양끝 삭제 재현과 유효 범위100개 사례를 수정 전에 실패시킨 뒤 통과시켰다. 서버 응답의 nullable revision도 타입에 반영했다.

| 검증                            | 상태                                          |
| ------------------------------- | --------------------------------------------- |
| 분 편집·기존 보호 동작24개 파일 | 165개 통과                                    |
| 회귀 재현2개                    | 수정 전 실패 → 수정 후 통과                   |
| 전체 저장소 테스트              | 5개 작업 통과, web7,314개 통과 / 기존1개 skip |
| 별도 경로 웹 빌드·포맷          | 통과                                          |
| 전체 타입·린트                  | 각5개 작업 통과                               |
| 실제 서버 OpenAPI 조회          | HTTP200, 새 계약 없음                         |
| 새 범위 저장·삭제·재조회·충돌   | 서버 반영 전 보류                             |
| 계정·기존 기록·앱 세션 변경     | 실행하지 않음                                 |

재배포 뒤 새 API 명세를 먼저 확인하고, 사용할 QA 계정을 확정한 후 새로 만든 임시 기록만 대상으로 저장·삭제·재조회를 진행한다. 기존 기록·과목·세션은 변경하지 않는다. VoiceOver·5분 순공 실측 보류도 유지한다.

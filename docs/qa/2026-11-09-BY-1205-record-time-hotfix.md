# BY-1205 기록 시간 수정 긴급 복구

원인: 저장된 기록의 시각 변경이 실제 기록 초안 대신 분 선택 상태만 바꿔 길이가67초에 머물고, 완료·상단 저장 후에도 서버 요청이 없었다.

기존 분 과목·삭제 범위 선택을 유지하고 `기록 시간 수정` 모드를 분리했다. 실제 시간 수정은 부모 전체를 미리 보고 `시간 적용` 후 상단 `저장`으로 UPDATE를 전송한다. revision0도 전송하고 원본 초·소수초와 내부 삭제 빈칸을 유지한다. 같은 부모의 미저장 범위 편집과 시간 수정을 섞지 않는다.

운영 BE03d89d3은 UPDATE 시 모든 과목을 단일값으로 다시 칠한다. 따라서 부모 전체가 조회 날짜 안에 보이고 실제 pieces의 과목(null 포함)이 하나인 기록만 시간 수정을 지원한다. 혼합 과목·다른 날짜·손상된 전체 경계는 보호한다. 이는 분 과목 변경·삭제에 전체 UPDATE를 대신 보내는 변경이 아니다.

검증: 신고 경로를 포함한11개 회귀 RED→GREEN, record-edit23개 파일158개 통과. 전체 pnpm test5개 작업/web7,331개 통과·기존1개 skip, 전체 타입·린트·별도 경로 웹 빌드 통과. 독립 리뷰9/10, 열린 중요 지적 없음. 360/834px 브라우저에서 시간 확대·UPDATE1회·원본 종료 초 보존 확인. 실제 폰·dev API 검증은 PR에 후속 결과를 기록한다. 운영 기록은 수정하지 않는다.

릴리즈: 웹26.45.9, 네이티브 변경 없음. 사용자 지시에 따라 dev PR 검증·머지 후 dev→main 수정 릴리즈·배포 검증을 진행한다.

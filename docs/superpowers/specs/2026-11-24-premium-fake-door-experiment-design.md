# 프리미엄 기능 사전 신청 페이크도어 실험 설계 (BY-1392)

- 스토리: BY-1392, FE 하위 BY-1393, BE 하위 BY-1394
- 일정: 2026-11-24 운영 배포 → 2026-11-30 23:59(KST)까지 실험 → 12/1~3 분석 → 12/4 최종 발표
- 목적: 발표에서 비즈니스 가치(지불 의향, 가격 적정성, 수요 기반 매출 추정)를 보여줄 근거를 모은다.

## 1. 무엇을 재는가

| 질문                    | 지표                                                           |
| ----------------------- | -------------------------------------------------------------- |
| 돈을 낼 생각이 있는가   | 노출 대비 사전 신청(이메일 제출 + 14세 미만 앱 알림 신청) 비율 |
| 이 가격에 팔아도 되는가 | 월 2,900원 vs 월 5,900원 두 집단의 신청률 차이                 |
| 어떤 기능이 끄는가      | 신청 후 "가장 기대되는 기능" 단일 선택 분포                    |

판정 초안: 노출 대비 이메일 제출 5% 이상이면 높음, 2% 미만이면 낮음. 실험 시작 전에 앱 안 다른 버튼 클릭률과 포인트 충전 탭 비율로 기준선을 확인해 고정한다. 6일 실험이라 유의하지 않으면 "예비 실험"으로 발표한다.

## 2. 사용자 흐름 (시안 E1-b2)

1. **노출**: 세션 결과 화면의 타임라인 카드 아래에 진입 카드("프리미엄 기능 사전 신청 · 6가지 기능 · 월 N원"). 실험 기간에 결과 화면 노출을 한 번도 받지 않은 사람에게는 홈 "공부 시작" 아래에도 같은 카드를 보인다. 카드 오른쪽 위 X로 닫으면 다시 보이지 않는다. 신청을 끝내도 다시 보이지 않는다.
2. **혜택 화면**(전체 화면): 제목 "프리미엄 기능" + 가격 표시(월 N원), 2열 타일 6개(아이콘·이름, 캐릭터 소품은 보조 표기 "세트 상품 제외", 오른쪽 위 작은 화살표). 타일은 모두 같은 높이다. 그리드 아래에 "기능을 누르면 자세한 설명을 볼 수 있어요.", 하단 고정 줄에 결제 안내와 그 아래 "사전 신청하기".
   - **기능 설명 시트**: 타일을 누르면 아래에서 올라온다. 위에서부터 아이콘, "출시 준비 중" 꼬리표, 기능 이름, 굵은 한 줄(후킹), 설명 문단, 체크 표시 항목 2~3개. 하단에 결제 안내와 "사전 신청하기"(누르면 시트를 닫고 14세 확인으로 간다). 오른쪽 위 X, 딤 누르기, Esc, 앱의 뒤로 가기는 시트만 닫고 혜택 화면에 남는다.
3. **14세 확인**(1/2): "만 14세 이상인가요?" 체크. 체크하면 "다음", 안 하면 버튼이 "앱 알림으로 신청하기"가 되고 이메일 없이 완료로 간다.
4. **이메일·동의**(2/2): 이메일 입력, [필수] 개인정보 수집·이용 동의, "자세히 보기" 펼침.
5. **완료**: "{닉네임}님, 사전 신청이 끝났어요", 알림 경로 안내, "가장 기대되는 기능은 무엇인가요?" 단일 선택(2열 타일, 아이콘·이름, 모두 같은 높이). 하단 버튼은 "결과로 돌아가기"/"홈으로 돌아가기".

- 혜택 화면 안내 줄: "기능을 누르면 자세한 설명을 볼 수 있어요."

- 완료 화면에서 기능을 고른 뒤: "답변해 주셔서 감사합니다!"
- 결제 안내: "사전 신청으로 자동 결제되지 않아요." 혜택 화면 하단과 설명 시트 하단에만 이 한 문장을 두고, 완료 화면에는 두지 않는다.
- 동의 한 줄: "이메일은 출시 알림에만 쓰고, 알림을 보낸 뒤 바로 지워요."
- 동의 자세히: 수집 항목 이메일 / 수집 목적 프리미엄 기능 출시 알림 / 보유 기간 알림을 보낸 뒤 바로 파기, 출시하지 않으면 실험이 끝난 뒤 6개월 안에 파기 / 동의 거부 시 사전 신청 불가.
- 14세 미만 완료: "출시되면 앱에서 알려드릴게요."
- 금지: 할인·정가·평생 가격 약속, "무제한", "포메 프리미엄"(→ "프리미엄 기능"), AI 정확도 주장.

## 3. 가격 배정

- 월 2,900원 / 월 5,900원, 사용자 ID 기준 50:50 고정. 프론트에서 userId의 결정적 해시로 배정한다(같은 사람은 늘 같은 가격).
- 보이는 가격은 월 가격 하나뿐이다.

## 4. API 계약 (BE BY-1394 ↔ FE BY-1393)

`PUT /api/premium-waitlist/me` · `API-Version: 2` · JWT 인증(게스트 포함) · 응답 `204 No Content`

```json
{
  "price": 2900,
  "placement": "RESULT",
  "ageOver14": true,
  "email": "user@example.com",
  "expectedFeature": null
}
```

| 필드            | 타입           | 규칙                                                                             |
| --------------- | -------------- | -------------------------------------------------------------------------------- |
| price           | int            | 2900 또는 5900만 허용                                                            |
| placement       | string         | `RESULT` 또는 `HOME`                                                             |
| ageOver14       | boolean        | 필수                                                                             |
| email           | string \| null | `ageOver14=true`면 필수·형식 검사, `false`면 null이어야 함(보내도 저장하지 않음) |
| expectedFeature | string \| null | 위 표의 id 6개 중 하나 또는 null                                                 |

- 사용자당 한 행 upsert. 프론트는 신청 완료 때 한 번, 기대 기능을 고를 때 같은 본문에 `expectedFeature`를 채워 한 번 더 부른다.
- 오류: `400 {code, message}`(값 위반), `401`(토큰 없음).
- 토큰 출처가 없는 구 앱(API-Version 1)에는 카드를 보이지 않는다.

## 5. 데이터와 개인정보

- 이메일은 백엔드 `premium_waitlist`에만 저장한다. Amplitude·GA4·Sentry·Meta로 이메일을 보내지 않는다.
- 탈퇴 시 `UserDataHandler`로 행을 지운다.
- 파기: 출시 알림 발송 직후 또는 2027-05-31(실험 종료 후 6개월)까지 런북 SQL로 수동 실행한다.

## 7. 끄는 방법

- 웹 코드의 실험 종료 시각(2026-11-30 23:59:59 KST)이 지나면 카드가 자동으로 사라진다.
- 더 일찍 끄려면 같은 모듈의 켜짐 상수를 `false`로 바꿔 웹만 배포한다. 앱 배포는 필요 없다.

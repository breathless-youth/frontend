# 프리미엄 기능 사전 신청 페이크도어 실험 설계 (BY-1392)

> 2026-11-24: 사용자에게 보이는 이름을 "프리미엄"에서 "스파르타"로 바꿨다. 단, 타이머 배경 기능 이름과 설명은 "프리미엄 타이머 배경", "프리미엄 전용 배경"을 그대로 쓴다. 코드 식별자, 이벤트 이름(`premium_fake_door_*`), API 경로, 저장소 키는 그대로 둔다.

- 스토리: BY-1392, FE 하위 BY-1393, BE 하위 BY-1394
- 일정: 2026-11-24 운영 배포 → 2026-12-03 23:59(KST)까지 실험(11/24~12/3, 2026-11-26 연장) → 분석 → 12/4 최종 발표
- 목적: 발표에서 비즈니스 가치(지불 의향, 가격 적정성, 수요 기반 매출 추정)를 보여줄 근거를 모은다.

## 1. 무엇을 재는가

| 질문                    | 지표                                           |
| ----------------------- | ---------------------------------------------- |
| 돈을 낼 생각이 있는가   | 노출 대비 사전 신청(이메일 제출) 비율          |
| 이 가격에 팔아도 되는가 | 월 2,900원 vs 월 5,900원 두 집단의 신청률 차이 |
| 어떤 기능이 끄는가      | 신청 후 "가장 기대되는 기능" 단일 선택 분포    |

판정 초안: 노출 대비 이메일 제출 5% 이상이면 높음, 2% 미만이면 낮음. 실험 시작 전에 앱 안 다른 버튼 클릭률과 포인트 충전 탭 비율로 기준선을 확인해 고정한다. 10일 실험이라 유의하지 않으면 "예비 실험"으로 발표한다.

## 2. 사용자 흐름 (확정 시안 R2 + 신청서 S1)

> 2026-11-25: 혜택 화면을 R2로, 신청서·완료 화면을 S1로 바꿨다. 만 14세 확인 단계와 14세 미만 앱 알림 신청을 없애고 이메일 화면 하나로 합쳤다. 시각 기준은 `premium-fake-door-prototype.html`의 `sparta-redesign`(R2)·`sparta-apply`(S1) 섹션이다.

1. **노출**: 세션 결과 화면의 타임라인 카드 아래에 진입 카드("스파르타 기능 사전 신청 · 6가지 기능 · 월 N원", 왼쪽에 44px 스파르타 티미). 진입 카드는 사용자 테마를 따른다. 홈에는 카드를 두지 않는다. 화면이 보내는 `placement`는 늘 `RESULT`다. 노출 조건(2026-11-26):
   - 방금 끝낸 세션의 기준 시간이 10분(600초) 이상일 때만 보인다. 기준 시간은 결과 화면 머리가 보이는 첫 세션의 값이고, 카메라로 잰 세션은 순공시간(`focusSec`), 자율 모드(타이머) 세션은 순공을 재지 않아 총 공부시간(`studySec`)이다(`premiumQualifyingSec`). 10분이 안 되면 카드도 `viewed` 이벤트도 없다.
   - 카드 오른쪽 위 X로 닫으면 닫은 시각(`dismissedAt`)을 사용자별 기록에 남기고 48시간 동안 숨긴다. 48시간이 지나면 다시 보인다. 토스트는 "이틀 뒤에 다시 알려드릴게요". `dismissed` 이벤트는 닫을 때마다, `viewed`는 지금처럼 사용자당 한 번 보낸다.
   - 예전 기록(`dismissed: true`, 시각 없음)은 처음 읽은 때 닫은 것으로 보고 그 시각을 저장한다. 그래서 이 배포 전에 닫은 사람도 배포 뒤 처음 결과 화면을 본 때부터 48시간이 지나면 다시 본다.
   - 신청을 끝내면 다시 보이지 않는다.
2. **신청 흐름 전체(혜택·설명 시트·이메일·완료)는 시스템 테마와 무관하게 다크**다. 흐름 루트와 body로 나가는 설명 시트에 `theme-dark`를 단다(세션 화면과 같은 방식). 상태 표시줄 영역까지 다크인 것은 받아들였다. 바탕·카드·글자색은 스파르타 전용 색(`index.css`의 `.sparta-surface`)을 쓴다. 하단 주 버튼(혜택 화면·설명 시트·이메일 화면의 "사전 신청하기", 완료 화면의 "결과로 돌아가기")은 흰 버튼(`.sparta-cta`: 바탕 #f6f7f9, 글자 #0b0e14, 누를 때 #dfe2e8, 보내는 중 #c9cdd4, 어두운 그림자, 다크 바탕에서 보이는 포커스 테두리)이다. 결과 화면의 진입 카드는 그대로다.
3. **혜택 화면**(위에서 아래로). 기능 그림은 손그림 SVG 아이콘(`assets/sparta/icon-*.svg`)이고 `premiumFeatureArt.ts`의 기능 id → 아이콘 표 한 곳에서만 고르므로, 바꿀 때는 이 파일과 `assets/sparta/`만 고친다:
   - 머리: 불빛 배경(`.sparta-hero-bg`) 위에 "공부를 끝까지 하게 만드는", 세로 불꽃 글자색 제목 "스파르타 기능", 불꽃이 일렁이는 240px 스파르타 티미(`SpartaHero`). 뒤로 가기 버튼은 왼쪽 위에 얹는다.
   - `SpartaHero`: 같은 크기로 맞춘 몸 그림(`timi-sparta-body.png`)과 불 그림(`timi-sparta-fire.png`)을 겹치고, 캔버스가 불을 세로 2px 줄마다 아래는 고정한 채 위로만 늘였다 줄이며(최대 9%) 자기 자신을 옅게 더해 불빛이 일렁이게 한다. 176px이 아닌 크기에서는 가로 물결 간격을 크기 비율만큼 늘인다. 불끝이 잘리지 않도록 캔버스만 상자 위로 14% 더 높다. 꾸밈 그림이라 읽는 사람에게 숨기고, 모션 줄이기면 불 그림 한 장만 그린다. 문서가 숨거나 화면을 떠나면 멈춘다.
   - "눌러서 자세히 보기" + "스파르타 기능 6가지", 2열 같은 높이 타일(72px 기능 아이콘, 이름, 아래 작은 줄은 보조 표기가 있으면 그것, 없으면 후킹 문구). 누르면 설명 시트.
   - 실제 기록 카드: "포커스 메이커스 실제 기록" / "의지만으로는 부족했던 순간들", "공부 흐름이 끊긴 순간 71,000번+ 앉아 있었지만 공부가 멈춘 횟수", "970시간+ '잠깐만' 쉬다 흘러간 시간", "280시간+ 공부 중 흐트러진 시간", "이 시간을 공부로 돌려놓는 게 스파르타 기능이에요", 출처 "2026년 8월~11월 포커스 메이커스 앱 기록".
   - 가격 카드: 불꽃 아이콘 + "스파르타 기능 6가지 모두", "월 N원", "하루 약 N원"(월 가격 ÷ 30 반올림: 2,900원 → 97원, 5,900원 → 197원), 6가지 기능 목록(22px 아이콘).
   - 하단 고정 줄: 위로 바탕색 흐림, "사전 신청으로 자동 결제되지 않아요.", 흰 "사전 신청하기".
   - **기능 설명 시트**: 후킹 문구, 기능 이름, 보조 표기, 120px 기능 아이콘, 가운데 맞춤 설명, 불꽃 아이콘이 붙은 체크 항목 상자, 하단에 결제 안내와 "사전 신청하기"(누르면 시트를 닫고 이메일 화면으로 간다). 오른쪽 위 X, 딤 누르기, Esc, 앱의 뒤로 가기는 시트만 닫는다.
4. **이메일 화면**(S1): 왼쪽 위 112px 스파르타 티미, "마지막 한 단계," / "불을 붙여 볼까요?"(불꽃 글자색), "출시 소식을 받을 이메일을 알려주세요.", 이메일 입력칸(포커스는 불꽃색 테두리, 오류는 위험 색 테두리), 필수 체크 칸 두 개를 이 순서로 따로 둔다: "[필수] 만 14세 이상이에요", "[필수] 개인정보 수집·이용 동의"(한 줄 + "자세히 보기"). 체크 칸은 이 흐름 전용 24px 둥근 사각 칸이고 체크하면 불꽃색이다. 하단 고정 줄에 "사전 신청으로 자동 결제되지 않아요."와 "사전 신청하기". 두 칸을 모두 체크해야만 보내고, `ageOver14`는 만 14세 확인 칸의 상태(true)를 그대로 싣는다. 근거: 개인정보 동의는 항목별로 따로 받는 것이 원칙이라 만 14세 확인과 동의를 한 칸에 묶지 않았다(PR #637 2차 리뷰, 2026-11-25). 14세 칸을 빼면 "만 14세 이상만 신청할 수 있어요.", 동의 칸을 빼면 "개인정보 수집·이용에 동의해야 신청할 수 있어요."를 각 칸 아래에 보이고 보내지 않는다(둘 다 빠지면 둘 다 보인다). 만 14세 미만은 신청할 수 없다.
5. **완료 화면**(S1): 150px 스파르타 티미, "사전 신청 완료" 알약(불꽃 아이콘), 불꽃 글자색 "가장 먼저 알려드릴게요", "알림은 앱과 {이메일}로 보내드려요."(신청한 이메일이 있을 때만 그린다), "가장 기대되는 기능은 무엇인가요?" 단일 선택(2열 같은 높이 타일, 48px 기능 아이콘, 고르면 불꽃색 테두리와 따뜻한 바탕). 하단 버튼은 "결과로 돌아가기". 닉네임은 보이지 않아 프로필을 읽지 않는다.

- 금지: 할인·정가·평생 가격 약속, "무제한"(예외: 사용자가 정한 기능 이름 "캐릭터 소품 무제한", 세트 상품 제외 표기와 함께만 쓴다), "포메 프리미엄"·"프리미엄 기능"(→ "스파르타 기능"). 예외로 타이머 배경은 "프리미엄 타이머 배경"으로 둔다, AI 정확도 주장.

## 3. 가격 배정

- 보이는 가격은 월 가격 하나뿐이다.

## 4. API 계약 (BE BY-1394 ↔ FE BY-1393)

`PUT /api/premium-waitlist/me` · `API-Version: 2` · JWT 인증(게스트 포함) · 응답 `204 No Content`

```json
{
  "price": 2900,
  "placement": "RESULT",
  "ageOver14": true,
  "email": "user@example.com",
  "expectedFeature": null
}
```

| 필드            | 타입           | 규칙                                                                                                                |
| --------------- | -------------- | ------------------------------------------------------------------------------------------------------------------- |
| price           | int            | 2900 또는 5900만 허용                                                                                               |
| placement       | string         | `RESULT` 또는 `HOME`(화면은 홈 카드를 뺀 뒤 늘 `RESULT`를 보낸다)                                                   |
| ageOver14       | boolean        | 필수                                                                                                                |
| email           | string \| null | `ageOver14=true`면 필수·형식 검사, `false`면 null이어야 함(보내도 저장하지 않음)                                    |
| expectedFeature | string \| null | 위 표의 id 6개 중 하나 또는 null. 서버는 예전 값 `SMART_NOTIFICATION`, `APP_LOCK`도 받지만 화면에서는 보내지 않는다 |

- 사용자당 한 행 upsert. 프론트는 신청 완료 때 한 번, 기대 기능을 고를 때 같은 본문에 `expectedFeature`를 채워 한 번 더 부른다.
- 오류: `400 {code, message}`(값 위반), `401`(토큰 없음).
- 토큰 출처가 없는 구 앱(API-Version 1)에는 카드를 보이지 않는다.

# 유예 재입장 공부시간 이어서 측정 (BY-431)

- 날짜: 2026-08-24
- 티켓: BY-431 — [FE] 유예 재입장 시 공부시간 이어서 측정
- 연관: 팀원 분석 문서 「유예 재입장 공부시간 초기화 · 유예 만료 시 세션 저장」(2026-08-24, dev 실측).
  유예 만료 시 세션 저장은 이 스펙의 범위 밖 — 별도 티켓으로 진행한다.

## 문제

유예(grace) 재입장 시 서버는 기존 `Participant`의 `studySeconds`를 보존해 SNAPSHOT으로
내려주지만, 재입장한 클라이언트는 `LiveRoomSession`이 새로 마운트되며 로컬 측정이 0부터
시작한다. `useRoomStatePublisher`가 60초 주기로 로컬 `focusSec`을 `studySeconds`로 발행하면
서버 `updateStudyTime`이 그대로 덮어써 서버 값과 전원 화면이 00:00으로 리셋된다.

흐름: `SNAPSHOT(이전 값) 표시 → 클라이언트가 0 전송 → 서버 덮어씀 → 전원 화면 리셋`

## 접근 비교

| 접근                            | 내용                                                                                                 | 판단                                                                   |
| ------------------------------- | ---------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------- |
| A. 표시 계층에서 기준값 보정    | 첫 SNAPSHOT의 자기 `studySeconds`를 기준값으로 캡처, 표시·발행값을 `기준값 + 로컬 focusSec`으로 계산 | **채택** — 측정(제출)과 표시(룸 공유)의 기존 경계 유지, 변경 최소      |
| B. 측정 타임라인에 이전 값 주입 | `useStudyRoomSession`이 초기 순공시간을 받음                                                         | 탈락 — 제출 세션에 이전 구간이 섞여 멱등 재제출(별도 티켓)과 이중 계산 |
| C. 입장 응답으로 이전 값 수신   | `RoomJoinResponse` 확장                                                                              | 탈락 — 백엔드 계약 변경 필요, 티켓 범위 밖                             |

## 설계 (접근 A)

변경 지점은 `apps/web/src/features/live-room/LiveRoomSession.tsx` 한 파일이다.

1. 구독 effect에서 dispatch 전에 메시지를 가로채, **첫 SNAPSHOT**의 자기 `studySeconds`를
   `baseStudySeconds`로 1회 저장한다(멤버에 내가 없거나 값이 없으면 0).
2. 내 타일(`myMember.studySeconds`)과 발행 입력(`useRoomStatePublisher`의 `focusSec`)을
   `baseStudySeconds + focusSec`으로 바꾼다.
3. `useRoomStatePublisher`·`useStudyRoomSession`·제출 경로는 바꾸지 않는다 — 제출은 이번
   마운트에서 측정한 값만 나간다. 룸 채널은 표시용 실시간 공유일 뿐 기록 저장 경로가 아니다.

### 확정한 결정

| #   | 결정             | 내용                                                                                                          |
| --- | ---------------- | ------------------------------------------------------------------------------------------------------------- |
| 1   | 기준값 적용 조건 | `graceRejoin` 플래그를 배관하지 않고 항상 첫 SNAPSHOT 값을 쓴다. 일반 입장은 서버 값이 0이라 동작 변화가 없다 |
| 2   | 발행 주기        | 기존 60초 주기 유지, 재입장 직후 즉시 발행하지 않는다. 서버가 이미 이전 값을 갖고 있어 정정할 것이 없다       |

### 경계 동작

- STOMP 자동 재연결(같은 마운트 내 끊김): 기준값은 첫 SNAPSHOT에서만 캡처하므로 재연결
  SNAPSHOT이 이중 가산을 만들지 않는다.
- 일반 입장·명시적 퇴장 후 재입장: 서버가 참가자를 제거해 SNAPSHOT 값이 0 — 기존과 동일.

## 테스트 계획

`apps/web/src/routes/__tests__/LiveRoomPage.test.tsx`에 추가한다.

1. SNAPSHOT에 내 `studySeconds: 2`가 실려 오면, 60초 후 발행값이 `2 + 로컬 측정값`이다
   (0이 발행되지 않는다).
2. 내 타일 표시가 SNAPSHOT 수신 후 기준값에서 이어진다.
3. 일반 입장(SNAPSHOT에 내 값 0 또는 나 없음)은 기존과 동일하게 0부터다.
4. 재연결로 두 번째 SNAPSHOT이 와도 기준값이 갱신되지 않는다.

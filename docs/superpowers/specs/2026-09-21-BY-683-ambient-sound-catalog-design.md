# BY-683 배경음 2차: 비트 합성과 lofi·장면 소리 추가

## 결론

배경음 목록을 여섯 개에서 열다섯 개로 늘린다. 바이노럴·모노럴 비트는 사인파 둘로 만들어 파일도 라이선스도 쓰지 않고, lofi 두 트랙과 장면 소리 다섯 개는 허용 라이선스 음원을 받아 루프로 다시 만든다. 탭 분류를 `kind` 추론에서 카탈로그의 `group` 칸으로 옮긴다.

재생 엔진에서 바뀌는 곳은 합성 버퍼를 만드는 한 자리뿐이다. 세션 연동, 집중 연동 음량, 무음 스위치 처리, 저장 구조는 1차 그대로 둔다.

## 0. 승인된 결정

| 번호 | 항목 | 결정 |
| --- | --- | --- |
| E1 | 범위 | 음원 추가만 한다. 시간대·날씨·장소 추천은 뺀다 |
| E2 | 소셜룸 | BY-714로 분리한다 |
| E3 | 국제화 | 디자인 개편으로 화면 문구가 크게 바뀔 예정이라 이후로 미룬다 |
| E4 | 비트 | 파일 없이 코드로 합성한다. 바이노럴과 모노럴 2종 |
| E5 | 탭 | 노이즈(비트 포함) / 주변 소리 / 음악 |
| E6 | 분류 기준 | `catalog.json`에 `group` 칸을 더한다 |
| E7 | 용량 | 파일당 1.2MB를 유지하고 폴더 총량 상한만 6MB에서 12MB로 올린다 |
| E8 | lofi 수급 실패 시 | 음악 탭을 빼고 나머지로 티켓을 닫는다 |

E7의 근거는 내려받는 시점이다. 소리 파일은 사용자가 그 소리를 켤 때 비로소 받으므로, 한 사람이 무는 비용은 총량이 아니라 파일 하나 크기다. 총량은 배포 크기 문제라 한 자릿수 MB 차이가 사용자에게 가지 않는다.

## 1. 카탈로그 계약

`apps/web/public/sounds/catalog.json`의 항목에 `group`을 더한다.

```json
{ "id": "binaural", "kind": "synth", "group": "noise", "label": "바이노럴 비트" }
{ "id": "bonfire", "kind": "file", "group": "ambience", "label": "모닥불", "file": "bonfire.mp3" }
{ "id": "lofi-1", "kind": "file", "group": "music", "label": "lofi 비트", "file": "lofi-1.mp3" }
```

`group`은 `noise`, `ambience`, `music` 셋 중 하나다. 모르는 값이 오면 그 항목을 버리지 않고 `kind`로 되돌아가 분류한다. `group`이 아예 없는 항목도 같은 경로를 탄다. 배포 순서가 어긋나 예전 `catalog.json`이 잡혀도 화면이 비지 않게 하려는 것이다.

`kind`는 그대로 둔다. `group`은 어느 탭에 놓을지를 말하고 `kind`는 소리를 어떻게 얻을지를 말해서 서로 역할이 다르다. lofi는 `kind: "file"`이면서 `group: "music"`이고, 비트는 `kind: "synth"`면서 `group: "noise"`다.

### 전체 목록

| group | id | 이름 | 얻는 방법 |
| --- | --- | --- | --- |
| noise | white, pink, brown | 백색소음, 핑크노이즈, 브라운노이즈 | 합성 (1차) |
| noise | binaural, monaural | 바이노럴 비트, 모노럴 비트 | 합성 (신규) |
| ambience | rain-trp, rain-mm, cafe-vec | 빗소리 둘, 카페 | 파일 (1차) |
| ambience | bonfire, airplane, library, waves, countryside | 모닥불, 기내, 도서관, 파도, 시골 저녁 | 파일 (신규) |
| music | lofi-1, lofi-2 | lofi 두 트랙 | 파일 (신규) |

## 2. 비트 합성

`noiseSynth.ts` 옆에 `beatSynth.ts`를 새로 둔다. 노이즈와 섞지 않는 이유는 출력 모양이 다르기 때문이다. 노이즈는 한 채널이고 비트는 좌우 두 채널이다.

캐리어를 200Hz로 잡고 좌 195Hz, 우 205Hz를 내보낸다. 차이 10Hz가 비트가 된다. 모노럴은 두 음을 더해 양쪽에 같은 값을 보낸다.

### 루프 이음매

버퍼는 노이즈와 같은 4초다. 4초 동안 195Hz는 780번, 205Hz는 820번 진동해 둘 다 정확히 정수 번 끝난다. 그래서 버퍼 끝과 시작이 같은 위상으로 이어지고 반복 지점에 클릭음이 생기지 않는다. 주파수를 바꾸려면 4를 곱해 정수가 되는 값에서 골라야 한다.

### 음량

노이즈 3종과 같은 `-18 LUFS`에 맞춘다. 사인파는 스펙트럼이 한 점에 몰려 있어 같은 피크의 노이즈보다 크게 들리므로, 피크만 맞추면 비트만 튄다. `noiseSynth.ts`의 `LOUDNESS_TRIM`과 같은 방식으로 실제로 재서 계수를 박고, 테스트가 실효값으로 그 값을 지킨다.

### 효과 표현

집중력이나 뇌파에 관한 주장은 화면 어디에도 쓰지 않는다. 바이노럴 행에만 이어폰을 끼고 들으라는 보조 문구를 단다. 스피커로 들으면 좌우가 섞여 모노럴과 같은 소리가 되기 때문이다.

## 3. 재생 엔진 변경

`ambientPlayer.ts`의 `loadBuffer`에서 합성 갈래 하나만 손댄다.

```
현재:  createBuffer(1, length, sampleRate)  →  노이즈 한 채널
변경:  비트면    createBuffer(2, ...)       →  좌우 두 채널
       노이즈면  createBuffer(1, ...)       →  지금 그대로
```

합성 id가 노이즈인지 비트인지 가르는 분기가 하나 늘어난다. 지금은 `isNoiseKind`가 아니면 곧장 실패로 떨어지는데, 비트 id를 먼저 보고 아니면 기존 경로로 간다.

믹싱·헤드룸·리미터·덕킹·무음 스위치 처리는 손대지 않는다. 비트는 다른 소리와 같은 보이스 하나로 들어가 전력합 헤드룸 계산을 똑같이 받는다.

## 4. 음원 수급

`sound-asset-pipeline` 스킬의 절차를 그대로 따른다. CC0부터 찾고, 후보 표를 라이선스 판별과 함께 승인받은 뒤에 내려받는다.

| 그룹 | 파일 | 인코딩 | 예상 크기 |
| --- | --- | --- | --- |
| ambience | 모닥불, 기내, 도서관, 파도, 시골 저녁 | 90초 mono 96kbps | 각 1.08MB |
| music | lofi 2트랙 | 60초 stereo 128kbps | 각 0.96MB |

lofi를 stereo로 두는 이유는 음악이라 좌우 배치가 소리의 일부이기 때문이다. 장면 소리는 mono로 충분하고 그만큼 용량을 아낀다.

전부 구간을 잘라 크로스페이드 루프로 다시 만들고 `-18 LUFS`로 맞춘다. 원본을 그대로 싣지 않는 것은 무료 스톡 라이선스의 재배포 금지 조항을 피하는 근거이기도 하다.

새 파일 일곱 개를 더하면 폴더가 10.6MB가 된다. 상한 12MB 안이고, 파일 하나가 1.2MB를 넘으면 항목을 빼는 대신 길이나 비트레이트를 줄인다.

`LICENSES.md`에 파일마다 한 행을 남기고 `LicensesPage`에서 보이게 한다.

## 5. 화면

시트의 탭이 둘에서 셋이 된다. 주변 소리 탭에 여덟 개가 들어가 스크롤이 생기는데, 시트가 이미 세로로 스크롤되므로 따로 손댈 것은 없다.

`soundGroups.ts`는 `kind`를 보던 자리를 `group`으로 바꾸고, 빈 그룹을 빼는 규칙은 그대로 둔다. lofi 수급이 막혀 음악 항목이 하나도 없으면 탭도 자동으로 사라진다.

소리 아이콘은 `soundIcons.ts`에 lucide 아이콘으로 놓여 있다. 새로 더하는 아홉 개(비트 둘, 장면 소리 다섯, lofi 둘)에도 같은 방식으로 아이콘을 고른다.

## 6. 테스트

| 대상 | 종류 | 확인 |
| --- | --- | --- |
| `beatSynth` | 단위 | 좌우 주파수 차이가 10Hz, 버퍼 끝과 시작의 위상 연속, 실효값이 노이즈와 같은 기준 |
| `catalog` | 단위 | `group` 파싱, 모르는 `group` 값과 `group` 없는 항목이 `kind` 경로로 떨어짐 |
| `soundGroups` | 단위 | 세 탭 분류, 빈 그룹 제외 |
| `ambientPlayer` | 단위 | 비트 id에 두 채널 버퍼, 노이즈 id에 한 채널 버퍼 |
| 실기기 | 수동 | 루프 이음매, 비트를 다른 소리와 겹쳐 켰을 때의 음량, 이어폰과 스피커의 차이 |

## 7. 범위 밖

- 상황 추천(시간대·날씨·장소). 위치 권한과 날씨 API, 개인정보처리방침 개정이 딸려 온다.
- 소셜룸 적용. BY-714로 분리했다.
- 국제화. 디자인 개편이 끝난 뒤에 다룬다.
- 조합 저장(프리셋). 1차에서 뺐고 게스트 토큰 인증이 자리 잡은 뒤 서버 저장으로 설계한다.

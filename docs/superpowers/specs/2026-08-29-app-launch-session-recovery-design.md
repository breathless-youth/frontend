# 앱 실행 시 미확정 세션 즉시 마감 설계

## 문제

앱을 강제 종료한 뒤 다시 켜서 기록 탭부터 열면 직전 공부가 보이지 않는다.

서버는 그 세션을 draft로 들고 있다가 5분에서 6분 뒤 자동으로 확정한다. 기록이 사라지지는 않지만 그 사이 사용자는 공부한 시간이 날아갔다고 느낀다.

지금 draft를 확정하는 곳은 집중 시작 버튼과 소셜룸 입장뿐이다. 둘 다 누르지 않으면 기다리는 수밖에 없다.

## 왜 웹만으로는 안 되나

홈 화면이 뜰 때마다 마감을 걸면 될 것 같지만 안 된다.

안드로이드는 렌더러 프로세스를 여러 웹뷰가 나눠 쓴다. 그 프로세스가 죽으면 `requestGlobalWebViewRecovery`가 마운트된 웹뷰를 **전부** 다시 세운다. 세션 화면에서 이 일이 일어나면 홈 웹뷰도 함께 다시 뜬다.

그때 홈이 마감을 걸면 세션 웹뷰가 복원하려던 바로 그 draft를 지운다. 공부가 통째로 끊긴다.

웹은 "앱이 방금 켜졌다"와 "전역 복구로 다시 마운트됐다"를 구분할 수 없다. 그 정보는 네이티브만 갖고 있다.

## 신호

네이티브가 앱 프로세스 시작 후 **처음 한 번만** 홈 웹뷰에 `app-launched`를 보낸다.

```text
앱 실행
  → 홈 웹뷰 로드 성공, 웹 JS가 구독을 걸고 home-ready 발신
  → 네이티브가 그 순간 플래그를 소비하고 app-launched 응답
  → 웹 홈이 POST /api/study-sessions/recovery
     200 → 서버가 기록으로 확정, 오늘 집계 다시 조회
     404 → 마감할 세션 없음, 아무 일도 하지 않음

전역 복구
  → 다시 선 홈 문서가 home-ready를 또 보냄
  → 플래그가 이미 소비됨, 응답하지 않음
  → 세션 웹뷰의 복원이 방해받지 않는다

로드 실패
  → 웹 JS가 돌지 않아 home-ready 자체가 없음, 플래그가 남는다
  → 재시도로 성공하면 그때 home-ready가 오고 정상 발신된다
```

### 쿼리로 붙이지 않는 이유

`?launch=1` 같은 쿼리는 안 된다.

전역 복구는 `RemoteWebViewHost`를 다시 만들지 않는다. `retryKey`만 올리는데 URL을 만드는 `useMemo`가 그 값에 걸려 있어 **URL은 새로 만들어진다.** 부모가 들고 있던 쿼리가 그대로 다시 붙는다.

마운트 시점에 플래그를 소비하는 방식도 같은 이유로 안 된다. 재마운트가 아니라 상태 변경이라 소비 시점이 오지 않는다.

**플래그는 응답하는 순간에 소비해야 한다.** 그래야 전역 복구 뒤에 오는 두 번째 `home-ready`에서 걸린다.

### 홈 웹뷰로 제한하는 이유

로드 콜백은 모든 웹뷰에서 발화한다. 세션 웹뷰가 이 신호를 받으면 자기가 복원하려던 세션을 스스로 지운다.

보낼 대상을 `path`가 홈인 호스트로 좁혀 구조적으로 막는다.

### 발신 시점: 로드 콜백이 아니라 handshake

웹 홈이 구독을 건 뒤 `home-ready`를 보내고, 네이티브는 그걸 받은 순간에만 `app-launched`로 응답한다.

로드 콜백에는 걸 수 없다. Android의 react-native-webview는 로드가 실패해도 finish 이벤트를 합성해 `onLoad`까지 불러 준다(`RNCWebViewClient.java`의 `emitFinishEvent`). `onLoadEnd`도 성공과 실패 모두에서 불린다. 어느 로드 콜백이든 웹 JS가 실제로 돌았음을 보장하지 못해서, 첫 로드가 깨지면 일회용 신호가 타 버리고 재시도로 성공해도 다시 알릴 수 없다.

`home-ready`는 웹 JS가 돌아 구독까지 건 뒤에만 나간다. 실패한 로드에서는 이 신호 자체가 없으니 플래그가 남고, 재시도 성공에서 정상 발신된다. 구독이 걸리기 전에 응답이 도착하는 race도 함께 사라진다.

## 웹이 하는 일

`closeStaleSession`을 그대로 쓴다. BY-452가 만든 함수이고 재시도 한 번, 4초 상한, Sentry 보고가 이미 들어 있다.

마감이 끝나면 `statsKeys.all`을 무효화한다. 홈의 오늘 집계와 연속일이 그 키 아래 있어 한 번에 다시 조회된다.

안내 문구는 띄우지 않는다. 정상 실행에서는 마감할 게 없어 404만 오고, 그때 아무 일도 일어나지 않는 편이 조용하다. 마감이 일어난 경우에도 기록 탭에 나타나는 것으로 충분하다.

## 변경 대상

| 파일                                                              | 변경                               |
| ----------------------------------------------------------------- | ---------------------------------- |
| `packages/types/src/bridge.ts`                                    | `app-launched`·`home-ready` 추가   |
| `apps/web/src/lib/bridge.ts`                                      | 파서에 `app-launched` 분기 추가    |
| `apps/mobile/components/RemoteWebViewHost.tsx`                    | `home-ready`에 1회 응답            |
| `apps/web/src/features/study-session/useLaunchSessionRecovery.ts` | 신호를 받아 마감하고 집계를 무효화 |
| `apps/web/src/routes/HomeTabPage.tsx`                             | 훅 호출                            |

## 실패 처리

| 상황               | 처리                                              |
| ------------------ | ------------------------------------------------- |
| 마감할 세션 없음   | 404를 받고 아무 일도 하지 않는다                  |
| 마감 실패          | 1회 재시도 후 그대로 둔다. 서버가 5분 뒤 확정한다 |
| 4초 초과           | 요청을 끊는다. 홈 화면은 막히지 않는다            |
| 신호 유실          | 집중 시작 버튼이 여전히 마감한다                  |
| 브라우저 단독 접속 | 브리지가 없어 신호가 오지 않는다. 아무 일도 없다  |

마감은 홈 화면 렌더를 막지 않는다. 결과를 기다리는 동안에도 화면은 평소대로 뜬다.

## 범위 밖

기록 조회가 미확정 세션을 함께 돌려주면 이 티켓 없이도 해결된다. 백엔드 요청은 보내지 않기로 했다.

소셜룸의 유예 만료 종료가 복원 동작과 어긋나는 문제는 별도 티켓에서 다룬다.

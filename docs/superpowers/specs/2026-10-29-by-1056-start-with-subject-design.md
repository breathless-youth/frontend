# BY-1056 과목 골라 시작 설계

- Jira: BY-1056 (스토리 BY-949의 하위 작업)
- 기획 명세: `.ai/product/specs/BY-949-홈-개편-과목-시작.md` §6, `.ai/product/specs/BY-696-과목-시트.md` §4
- 앞선 작업: BY-1054 홈 헤더·날짜 줄·과목 목록(`2026-10-29-by-1054-home-header-date-list-design.md`)
- 브랜치: `feature/BY-1056-start-with-subject` → PR 대상 `feature/BY-949-home-redesign`

## 범위

오늘 홈의 과목 재생 버튼으로 시작하면 세션 첫 순간부터 그 과목이 선택 과목이 되게 한다. 앱은 고치지 않는다. 재생 버튼을 조금 키우고 누르는 효과를 더한다.

## 지금 흐름에서 확인한 것

- 홈은 `requestSessionStart`에서 옛 세션 마감을 기다린 뒤 앱에 `start-session { atMs }`를 보낸다. 브라우저 단독이면 `/room/1`로 바로 간다.
- 앱은 카메라 권한을 확인하고 `/room/1`을 연다. `atMs`는 세션 화면에 넘기지 않는다.
- 그래서 세션 화면은 자기를 연 요청의 시각을 알 수 없고, 기록이 이번 시작의 것인지는 시간 창으로만 판단한다.
- 세션 화면은 신원과 진행 중 세션 조회가 끝난 뒤 세션을 만든다. 새 세션의 시작 시각은 그 순간의 `Date.now()`이고, 과목 구간도 이 시각부터 열어야 서버 검증(구간은 세션 안)을 통과한다.
- 서버는 과목 구간의 소유만 보고 삭제 여부는 보지 않는다. 삭제한 과목의 구간도 저장되므로 화면에서 걸러야 한다.
- 탭 바 재생 버튼(BY-1058 PoC)은 앱이 직접 `start-session`을 처리해 웹을 거치지 않는다.

| ----------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 전달 방법         | 기기 저장소 키 `focusmakers:start-subject` 하나. 홈과 세션 웹뷰가 같은 저장소를 쓰는 것을 2026-10-28 iPhone·A23에서 확인했다                                                                                                                                                                                                 |
| 기록 모양         | `{ userId, subjectId, atMs }`. `atMs`는 같은 시작의 `start-session` 메시지 `atMs`와 같은 값이다                                                                                                                                                                                                                              |
| 쓰는 때           | 옛 세션 마감이 끝난 직후, `start-session`을 보내기(브라우저는 세션 화면으로 이동하기) 바로 앞                                                                                                                                                                                                                                |
| 과목 없는 웹 시작 | `순공 시작`(이전 앱)과 랭킹의 시작은 같은 자리에서 남은 기록을 삭제한다. 신원이 없을 때도 남기지 않고 삭제한다                                                                                                                                                                                                               |
| 맞춰 보는 규칙    | 세션 화면이 들어오자마자 기록을 읽는다. 남긴 지 30초 안이고 userId가 같을 때만 쓴다. 남긴 시각이 읽는 때보다 뒤이거나 형식이 틀리면 버린다                                                                                                                                                                                   |
| 읽는 자리         | 진입 게이트(`RoomPage`)의 첫 렌더. 신원과 복원 확인을 기다린 시간이 30초 창에 들지 않게 하려는 것이다. userId 비교와 복구 여부 확인은 신원과 복원 확인이 끝난 뒤 같은 게이트에서 하고, 세션 화면에는 쓸 과목 id만 넘긴다                                                                                                     |
| 읽은 뒤           | 세션 화면이 뜨면 기록을 늘 삭제한다. 쓰지 않은 경우도 삭제한다                                                                                                                                                                                                                                                               |
| 복구              | 진행 중 세션을 이어받으면 기록을 쓰지 않는다. 마지막 과목은 지금처럼 서버 구간으로 되살린다                                                                                                                                                                                                                                  |
| 과목 구간         | 새 세션의 첫 구간을 세션 시작 시각부터 연다(`useStudyRoomSession`의 `initialSubjectId`). 고른 시각이 따로 없다                                                                                                                                                                                                               |
| 삭제된 과목       | 세션 화면이 처음 받은 과목 목록에 그 과목이 없으면 그 과목 구간을 버려 과목 없이 시작한 것으로 되돌린다(`discardSubject`). 처음 한 번만 본다. 세션 중 과목 페이지에서 제거한 과목은 고른 동안의 시간을 남긴다. 목록을 받지 못하면 홈이 방금 보여 준 과목이라 그대로 쓴다                                                     |
| 과목 줄 표시      | 과목 목록을 받기 전에는 타이머 위 과목 줄을 그리지 않는다. 받기 전에 `과목`이라는 이름과 오늘 기록이 빠진 시간이 잠깐 보였다가 바뀌는 것을 막는다. 목록을 받은 뒤에는 지금처럼 그린다. 다른 곳에서 과목을 삭제한 복원 세션처럼 받은 목록에 그 과목이 없거나, 목록을 못 받으면 `과목`으로 보인다. 복원 세션에도 같게 적용된다 |
| 남은 기록 정리    | 홈 탭이 다시 보이면(앱의 `tab-focus` 참) 남은 기록을 삭제한다. 권한 거부 안내를 닫고 돌아온 경우가 여기 걸린다                                                                                                                                                                                                               |
| 분석              | `focus_start_tapped`의 `source`에 `home_subject`를 더한다. `home_fallback`은 그대로다. 보내는 곳이 없어진 `home`과 `trackFocusStartTapped`의 기본값은 삭제한다. `subject_item_selected`는 보내지 않는다(아래)                                                                                                                |
| 재생 버튼         | 보이는 원 48px(누르는 영역도 48px), 재생 글리프 14px에서 18px. 줄 높이 68px은 위아래 여백을 12px에서 10px로 줄여 유지하고, 지난 날의 색 막대 자리도 48px로 맞춰 과목 이름 위치가 날짜마다 같다. 키보드 포커스는 앱의 다른 버튼과 같은 `--state-focus` 링으로 보인다                                                          |
| 누르는 효과       | 누르는 동안 `scale 0.92`, 배경 틴트 15%에서 25%. 150ms, 저장소의 강한 ease-out(`ease-overlay`). 모션 줄이기에서는 크기 변화 없이 틴트만 바뀐다. 햅틱은 그대로 medium                                                                                                                                                         |

### `subject_item_selected`를 보내지 않는 이유

이 이벤트는 세션 안에서 사용자가 과목 페이지로 선택을 바꾼 횟수다. 홈에서 고른 과목은 복구 때 마지막 과목이 되살아나는 것처럼 세션의 처음 상태이고, 누른 행동은 홈의 `focus_start_tapped { source: "home_subject" }`가 이미 센다. 세션에서 다시 보내면 과목 페이지 사용량이 부풀어 보인다.

## 남는 위험

- 탭 바 재생 버튼은 웹을 거치지 않아 기록을 삭제할 수 없다. 실패한 시작이 남긴 기록은 홈이 다시 보일 때 삭제되므로, 앱이 화면을 하나도 띄우지 못하고 끝난 시작 뒤 30초 안에 탭 바 재생 버튼을 눌러야만 과목이 붙는다. 권한 확인 중 예외 같은 드문 경로다.
- 이것까지 막으려면 BY-1058에서 탭 바 시작이 세션 화면에 과목 없음을 알리거나(경로 파라미터) 홈 웹뷰의 기록을 삭제해야 한다. 이번 작업은 앱을 고치지 않는다.
- `tab-focus`를 보내지 않는 옛 앱은 30초 창만으로 막는다. 옛 앱에는 탭 바 재생 버튼이 없어 과목 없는 시작은 모두 웹을 거치고, 그때 기록이 삭제된다.
- 처음 쓰는 사람이 카메라 권한 창을 30초 넘게 띄워 두면 과목 없이 시작한다. 잘못된 과목에 시간이 쌓이는 것보다 낫다고 봤다.

- `sessionStart.test.ts`: 마감 뒤 기록을 남기고 그 `atMs`가 `start-session`과 같다. 브라우저 단독도 이동 전에 남긴다. 과목 없이 시작하면 남은 기록을 삭제한다. 신원이 없으면 과목을 골라도 남기지 않고 삭제한다.
- `useStudyRoomSession.startSubject.test.tsx`: 첫 화면부터 선택돼 있고 제출 구간이 세션 시작 시각에서 시작한다. 복원이면 쓰지 않는다. 버리면 과목 없는 세션과 같다.
- `RoomPage.restore.test.tsx`: 새 세션은 훅에 과목을 넘기고 기록을 삭제한다. 복원이면 넘기지 않고 삭제한다. 다른 사용자가 남긴 기록은 넘기지 않고 삭제한다. 복원 확인을 기다리는 동안에도 들어오자마자 읽어 둔다. 다른 곳에서 과목을 삭제한 복원 세션은 목록을 받은 뒤 과목 줄이 `과목`으로 보인다.
- `RoomPage.subjectPage.test.tsx`: 첫 화면부터 과목 버튼이 선택 상태이고 과목 줄은 목록을 받은 뒤 그 이름으로 보인다. 목록에 없는 과목이면 과목 없이 시작한다. 처음 목록에 있던 과목은 세션 중 과목 페이지에서 제거해도 고른 동안의 구간이 제출에 남는다. 목록을 받지 못하면 과목을 유지한다.
- `HomeTabPage.test.tsx`: 재생 버튼이 그 과목을 남기고 세션을 열며 `home_subject`를 남긴다. `순공 시작`은 남은 기록을 삭제한다. 홈이 다시 보이면 기록을 삭제한다.
- `HomeSubjectList.test.tsx`: 재생 버튼 이름·과목 색·글리프 숨김. 저장소 규칙대로 클래스 문자열은 단언하지 않는다.
- 웹 뷰포트 확인(Playwright, API 가짜 응답, 390px): 버튼 48×48, 줄 높이 68px, 누르는 중 `scale 0.92`와 틴트 25%, 모션 줄이기에서 `scale 1`과 틴트 25%, 라이트·다크 스크린샷.

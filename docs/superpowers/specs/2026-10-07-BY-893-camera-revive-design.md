# BY-893 안드로이드 백그라운드 복귀 후 카메라 재획득 설계

- 티켓: BY-893 (관련 BY-834)
- 브랜치: `fix/BY-893-android-camera-resume` (base `dev`)
- 작성일: 2026-10-07

## 문제

Android 웹뷰는 앱이 백그라운드로 가면 카메라 트랙을 끊는다(`readyState === "ended"`). 지금 코드는 이를 알아채지 못한다.

| 위치                     | 지금 동작                                                                    | 결과                                                                              |
| ------------------------ | ---------------------------------------------------------------------------- | --------------------------------------------------------------------------------- |
| `mediaStreamCamera.ts`   | `stream !== null`이면 켜져 있다고 본다                                       | 죽은 스트림을 그대로 들고 있고 다시 열지 않는다                                   |
| `useStudyRoomSession.ts` | `onReturnFromBackground`가 no-op, `cameraStream`은 렌더 중 어댑터에서 읽는다 | 복귀해도 아무 일도 안 일어나고, 스트림이 바뀌어도 리렌더가 없다                   |
| `focusDetector.ts`       | `<video>`의 `readyState`만 본다                                              | 끊긴 트랙이어도 `<video>`가 마지막 프레임을 들고 있어 멈춘 장면으로 계속 판정한다 |

재현은 2026-10-06 Android 실기기(A23)에서 운영 앱·DEV 앱 모두 확인했다. iOS는 같은 경로에서 재현되지 않는다(티켓 BY-893 기록). iOS에서 트랙이 실제로 살아 있는지는 따로 재지 않았다.

## 확정 결정

| #    | 항목                  | 결정                                                                     |
| ---- | --------------------- | ------------------------------------------------------------------------ |
| 접근 | 수정 위치             | 어댑터 `ensureLive()` + 훅 호출 + 감지기 가드 (A안)                      |
| 1    | 다시 잡는 시점        | 백그라운드 복귀 즉시, 재개 버튼 때 한 번 더 확인                         |
| 2    | 실패 알림             | 기존 토스트 "카메라가 꺼져 있어요"(`CAMERA_TOAST_COPY.cameraOff`) 재사용 |
| 3    | 실패 시 재개          | 막지 않는다. 기존 카메라 실패 정책처럼 감지 없이 진행한다                |
| 4    | 화면이 보이는 중 끊김 | 트랙 `ended`를 듣고 바로 다시 잡는다                                     |

정책 근거: 위키 `product/mvp-scope.md` — 백그라운드는 일시정지, 복귀 시 자동 재개하지 않는다. 이번 변경은 카메라만 되살리고 세션 상태는 건드리지 않는다.

## 설계

### 1. 어댑터 — `ensureLive()`

`CameraAdapter`에 선택 메서드 `ensureLive?(): Promise<void>`를 추가한다. `stream?`과 같은 이유로 옵셔널이다 — 실제 피드가 없는 mock과 테스트 대역은 두지 않는다. 실제 어댑터 타입(`MediaStreamCameraAdapter`)에서는 필수다.

- `wanted`가 거짓이면(세션 이탈) 아무것도 하지 않는다.
- 진행 중인 열기(`pending`)가 있으면 그 결과를 기다리고 끝낸다. 전환과 겹쳐 스트림이 고아가 되는 것을 막는 기존 규칙과 같다.
- 스트림에 살아 있는 영상 트랙이 있으면 끝낸다.
- 처음부터 열지 못한 경우(권한 거부 등)는 다시 시도하지 않는다. 재개할 때마다 권한 창이 다시 뜨지 않게 하기 위해서다. 한 번 열렸다가 끊긴 카메라만 다룬다. 이를 가르는 내부 표시(`lost`)를 둔다.
- 죽은 스트림을 정리하고 같은 `facing`으로 다시 연다. 실패하면 `RESTORE_RETRY_MS`(700ms) 뒤 한 번 더 시도한다. 방금 놓인 카메라는 해제가 늦을 수 있어서이고, 전환 복원과 같은 실측값이다.
- 다시 여는 사이 `stop()`이 들어오면 뒤늦게 열린 스트림은 버린다.
- 끝내 실패하면 `stream = null`, `lost = true`로 둔다. 다음 `ensureLive()`(재개 버튼)가 다시 시도한다.

### 2. 세션 훅

- `cameraStream`을 state로 올린다. 기존 주석의 불변식("스트림만 조용히 바뀌는 어댑터 동작을 추가하면 스트림도 state로 올려야 한다")을 따른 것이다.
- 카메라 전환(`flipCamera`)도 스트림을 새로 여므로 같은 동기화(`syncCamera`)를 거친다.
- 내부 `reviveCamera()`가 `camera.ensureLive()` 뒤 `isRunning`·`stream`을 다시 읽어 state에 반영한다. 호출 전에 켜져 있다고 보던 카메라가 꺼진 채 끝나면 새 옵션 `onCameraLost`를 부른다.
- 호출 지점
  - 백그라운드 복귀(`onReturnFromBackground`): 세션 상태는 바꾸지 않는다(수동 재개 정책 유지).
  - `resume()`
  - 현재 영상 트랙의 `ended` 이벤트: 화면이 보일 때(`document.visibilityState === "visible"`)만 부른다. 숨은 동안 끊긴 것은 복귀가 처리한다. 우리가 `stop()`으로 끈 트랙은 `ended`를 내지 않는다.
- 소셜룸(`LiveRoomSession`)은 같은 훅을 쓰므로 함께 고쳐진다. 스트림 state가 바뀌면 `usePeerMesh`의 `setLocalStream`이 상대에게 새 트랙을 보낸다(`replaceTrack`).

### 3. 화면

- `RoomPage`가 `onCameraLost`로 `CAMERA_TOAST_COPY.cameraOff` 토스트를 띄운다.
- 소셜룸은 토스트를 달지 않는다. 카메라를 잃으면 `isCameraRunning`이 거짓이 되어 컨트롤 바 아이콘과 타일이 꺼짐으로 바뀐다.

### 4. 감지기

`processFrame`에서 `cameraTrackLive(element)`가 거짓이면 판정을 건너뛰고 직전 신호를 유지한다. 원인과 관계없이 멈춘 프레임으로 판정하는 것을 막는다. 타임랩스 사진 조건에 있던 같은 검사는 이 조기 반환으로 흡수되어 지운다.

## 구현 중 확인한 것

- React Compiler는 클로저 안의 `camera.stream`·`camera.isRunning` 읽기를 그 함수의 의존성으로 잡는다. 그래서 `syncCamera`는 스트림이 바뀔 때마다 새 함수가 된다. 마운트 effect가 이 함수를 의존하면 재획득할 때마다 카메라를 껐다 켠다(훅 테스트에서 `start` 3회·`stop` 2회로 드러남). 마운트 effect는 effect 안의 지역 함수로 반영하고 `syncCamera`를 의존하지 않는다. `reviveCamera`가 새로 만들어져 `ended`·복귀 구독이 다시 걸리는 것은 무해하다.
- 컴파일러 프로브: 변경 뒤에도 `useStudyRoomSession`이 컴파일된다(memoSlots 137 → 155, 건너뛴 함수 없음).

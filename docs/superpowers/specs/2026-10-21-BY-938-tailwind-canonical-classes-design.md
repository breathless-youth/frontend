# BY-938 Tailwind 표준 클래스 표기 일괄 적용 설계

BY-641 태블릿 작업에서 미뤄 둔 정리 작업이다. IntelliSense 경고를 0건으로 만들어, 앞으로 새로 생기는 경고가 바로 눈에 띄게 한다.

## 배경

- Tailwind IntelliSense 0.16의 `suggestCanonicalClasses`는 같은 CSS를 내는 더 짧은 표기가 있으면 경고를 띄운다. `h-[52px]` → `h-13`, `bg-[var(--x)]` → `bg-(--x)`, `rounded-[20px]` → `rounded-xl` 같은 식이다.
- 10-19 조사 때는 584건이었다. 그 뒤 BY-936·937이 손댄 파일을 정리해서, 2026-10-21 dev(a51088bf) 기준으로는 92개 파일에서 513건, 테스트 6개 파일에서 13건, 합쳐 526건이다.
- 판정은 IntelliSense가 쓰는 Tailwind 함수 `canonicalizeCandidates`(설치된 `@tailwindcss/node` 4.3.3)를 그대로 불러서 했다. 그래서 스크립트 결과와 에디터 경고가 같다.

| 종류                    | 건수 | 예                                                                |
| ----------------------- | ---- | ----------------------------------------------------------------- |
| px 임의값 → 간격 스케일 | 410  | `mt-[10px]` → `mt-2.5`                                            |
| `var()` 축약            | 82   | `ring-[color:var(--x)]` → `ring-(--x)`                            |
| 토큰 이름               | 8    | `rounded-t-[24px]` → `rounded-t-3xl`                              |
| 단위 없는 값            | 8    | `duration-[260ms]` → `duration-260`                               |
| 그 밖의 v4 문법         | 18   | `bg-gradient-to-r` → `bg-linear-to-r`, `-top-[7px]` → `-top-1.75` |

## 결정

| 항목           | 결정                                                                                                     | 이유                                                                                                                                                                                                     |

| 변환 도구      | 저장소에 스크립트 하나를 둔다(`apps/web/scripts/canonicalizeClasses.js`)                                 | 리베이스나 다른 브랜치 머지 뒤에 다시 돌려야 한다(티켓 PRD). 에디터와 같은 함수를 써서 판정이 갈리지 않는다                                                                                              |
| 기본 동작      | 인자 없이 돌리면 목록만 출력하고 1건 이상이면 종료 코드 1, `--write`일 때만 파일을 고친다                | 확인과 수정을 한 스크립트로 끝낸다                                                                                                                                                                       |
| 대상           | `apps/web/src`의 `.ts`·`.tsx` 문자열 리터럴과 템플릿 문자열 조각, 테스트 파일 포함                       | 클래스 상수(`const ROW = "py-[14px] ..."`)와 테스트 단언도 경고 대상이고, 테스트가 새 표기로 통과해야 한다(완료 조건)                                                                                    |

| CI             | 이번에는 넣지 않는다                                                                                     | 목표는 에디터 경고가 보이게 하는 것이다. 다시 쌓이면 `pnpm --filter web lint:classes`를 CI에 한 줄 추가한다                                                                                              |
| 손으로 고친 줄 | 생기면 기계 변환 커밋과 다른 커밋으로 나눈다                                                             | 티켓 PRD. 리뷰어가 기계 변환 커밋은 스크립트 재실행으로 확인할 수 있다                                                                                                                                   |

### 버린 안

- `npx @tailwindcss/upgrade`: v3 → v4 이전 도구라 CSS·설정 파일까지 건드린다. 설치되지 않은 패키지를 내려받아야 하고, 무엇을 바꿀지 고를 수 없다.
- ESLint 플러그인(`eslint-plugin-better-tailwindcss` 등): 새 의존성이다. 설치된 `@tailwindcss/node`로 같은 판정을 할 수 있다.
- 정규식 치환: 문자열이 클래스인지 모르고, `[`·`(` 안의 콜론을 잘못 자를 수 있다. TypeScript 파서로 문자열 위치를 찾는다.

## CSS가 같은지 확인

- 변환 쌍마다 바꾸기 전·후 CSS를 컴파일해 비교한다(루트 16px 기준으로 `calc(var(--spacing) * N)`을 px로 풀어서). 일회성 확인이라 스크립트는 `reports/`에 둔다.
- 10-21 기준 결과: 526건 중 520건은 같고 6건만 문자열이 다르다. 여섯 건 모두 화면 결과는 같다.
  - `bg-gradient-to-r` → `bg-linear-to-r` 2건: 그라디언트 보간 공간을 `@supports`로 감싸 구형 웹뷰 폴백이 붙는다.
  - `[transform:...]` → `transform-[...]` 3건: 같은 `transform` 선언에 Tailwind의 `@property` 등록이 따라붙는다.
  - `landscape-compact:aspect-[2/1]` → `landscape-compact:aspect-2/1` 1건: 선언은 같고 비교식이 `[2/1]` 이스케이프를 다르게 읽었다.

## 테스트

- 스크립트의 변환 함수(파일 경로·소스 문자열 → 고친 문자열과 바꾼 목록)를 vitest로 검증한다. 웹 스크립트 테스트의 기존 자리인 `apps/web/scripts/__tests__/canonicalizeClasses.test.ts`에 둔다.
  - className 문자열의 px 임의값을 스케일로 바꾼다
  - 같은 줄의 다른 클래스, 변형(`sm:`·`before:`)을 보존한다
  - 템플릿 문자열에서 `${}` 옆 토큰은 건드리지 않는다
  - 클래스가 아닌 문자열(문구, import 경로)은 그대로 둔다
  - 바꿀 것이 없으면 원문을 그대로 돌려준다
- 실행 뒤 스크립트를 다시 돌려 0건, `lint`·`typecheck`·`test`·`format:check` 통과를 확인한다.
- 주요 화면 스크린샷 비교는 6단계 화면 검증에서 한다.

## 문서

- `focusmakers-design` 스킬의 px 규칙 줄에 확인 명령을 적고, 예시 코드(`px-[9px] py-[3px]`, `h-[92px]`)를 새 표기로 바꾼다.

## 범위 밖

- `style={{ ... }}`의 숫자 px 42곳: IntelliSense 경고 대상이 아니다.
- `text-[13px]`처럼 표준 표기가 없는 임의값: 경고가 나지 않으므로 그대로 둔다.
- 진행 중인 BY-947 브랜치: 이 작업이 먼저 머지되면 그쪽에서 리베이스 뒤 `--write`를 다시 돌린다.

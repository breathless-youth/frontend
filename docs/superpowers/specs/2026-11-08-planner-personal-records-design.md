# 기록 탭 개인 통계와 기록 수정 표시

상태: 승인. 사용자는 서버와 프론트를 함께 구현하고 공부 리듬까지 모두 반영하도록 요청했다.

## 사용자 요청

- 플래너에서 고친 시간이 기록 탭 통계에도 반영된다.
- 과목 없음으로 공부한 기록에도 연필 표시가 남는다.
- 앱을 다시 열어도 서버에 저장된 수정 표시가 유지된다.
- Android에서 시스템 하단 바가 있어도 기록 고치기의 마지막 04:00 행을 누를 수 있다.

## 구현 방향

기존 측정 원본과 랭킹은 보존하고, 개인 수정본을 읽는 통계 조회를 추가한다. 수정 여부는 기존 수정 행의 존재로 판단하므로 이 표시를 위해 DB 컬럼을 추가하지 않는다. 브라우저 저장소에서 수정 이력을 추측하는 방식은 재설치와 다른 기기에 대응하지 못한다. 기존 원본 통계 API의 의미를 바꾸면 홈과 랭킹에 영향이 생기므로 사용하지 않는다.

## 제안한 서버 명세

- `PlannerRecordView.edited: boolean`을 제공한다. 측정 원본은 false이며, 수정 행을 적용한 기록과 새 개인 직접 입력은 true다. source의 MEASURED/MANUAL 의미는 유지한다.
- 인증된 `GET /api/planner/records/stats?date=&timeZone=`를 추가한다.
- 인증된 `GET /api/planner/records/stats/period?from=&to=&compareFrom=&compareTo=&timeZone=`를 추가한다.
- 인증된 `GET /api/planner/records/stats/rhythm?timeZone=`를 추가한다.
- 모든 새 조회는 기존 API-Version 1과 본인 토큰을 사용한다.
- 일간 목록은 문자열 `displayKey`, 배치 편집에 사용할 `recordKey`, 실제 원본이 있는 경우의 `originalSessionId: number|null`, source, edited, 자정 기준 날짜, 표시 시각과 전체 시각, 총공부와 순공, 이벤트, 과목 구간, 완료한 할 일을 제공한다.
- 원본 ID가 없는 개인 직접 입력을 가짜 숫자 세션 ID로 채우지 않는다.
- 기간 응답은 기존 기간 통계의 표시 구조를 사용하되 개인 수정본을 기준으로 계산한다.

## 날짜와 시간

- 기록 탭의 하루는 자정 기준이며 플래너의 하루는 05시 기준이다.
- 수정하지 않았거나 과목만 바꾼 원본은 기존 statDate와 초 단위 합계를 유지한다.
- 원본의 실제 시간을 변경한 경우 원본에 저장된 시간대로 자정에서 나눈다.
- 원본이 없는 개인 직접 입력은 요청 timeZone으로 날짜를 계산한다. 기존 수정 행에는 입력 당시 시간대가 없으므로 이를 복원했다고 주장하지 않는다.
- 옛 수동 기록은 시작 시간 수정 때 키가 변경돼 원본 연결을 복원할 수 없는 경우가 있다. 이 경우도 originalSessionId는 null이며 요청 timeZone으로 개인 기록을 조회한다. 기존 키 규칙은 유지하고 원본을 추측해 연결하지 않는다.
- 옛 수동 묶음의 여러 조각 사이 빈 시간은 공부시간에 포함하지 않는다.
- 화면에서 4초를 1분 칸으로 보여도 실제 통계에 임의의 60초를 추가하지 않는다. 기존 통계의 60초 미만 기록 제외 기준을 유지한다.

## 화면과 갱신

- 일간 목록, 선택일 합계, 달력, 월 합계, 주간 합계와 이전 기간 비교를 개인 조회로 연결한다.
- 리듬은 기존과 같이 측정 기록만 대상으로 하되 개인 수정본의 시간과 삭제를 반영한다. 직접 입력을 측정 기록으로 바꾸지 않는다.
- 홈과 랭킹, 기존 스트릭 조회는 원본을 사용한다.
- 연필은 과목 유무와 독립적으로 표시하며, 직접 입력과 수정됨의 접근성 설명을 구분한다.
- 수정 표시는 기록 고치기의 편집기·선택 패널·삭제 미리보기와 기록 탭 목록에서만 제공한다. 일반 플래너의 타임테이블에는 연필과 수정 여부 설명을 표시하지 않는다(2026-11-08 사용자 결정). 좁은 편집 칸에서는 기존 레이아웃을 유지하고 선택한 기록의 설명에도 수정 여부를 제공한다. 주간 플래너는 할 일 목록 화면이므로 기록 연필을 할 일에 추가하지 않는다.
- 개인 통계 쿼리는 사용자와 시간대, 날짜와 비교 기간을 키에 포함한다. 과거 기록도 바뀔 수 있으므로 무기한 최신 캐시로 취급하지 않는다.
- 저장 성공과 부분 성공 후 같은 문서의 개인 통계를 무효화하며 기존 records-changed 메시지로 다른 탭 웹뷰도 갱신한다.
- Android 마지막 행 문제는 안전 영역과 스크롤 영역을 진단한 뒤 실제 격자 좌표와 편집 조작이 일치하도록 수정한다.

## 검증

서버에서는 수정 없음, 과목만 변경, 과목 없음, 시간 변경, 삭제, 날짜 이동, 새 직접 입력, 옛 수동 묶음의 빈 구간, 자정과 05시, DST, 비교 기간을 실제 PostgreSQL로 검증한다. 원본 stats와 랭킹이 유지되는 회귀도 확인한다.

프론트에서는 원본 ID 없는 항목의 목록과 편집, 새 응답만으로 유지되는 연필, 같은 문서와 다른 웹뷰의 캐시 갱신, 날짜 변경과 재진입을 검증한다. Android 하단 시스템 바가 있는 화면에서 04시 행과 마지막 분을 직접 선택한다.

커밋과 원격 반영은 구현과 검증 내용을 보여 준 뒤 요청 범위에 따라 진행한다.

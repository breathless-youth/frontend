# BY-959 세션 시간 표시의 초 단위 갱신 시점 맞추기

- Jira: [BY-959](https://breathless-youth.atlassian.net/browse/BY-959)
- 관련: BY-714(소셜룸 개편이 이 값을 그대로 쓴다), BY-939, BY-696

## 문제

세션 화면의 순공 시간, 총 공부 시간, 과목 시간이 서로 다른 순간에 1초씩 바뀐다.

- `computeSessionTotals`는 공부 구간과 집중 구간의 밀리초를 따로 더한 뒤 따로 초로 내린다. 비집중 구간 길이에 소수점 아래 값이 섞이면 두 값이 정수 초를 넘는 순간이 어긋난다.
- 과목 시간은 200ms 타이머가 쓴 시각이 아니라 렌더 순간의 시각(`renderNowMs`)으로 계산한다.
- 과목 선택 시각에도 밀리초가 붙고, `deriveSubjectTotals`는 겹침마다 따로 초로 내린다.

## 결정

| 항목                                                   | 결정                                                                                                           |
| ------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------- |
| 방식                                                   | 화면 표시용 계산에서만 시각을 세션 시작 기준 1초 눈금에 맞춘다                                                 |
| 지금 시각                                              | 눈금으로 내린다                                                                                                |
| 경계 시각(상태 전환, 과목 선택, 서버가 준 이전 이벤트) | 지금 시각처럼 눈금으로 내린다                                                                                  |
| 기준점                                                 | `initial.startedAtMs`(세션 시작 시각). 복원 세션도 같다                                                        |
| `deriveSubjectTotals`                                  | 고치지 않는다. 서버 규칙을 흉내 내는 함수이고 계약 테스트가 쓴다. 입력이 정수 초라 겹침마다 내려도 오차가 없다 |
| 서버로 보내는 값                                       | 진행 스냅샷, 최종 제출, 결과 화면, 분석 이벤트는 원래 밀리초를 그대로 쓴다                                     |

검토하고 버린 방식은 아래와 같다.

- 경계 시각을 반올림하는 방식은 경계가 화면의 지금 시각보다 늦게 놓일 때 과목 시간이 순공과 어긋나서 최종 리뷰 뒤 버렸다(2026-10-24 결정).
- 과목 시간에만 타이머 시각을 넘기는 방식은 순공과 총 공부의 어긋남을 남겨서 버렸다.
- 1초마다 표시값을 올리는 카운터를 따로 두는 방식은 복원·백그라운드·타이머 스로틀 때 실제 측정값과 벌어져서 버렸다.

## 구성

### `displayClock.ts` (순수 함수, study-session)

- `floorToSecondGrid(ms, originMs)`는 화면의 "지금"과 경계 시각을 눈금으로 내린다.
- `snapTimeline(timeline, originMs)`는 구간 경계를 내린 사본을 만든다. 열린 마지막 구간의 `endedAtMs: null`은 그대로 둔다.
- `snapStatusEvents(events, originMs)`는 서버가 준 이전 이벤트의 시작·끝을 내린 사본을 만든다.
- `snapSubjectTracker(tracker, originMs)`는 닫힌 과목 구간과 지금 구간의 시작 시각을 내린 사본을 만든다.
- 모든 함수는 입력을 바꾸지 않는다.

### `useStudyRoomSession`

- 타이머 틱에서 `displayNowMs = floorToSecondGrid(nowMs, origin)`를 구한다.
- 순공과 총 공부는 `computeSessionTotals(snapTimeline(timelineRef.current, origin), displayNowMs)`에 서버 누적값(`withBase`)을 더해 계산한다.
- `displayNowMs`는 totals와 같은 state에 함께 담는다. 값이 그대로면 지금처럼 이전 state를 유지해 리렌더를 막는다.
- 틱과 과목 선택은 같은 `refreshDisplay(nowMs)`로 화면 집계를 다시 낸다.
- 반환값 `subjectSegments`와 `sessionEvents`는 눈금에 맞춘 입력과 `displayNowMs`로 만든다. `renderNowMs`와 그 eslint 예외 주석은 지운다.
- 종료 시에는 `setDisplay({ totals: finalTotals, nowMs: floorToSecondGrid(endedAtMs, origin) })`로 원래 밀리초로 계산한 집계를 넣는다.
- 끝난 세션에서는 `refreshDisplay`가 아무것도 하지 않아 종료 집계를 덮어쓰지 않는다.

## 경계 사례

- 경계를 내리므로 표시값과 서버 기록의 차이는 전환 1회당 1초 미만이다.
- 같은 1초 눈금 안에서 시작하고 끝난 구간은 길이 0으로 접혀 표시에서 빠진다(서버 이벤트도 1초 미만 구간은 `MIN_EVENT_MS`로 버린다).
- 틱이 눈금과 어긋나 있어도 일시정지 중 과목을 바꾼 직후 이전 과목 시간이 1초 올랐다 돌아오지 않는다(과목 경계와 화면의 지금 시각을 같은 시각에서 낸다).
- 소셜룸은 같은 훅을 쓰므로 순공 표시가 함께 맞춰진다.
- 소셜룸 STOMP `publishState({ focusSec })`는 표시용 `focusSec`을 보내지만, 이 채널은 설계상 표시 전용이라 기록 경로가 아니다(`live-room/useRoomStatePublisher.ts`).

## 테스트

- `displayClock` 단위 테스트
  - 지금 시각과 경계 시각을 내리고 원본은 바꾸지 않는다.
  - 내린 경계가 화면의 지금 시각보다 늦게 놓이지 않는다.
  - 표시값과 서버 계산값의 차이가 전환 1회당 1초를 넘지 않는다.
- 훅 테스트(가짜 타이머)
  - 소수점 시각에 비집중이 섞여도 순공과 총 공부가 같은 틱에 바뀐다.
  - 소수점 시각에 과목을 바꿔도 과목 시간이 순공과 같은 틱에 바뀐다.
  - 소수점 아래가 0.5초 이상인 시각에 비집중이 시작돼도 과목 순공이 순공과 같다.
  - 일시정지 중 소수점 시각에 과목을 바꿔도 이전 과목 시간이 줄지 않는다.
  - 틱이 눈금과 어긋나도 일시정지 중 과목을 바꾼 직후 이전 과목 시간이 올랐다 내려가지 않는다.
  - 세션을 끝낸 뒤 과목을 바꿔도 종료 집계가 바뀌지 않는다.

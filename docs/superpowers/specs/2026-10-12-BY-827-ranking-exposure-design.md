# BY-827 랭킹 노출 지점 (PR ②) 설계

> **갱신 노트 (2026-10-20)**: 홈 추월 시트는 BY-944에서 뺐다. 이 문서의 추월 시트와 `GET /api/rankings/home` 설명은 당시 설계 기록으로 남겨 뒀다.

- 티켓: BY-827, BE 짝은 BY-828
- 브랜치: `feature/BY-819-ranking-exposure`, base는 PR ① 브랜치 `feature/BY-819-ranking`이다. PR ①이 `dev`에 머지되면 base를 `dev`로 바꾼다.
- 앞선 설계: `docs/superpowers/specs/2026-10-10-BY-827-ranking-design.md`(PR ①). 이 문서는 그 문서 §16 PR ② 개요를 대신한다.
- Figma: `FocusMakers-V2-Design`(`YcyImcuVORDbBneii41Byh`) `S10 · 랭킹 (Soft Blue)`, 노드는 부록에 있다.

## 1. 목적

- 랭킹 탭에 들어가지 않아도 순위가 바뀐 것을 알게 해서 다시 공부할 계기를 만든다.
- 자리를 비운 사이 밀려났으면 홈에서 한 번 알려 주고, 마감 때 TOP 3에 들었으면 메달을 보여 주고, 공부를 마치면 그 공부로 오른 순위를 보여 준다.

## 2. 범위

| 화면                | 시안               | 들어가는 곳             |
| ------------------- | ------------------ | ----------------------- |
| 추월 바텀시트       | 5a                 | 홈                      |
| 마감 메달 모달      | 5t, 5u, 5v, 5w, 5x | 홈                      |
| 공부 결과 랭킹 카드 | 5i                 | 솔로 결과, 소셜 룸 결과 |
| 홈 팝업 순서        | 없음               | 홈                      |

- 홈 한 줄 랭킹 카드(5b)는 사용자 결정으로 뺀다. `home` 응답의 `card`는 쓰지 않는다.
- 모든 진입점은 `hasRankingTab()`이 참일 때만 보인다(랭킹 탭이 없는 옛 앱에서는 숨긴다).
- 신원이 없는 저장 안 함 모드에서는 셋 다 보이지 않는다.

## 4. 서버 API

네 API 모두 `API-Version: 1` 헤더가 필요하고 `packages/types`에 아직 타입이 없다. Swagger(`/v3/api-docs`) 기준으로 타입을 더하고 `apiVersion`에 등록한다.

### `GET /api/rankings/home?since=`

- `since`는 UTC ISO 시각이고, 홈 추월 시트에만 쓴다.
- 응답 `RankingHomeResponse`는 `card`(쓰지 않음)와 `overtaken`이다.
- `overtaken`: `{ fromRank, toRank, count, nearest: [{ nickname, gap, studiedFrom, studiedFocusSec }] }`, `nearest`는 최대 2명이다.
- `overtaken`이 null인 경우: `since`가 없음, `since`가 이번 주 월요일 0시(KST) 전이거나 미래, `since`에 순위가 없었음, 순위가 내려가지 않았음.
- `since`가 있으면 호출마다 이번 주 전체를 다시 집계하므로 그날 첫 확인에만 붙인다(BE 전달사항).

### `GET /api/rankings/records/unseen`

- 응답 `{ total, records: RankingRecordItem[] }`, `records`는 최대 100개다.
- `total`은 이미 본 것까지 더한 누적 메달 수로 `현재까지 메달을 N번 얻었어요`에 쓴다.
- 서버 순서는 순위, 일·주·월, 순공·집중률·시간대다.
- 00:00~04:01에는 그날 0시 마감 기록을 돌려주지 않는다(서버가 처리).

### `POST /api/rankings/records/seen`

- 본문 `{ ids: number[] }`, 최대 100개이고 넘으면 400, 빈 배열은 아무 일도 하지 않는다. 응답은 204다.

### `GET /api/rankings/session-gains?startedAt=`

- `startedAt`은 제출한 세션의 시작 시각(`sessions[0].startedAt`)이다.
- 응답 `{ weekly: Gain | null, others: BoardGain[] }`, `Gain`은 `{ before, after, delta }`, `BoardGain`은 거기에 `type`, `period`, `slot`을 더한다.
- 그 시각으로 제출된 내 세션이 없으면 404다. 오류가 아니라 오른 순위가 없는 것으로 본다.
- 1분 미만 조각만 있는 세션이나 자정을 넘긴 세션은 빈 응답이 올 수 있다. 그때는 카드를 숨긴다.

## 6. 홈 팝업 흐름

```
홈 문서가 뜸
  └ 공지 판단 끝남(NoticeModalHost onSettled)
  └ 세션 복구 판단 끝남
      ├ 이번 실행에 공지·인터뷰·복구 창이 떴음 → 랭킹 팝업 쉼
      └ 아무것도 안 떴음
          ├ unseen 메달이 있음 → 메달 모달, 띄운 직후 seen 전송, 오늘 날짜를 '메달 본 날'로 저장
          └ 없음
              ├ 오늘 이미 추월을 확인했거나 메달 본 날 → 쉼
              └ 아님 → 오늘을 '추월 확인한 날'로 저장, since가 있으면 home?since 호출
                  ├ overtaken 있음 → 추월 시트
                  └ 없음 → 쉼
```

- 한 번 실행에 하나 규칙은 공지가 쓰는 '이번 실행에 띄움' 표시를 같이 쓴다.
- 그 표시를 sessionStorage에 쓰지 못한 기기에서도 같은 문서에서는 홈이 공지·복구 창·랭킹 팝업이 떴는지 메모리로 기억해 규칙을 지킨다.
- 복구 결과는 랭킹 팝업이 뜬 뒤에 늦게 올 수 있다. 그때 랭킹 팝업은 그대로 두고, 복구 창을 공지 때처럼 그 팝업이 닫힐 때까지 미룬다.
- 랭킹 팝업을 내리지 않는 까닭은 메달을 띄운 직후 본 것으로 보내서, 내리면 사용자가 못 본 메달이 본 것으로 넘어가기 때문이다.
- `since`는 마지막으로 앱이 가려진 시각(`loadLastHiddenAt`)이다. 없으면 추월 확인을 하지 않는다.
- 그 시각은 홈이 뜰 때 읽어 둔다. 판단은 공지·복구 판단 뒤라, 그 사이 앱을 오가면 시각이 지금으로 바뀌어 그날 확인을 헛되이 쓴다.
- 날짜는 KST 날짜 키(`todayKstDateKey`)로 비교한다.
- 브라우저 단독 모드(브리지 없음)에서도 같은 흐름을 쓰되, 탭 이동은 웹 라우팅으로 한다.
- 메달 요청이 실패하면 그 실행에서는 랭킹 팝업을 쉬고 오류를 보이지 않는다. 추월 요청이 실패해도 같다.

## 7. 화면

### 5a 추월 바텀시트

- 위에서부터 손잡이, `마지막 접속 이후`(작은 강조 글자), 제목 `자리 비운 사이` 줄바꿈 `N명이 추월했어요`, `주간 순공 1,201위 → 1,205위`(순위만 굵게)를 둔다.
- 목록 상자에 `nearest`를 서버 순서대로 최대 2줄 둔다. 줄은 아바타(첫 글자), 닉네임, 오른쪽 `+{gap}`이다.
- `gap`은 `formatGapDuration` 형식이다(`+31분`, 1시간 이상이면 `+1시간 5분`).
- 오른쪽 값 색은 시안에서 둘째 줄만 파랑이라, 차이가 가장 작은 줄(가장 따라잡기 쉬운 사람)을 파랑으로 쓴다. Figma 확인 요청에 넣는다.
- 파랑 값은 회색 목록 상자 위에 놓이므로 파랑을 글자색 쪽으로 조금 누른 `rank-value` 색을 쓴다. 시안의 파랑 그대로는 상자 위에서 4.35:1이라 4.5:1에 못 미친다.
- 버튼은 `공부하러 가기`(채운 큰 버튼)와 `랭킹 보기`(글자 버튼)다.
- 두 버튼 모두 다른 화면으로 보내고 손잡이는 화면 낭독기에 가려져 있어, 화면 낭독기에만 보이는 `닫기` 버튼을 더 둔다.

### 5t~5y 메달 마감 모달

- 맨 위에 메달 그림을 둔다. 메달이 1개면 그 메달 하나를 크게 두고, 1위면 그 위에 왕관을 둔다. 메달 뒤에 은은한 빛을 깐다.
- 메달이 2개 이상이면 딴 순위와 관계없이 늘 가운데 1위, 오른쪽 2위, 왼쪽 3위 메달 셋(`3 · 1 · 2`)을 겹쳐 두고 가운데 메달 위에 왕관을 둔다(5v~5y). 이 그림은 메달을 여러 개 땄다는 표시이고, 실제 순위는 목록과 개수 줄이 보여 준다.
- 메달 1개(5t, 5u): 파랑 작은 글자 `{기간 표기} · {기간} · {판}`(예: `10월 9일 (금) · 일간 · 오전 구간`, `10월 1주 · 주간 · 순공`), 제목 `N위로 마감했어요`, `기록 3:04:20`.
- 메달 2~3개(5v): 작은 글자 `{기간 표기} · {기간}`, 제목 `메달 N개를 땄어요`, 목록 줄마다 메달, 판 이름, `N위로 마감`, 오른쪽 기록.
- 메달 4개 이상(5w): 제목 아래 금·은·동 개수 줄, 목록은 앞 3개, 그 아래 `외 N개`.
- 기간이 섞이면(5x): 작은 글자는 가장 늦은 마감 시각으로 `10월 12일 (월) 00시 마감`, 줄마다 `{기간} · N위로 마감`(예: `일간 · 1위로 마감`)이다. 마감 시각이 여럿이면 줄의 기간 자리에 `recordPeriodShort`를 쓴다.
- 기록 값은 시간 판이면 `H:MM:SS`, 집중률이면 `96.0%`다.
- 목록 줄의 오른쪽 기록 값은 회색 목록 상자 위에 놓여 추월 시트의 파랑 값과 같은 `rank-value` 색을 쓴다.
- 아래에 `현재까지 메달을 {total}번 얻었어요`(메달 세 개 그림), 버튼 `랭킹 기록 보기`, 글자 버튼 `닫기`.

### 5i 공부 결과 랭킹 카드

- 테두리를 두른 카드에 `랭킹이 올랐어요`와 오른쪽 `랭킹 보기 ›`를 둔다.
- 큰 줄은 `주간 순공` `1,205위 → 1,202위` `▲3`(초록 배지)다.
- 칩 줄은 `저녁 구간 ▲9` `집중률 ▲208` `누적 시간 ▲41`처럼 판 이름과 오른 계단 수다.
- 판 이름은 순공이면 기간을 붙인 `일간 순공`·`월간 순공`, 집중률은 종목 이름, 시간대는 `{구간} 구간`, 명예의 전당은 `누적 시간`·`누적 일수`·`연속 공부`다.
- 순공에만 기간을 붙이는 까닭은 기간 없는 `순공 ▲150`이 바로 위 `주간 순공` 큰 줄과 같은 판처럼 읽혀 숫자가 어긋나 보이기 때문이다.
- 같은 판의 일간과 월간이 함께 오르면 더 많이 오른 하나만 그 기간 이름으로 쓴다.
- `▲N`은 화면 낭독기에 기호 이름 대신 `N계단 올랐어요`로 읽힌다. 칩은 `집중률 208계단 올랐어요`처럼 읽힌다.
- 응답이 오기 전에는 자리를 잡지 않고, 오면 나타난다.

## 10. 테스트

### 순수 함수 (vitest)

- 홈 팝업 판단: 공지·인터뷰·복구 창이 떴으면 쉼, unseen이 있으면 메달, 같은 날 두 번째 확인은 쉼, 메달 본 날은 추월 쉼, `since` 없으면 쉼, 날짜가 KST로 바뀌는 경계
- 메달 모달 모양 고르기: 1개, 2~3개, 4개 이상, 2개 이상이면 딴 순위와 관계없이 늘 같은 세 메달 그림, 기간 섞임, 마감 시각 여럿
- 칩 고르기: 같은 판 합치기, 최대 3개, 서버 순서, 순공만 기간 이름
- 표기: 메달 위 작은 글자, `+gap`, `▲N`

### 화면 (Testing Library)

- 추월 시트: 문구, 2명 목록, 두 버튼의 이동과 이벤트, 닫으면 다시 안 뜸
- 메달 모달: 다섯 모양의 문구, 띄운 직후 seen 호출, `랭킹 기록 보기` 이동
- 결과 카드: 주간 없으면 숨김, 404면 숨김, 빈 응답이면 숨김, 칩 3개, `랭킹 보기` 이동(솔로·소셜)
- 홈: 공지가 뜬 실행에는 랭킹 팝업이 안 뜸, 복구 창이 뜬 실행에도 안 뜸, 둘 다 없으면 메달 모달

## 11. 범위 밖과 후속

- 홈 한 줄 카드(5b)

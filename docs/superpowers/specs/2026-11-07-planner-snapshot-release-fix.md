# 플래너 스냅샷 복구와 릴리즈 사전 검사 보완

과목을 선택한 새 세션과 과목 변경 직후에는 다음 틱에서 실제 시각이 전진했는지 확인한 뒤 누적 스냅샷을 전송한다. 시계 정밀도 제한으로 같은 시각이면 10밀리초 뒤 다시 확인하며, 언마운트 시 재확인 타이머를 정리한다. 0길이 과목 구간은 서버에 전송하지 않는다. 기존 요청이 진행 중이면 요청이 끝난 뒤 최신 누적본을 한 번 더 보낸다. 평상시 30초 주기와 네트워크 실패 재전송은 유지한다.

서버의 `PUT /api/study-sessions/active?durable=true` 계약은 DB UPSERT 커밋 후에 성공을 반환한다. 구 앱용 같은 경로에도 적용한다. 파라미터를 생략한 기존 클라이언트는 메모리 버퍼를 사용한다. 서버 구현은 [backend#157](https://github.com/breathless-youth/backend/pull/157)의 v2.11.3 핫픽스이며 프런트 출시 전에 운영 반영이 필요하다. 전송 완료 전에 앱이 종료되거나 네트워크가 끊기면 복구는 마지막 성공한 체크포인트까지만 가능하다.

사전 검사의 `env.kv` 17건은 React key 표현식과 플래너 테스트 식별자였다. 사용자 소유 gstack 정책의 allowlist에 finding ID, 정확한 파일 경로, 해당 표현식 전체의 정규식과 사유를 기록했다. 실제 환경변수 값 검사와 다른 비밀값 검사는 유지한다. 시간 숫자 15가 할 일 글자 수의 옛 제한값으로 검출된 테스트는 90분 길이와 검증 동작을 유지하면서 어제 13:00~14:30으로 옮겼다.

## 로컬 검증 결과

- Node 24에서 웹 전체 테스트 7,154개 통과, 기존 서버 연동 통합 테스트 1개 건너뜀.
- 과목 변경 직후 전송, 진행 중 요청이 끝난 뒤 최신 과목 후속 전송, 시각이 전진하지 않을 때 0길이 보고를 미루는 동작을 회귀 테스트로 확인.
- 웹 타입 검사, 린트, 빌드와 변경 파일 형식 검사 통과.
- 서버 `gradlew check` 전체 통과. 이후 강화한 1밀리초 과목 구간의 즉시 DB 저장·복구 조회 테스트와 Checkstyle·Spotless도 통과.
- 최종 프런트 작업 트리에서 pregate `secrets,literals` 검사 모두 통과. 다른 pregate 단계나 운영 API 실호출을 검증한 결과는 아님.
- 서버 계약이 운영에 반영되기 전에는 기존 서버가 `durable` 쿼리를 무시하므로 DB 저장 보장이 적용되지 않음. backend#157의 배포 완료를 확인한 뒤 frontend#487을 출시한다.

## 릴리즈 통합 기준

최신 origin/dev의 그룹 카테고리 접기·소개 보기(#488)를 포함한다. 플래너 변경을 먼저 dev에 반영한 뒤 main 릴리즈를 병합한다. 병합 직전 후보와 dev, 병합 직후 main과 dev의 전체 파일 트리를 비교해 차이가 없는지 확인한다.

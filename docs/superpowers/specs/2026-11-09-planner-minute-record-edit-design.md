# 플래너 분 단위 대표 과목과 기록 편집

상태: BY-1204 범위 계약 확정. BY-1205 프론트엔드 구현과 로컬 검증 진행. 배포 서버의 실제 저장·재조회 검증은 별도 확인한다.

관련 작업: [BY-1205 FE](https://breathless-youth.atlassian.net/browse/BY-1205), [BY-1204 BE 계약](https://breathless-youth.atlassian.net/browse/BY-1204?focusedCommentId=10409), BY-1162, 기존 서버 기록 편집 BY-1167. 범위 계약 이전 서버 소스 확인 기준은 `bd4e3c522b01663d09f8af1acf6195f8775352f3`이다.

## 사용자가 확정한 동작

1. 플래너의 표시·선택 단위는 1분이다.
2. 같은 기록의 한 분 안에서 여러 과목을 공부했다면, 과목별로 그 분에 차지한 시간을 합산한다.
3. 합산 시간이 가장 긴 과목 하나를 표시한다. 동률이면 그 분 안에서 마지막 종료 시각이 늦은 과목을 표시한다.
4. 표시된 분의 과목을 바꾸면, 그 분에 속한 모든 과목 구간을 선택한 과목으로 바꾼다.
5. 표시된 분을 삭제하면, 그 분에 속한 실제 기록 구간을 함께 개인 기록에서 제외한다.
6. 선택 범위 밖의 분과 다른 기록은 보존한다. 과목 변경으로 공부시간·순공시간이 바뀌지 않는다.
7. 원래 측정한 데이터와 랭킹 값은 기존 개인 기록 편집 원칙대로 유지한다.

20초마다 세 과목을 바꾼 경우에도 20초 선택 목록이나 세 색으로 나누는 UI는 만들지 않는다.

| 한 분 안의 원본 구간                           | 표시         | 과목 변경                          | 삭제                            |
| ---------------------------------------------- | ------------ | ---------------------------------- | ------------------------------- |
| 12:00:00–12:00:20 A, :20–:40 B, :40–12:01:00 C | C            | A·B·C 구간 모두 선택 과목으로 변경 | 세 구간 모두 개인 기록에서 제외 |
| A 30초, B 20초, C 10초                         | A            | 해당 분의 모든 구간 변경           | 해당 분의 실제 구간 제외        |
| A 20초, B 20초, A 20초                         | A, 합계 40초 | 해당 분의 모든 구간 변경           | 해당 분의 실제 구간 제외        |

## 표시와 실제 기록의 분리

대표 과목은 표시를 위한 값이다. 대표에서 제외된 과목 구간을 조회·저장 데이터에서 합치거나 없애지 않는다. 분 색칠 결과로 공부·순공 합계를 다시 계산하지 않는다.

계산은 원본 구간을 `[minuteStart, minuteEnd)`과 먼저 교차시킨 후 수행한다. 과목별 교차 길이의 합과 가장 늦은 교차 종료 시각을 비교한다. 분 올림이나 표시 폭 확대를 먼저 하면 짧은 구간의 비율이 바뀌므로 비교에 쓰지 않는다. 소수초 차이를 비교할 때 정수 초로 먼저 버리지 않는다.

선택 식별자는 기존 부모 기록 키와 UTC 분 시작 시각의 조합이다. 같은 분에 서로 다른 기록 키가 있더라도 하나의 수정 대상으로 합치지 않는다. 시간대에 따른 날짜 조회 창과 분 표시는 기존 플래너의 시간대 정책을 따른다.

현재 과목 구간의 벽시계 경계에는 PAUSE가 포함될 수 있다. 대표를 고르는 구간 점유 길이와 기존 `studySec`·`focusSec`는 별개로 취급한다. PAUSE를 제외한 분별 공부시간으로 대표를 고르려면 서버가 이벤트를 절삭한 분별 값을 제공해야 한다. 구간 전체의 `studySec`를 분마다 비례 배분해 추정하지 않는다.

과목 없는 실제 공부, 원래 비어 있는 시간, 일시정지와 삭제로 비워진 시간은 서로 구분돼야 한다. `subjectSegments`의 빈 부분만 보고 실제 과목 없는 공부라고 추정하지 않는다.

## 범위 계약 이전 API의 제약

계약 확장 전 FE의 편집 블록은 `record.key` 하나를 사용한다. 세션의 과목 이름을 이어 붙이며, 시간과 삭제도 같은 부모 키로 저장한다.

기존 BE `UPDATE`는 그 키의 전체 기록을 수정본 하나로 덮어쓰고, `DELETE`는 전체 키에 삭제 표식을 남긴다. 선택한 한 분의 시작·끝만 기존 `UPDATE`에 보내면 앞뒤 분이 개인 기록에서 사라진다. 기존 검증은 변경 경계를 분으로 내리고 최소 1분을 요구해 37초 기록의 실제 경계를 보존하는 범위 수정에도 맞지 않는다.

부모를 지운 뒤 여러 수동 기록을 생성하는 방식은 사용하지 않는다. 측정 출처·순공 의미가 달라지며, 현재 배치가 작업별 트랜잭션이라 일부만 성공할 수 있다.

따라서 기존 부모 키 API에 가상 분 블록을 연결하는 FE 변경은 배포하지 않는다. 서버의 분 범위 수정 계약을 먼저 확장한다.

## 백엔드 전달사항

### 조회

- 부모 기록 키와 수정 충돌을 확인할 revision을 제공한다.
- 현재 개인 기록에서 실제 존재하는 조각을 정확한 시작·끝과 과목 유무로 제공한다.
- 실제 과목 없는 공부와 삭제·미기록 공백을 구분할 수 있어야 한다.
- 공부·순공·측정 출처와 변경 여부를 기존 개인 기록 투영과 일치시킨다.
- 날짜 창으로 잘린 표시 경계와 수정 가능한 원본 경계를 혼동하지 않도록 한다.

### 저장

- 타깃은 부모 기록 키와 선택한 UTC 분 또는 연속 분 범위다. 끝은 exclusive다.
- 적용 범위는 현재 개인 기록의 실제 조각과 선택 범위의 교집합이다. 실제 37초를 60초로 늘리거나 빈 시간을 만들지 않는다.
- 과목 변경은 교집합 안의 모든 과목 구간에 적용한다. `subjectId=null`은 시간 삭제가 아니라 과목 없음으로 변경한다.
- 삭제는 교집합만 개인 기록에서 제외한다. 중간 분 삭제로 생긴 빈 구간이 조회 후 되살아나지 않아야 한다.
- 앞뒤 분과 같은 분의 다른 부모 기록은 보존한다. 원본 측정·이벤트·랭킹은 바꾸지 않는다.
- 한 부모의 변경 분 목록을 하나의 원자적 명령으로 처리하고 부모 revision을 한 번 검사한다. 같은 revision을 넣은 독립 분 작업을 연속 호출해 두 번째 작업이 stale이 되도록 만들지 않는다.
- `operationId` 재전송은 최초 결과를 재생한다. 동시 수정 충돌은 409와 최신 조회 복구 계약으로 처리한다.
- 서로 다른 부모 기록 사이의 부분 성공은 현재 저장 복구 방식과 호환되게 응답한다.

권고 구조는 기존 부모 개인 수정본에 범위별 수정·삭제 표식을 합성하는 것이다. 논리 과목 구간 ID나 과목별 20초 편집 API는 새로 요구하지 않는다. 확정된 endpoint·필드명은 아래 계약에 따라 `packages/types`에 반영했다.

## 확정된 BY-1204 계약

- 조회 입력은 `records[].pieces`와 `revision`이다. revision 0과 빈 pieces 배열도 유효하다. 구계약 응답은 표시할 수 있지만 분 수정은 비활성화한다.
- 저장은 기존 `POST /api/planner/records/batch`에 `EDIT_RANGES`를 추가한다. 한 부모의 모든 범위를 한 작업으로 묶고 필수 revision을 보낸다.
- UTC 분 경계의 `[startedAt, endedAt)` 범위만 쓰며, 1분 이상·최대100개·작업 내 비겹침을 지킨다. 같은 변경 종류와 과목의 인접 범위만 합친다.
- `SUBJECT`의 subjectId null은 과목 없음이다. `DELETE`와 구분한다. 선택 범위의 실제 조각만 바꾸고 빈 시간을 채우지 않는다.
- 저장 전 초안에서 삭제한 분도 넓은 과목 선택으로 되살리지 않는다. 삭제된 분에 새 수동 기록을 만드는 경우는 별도 CREATE다.
- 항목409 `STALE_RECORD`는 재시도 대기열에서 제외하고 canonical 재조회 후 다시 선택한다. 다른 부모의 미저장 변경과 새 기록은 보존한다.
- 응답 유실은 최초 operationId·revision·본문을 그대로 재전송한다. 성공 응답의 revision을 확인하며 재조회 실패 재시도는 저장 요청을 다시 보내지 않는다.

## 프론트엔드 변경 범위

- 기존 과목색 토큰, 격자 그리기와 `RecordBlockSheet`·`RecordSubjectSheet`·`RecordDeletePopover`를 재사용한다.
- 원본 정밀 구간에서 대표 과목을 고르는 계산을 별도 순수 함수로 둔다. 이미 분으로 올림한 `plannerRecordPaints` 결과를 투표 입력으로 쓰지 않는다.
- 현재 부모 키 하나인 선택 상태를 부모 키와 선택 분 범위로 바꾼다. 패널의 과목·강조·삭제 대상·손잡이는 그 범위를 표시한다.
- 저장은 새 범위 계약으로 연결한다. 기존 계정 변경 중단, 같은 operationId 재시도, 부분 성공 후 재조회 동작은 재사용한다.
- 서버의 범위 계약이 확정되기 전에는 기존 전체 기록 수정 API로 분 편집을 흉내 내지 않는다.

## 수용 테스트

- [ ] A/B/C 각 20초이면 C, 30/20/10초이면 A를 표시한다.
- [ ] 같은 과목이 떨어져 나타나도 합산하고, 합산 동률은 가장 늦은 종료 시각으로 결정한다.
- [ ] 입력 배열 순서가 결과를 바꾸지 않는다. 소수초 차이도 정밀하게 비교한다.
- [ ] 분 경계에 걸친 구간은 각 분에 실제 교차 길이만 기여한다.
- [ ] 37초 기록의 원본 시작·끝과 공부·순공은 표시 뒤에도 보존된다.
- [ ] 대표가 C인 분을 A로 바꾸면 그 분의 모든 구간이 A가 되고 앞뒤 분은 유지된다.
- [ ] 가운데 한 분 삭제 후 앞뒤 경계·과목·공부·순공이 그대로이며 재조회 뒤 삭제 구간이 다시 나타나지 않는다.
- [ ] 과목 없음 변경과 삭제가 서로 다른 결과를 만든다.
- [ ] 같은 분의 다른 부모 기록, 자정·05시 경계와 DST 반복 분을 구분한다.
- [ ] PAUSE·비집중이 있는 기록의 공부·순공을 대표 색칠로 다시 계산하지 않는다.
- [ ] 여러 분 저장의 원자성, revision 충돌, 응답 유실 재시도와 계정 전환을 확인한다.

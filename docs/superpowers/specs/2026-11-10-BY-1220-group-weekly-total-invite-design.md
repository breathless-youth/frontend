# BY-1220 그룹 주간 합계 순공과 빈자리 초대 설계

- 티켓: BY-1220(FE), BY-1221(BE), 상위 스토리 BY-1123
- 브랜치: `feature/BY-1220-group-weekly-total-invite` (base `origin/dev` `572f8b17`)
- 시안: 그룹 공부방 캔버스 40번 줄, 40-A를 골랐다(2026-11-10)

## 왜 하는가

공개 그룹 카드와 소개 화면은 이번 주 멤버 평균 순공을 보여 줬다. 사용자는 그룹이 함께 공부한 양을 보여 주고 싶어 했고, 평균보다 합계가 그 뜻에 맞다.

그룹 홈 빈자리는 바로 가입하는 공개 그룹에서 아무 글자도 없이 비어 있었다. 빈자리는 사람을 더 데려올 자리라서, 그 자리에서 바로 초대 링크를 보낼 수 있어야 한다.

비공개 그룹 초대 링크로 들어오면 코드가 채워진 입력 화면에서 참여하기를 한 번 더 눌러야 했고, 공개 그룹에는 초대 링크가 아예 없었다.

## 목표

- 공개 그룹 카드와 공개 그룹 소개 화면이 이번 주 멤버 순공 합계를 보여 준다.
- 멤버가 보는 그룹 홈의 빈자리를 누르면 그 그룹 초대 링크를 공유한다.
- 비공개 그룹 링크로 들어오면 바로 가입한다.
- 공개 그룹 링크로 들어오면 그룹 소개 화면이 열린다.
- 지금 설치된 앱에서도 웹 배포만으로 위 동작을 한다.

## 하지 않는 것

- 앱 셸(`apps/mobile`)은 바꾸지 않는다.
- 그룹 홈의 `이번 주 순위` 카드(멤버별 주간 순공)는 바꾸지 않는다.
- 가입 전에 보는 공개 그룹 소개 화면의 빈자리는 바꾸지 않는다.
- 메뉴의 기존 `초대하기`(비공개 그룹)는 그대로 둔다.

## 실패로 볼 것

- 지금 설치된 앱에서 공개 그룹 링크를 눌렀는데 그룹 탭 첫 화면이 열린다.
- 비공개 링크로 들어왔는데 사용자가 아무것도 누르지 않았는데 가입이 두 번 요청된다.
- 공개 그룹 링크 모양이 비공개 6자리 초대코드와 겹쳐서 엉뚱한 그룹 참여를 시도한다.
- 화면 숫자는 합계인데 목록 순서는 평균 순서로 남는다.

## 정해진 것

### 주간 합계 (사용자 결정)

- 서버가 공개 그룹 목록 카드와 상세에 `weeklyTotalFocusSec`를 새로 내려 주고, 목록을 합계 순으로 정렬한다(BY-1221).
- 앱은 이 값을 그대로 보여 주고 순서는 서버 정렬을 따른다.
- 카드 문구는 `이번 주 합계 N시간 N분`, 소개 화면 제목은 `이번 주 멤버 순공 합계`다.
- `packages/types`의 `weeklyTotalFocusSec`는 BE Swagger에 올라온 이름과 타입으로 맞춘다. 저장소 규칙상 Swagger에 없는 필드를 먼저 만들 수 없으므로, BE가 개발 서버에 올리기 전에는 가짜 서버(`groupRoomMockData.ts`)로 개발하고 FE PR은 BE가 개발 서버에 배포된 뒤 머지한다.
- 앱은 `weeklyAverageFocusSec`를 더 읽지 않는다. 서버는 당분간 두 필드를 함께 내려 준다.

### 빈자리 초대하기 (사용자 결정, 시안 40-A)

- 멤버가 보는 그룹 홈(`RoomHomeScreen`)의 빈자리마다 보인다.
- 공개·비공개 그룹 모두, 그룹장과 멤버 모두에게 보인다.
- 모양은 지금 점선 사람 그림을 그대로 두고, 그 아래 회색 `빈자리`와 `신청을 받고 있어요` 대신 파란 `+ 초대하기` 한 줄을 둔다.
- 바로 가입하는 공개 그룹에서 숨기던 빈자리 글자도 이 한 줄로 바뀐다.
- 빈자리 칸 전체가 하나의 버튼이고 터치 영역은 44px 이상이며 읽기 이름은 `초대하기`다.
- 누르면 앱에서는 공유 시트가 열리고, 공유 기능이 없는 브라우저에서는 링크를 복사하고 지금과 같은 복사 토스트를 띄운다(`shareInvite`의 지금 동작).

### 초대 링크 모양 (사용자 결정)

- 비공개 그룹은 지금 초대코드 링크 `/social/join?code=<6자리>`를 그대로 보낸다.
- 공개 그룹은 `/social/join?code=go-<groupId>`를 보낸다.
- `code` 칸에 넣는 이유는 앱 셸 `app/social/join.tsx`가 `code` 값만 웹으로 넘기고 다른 값은 버리기 때문이다. 이렇게 해야 앱을 새로 내지 않아도 된다.
- 접두가 `go-`인 이유는 6자리 초대코드와 겹치지 않게 하려는 것이다. 앱 셸은 하이픈을 지우고 대문자로 바꾼 6자리가 초대코드 글자면 그룹 초대코드로 넘기는데, 서버 초대코드에는 `O`가 없어서 `GO`로 시작하면 초대코드가 되지 않는다(처음 정한 `g-`는 `g-23456`이 `G23456`이 되어 PR 리뷰에서 바꿨다). 판별은 하이픈을 지우는 `normalizeInviteCode`보다 먼저 원래 값으로 한다.
- 오리진은 지금 `inviteLink`처럼 떠 있는 웹 오리진을 쓴다.

### 링크로 들어온 사람 (사용자 결정)

- 공개 그룹 링크는 승인제·바로 가입 모두 그룹 소개 화면 `/social/public/<groupId>`를 연다. 신청서는 거기서 `신청하기`를 눌러 들어간다. 처음 요청은 "신청서를 바로 보게"였지만 사용자가 "공개 그룹은 무조건 그룹 소개 화면"으로 바꿨다.
- 비공개 그룹 링크는 화면이 열리고 신원이 정해지면 한 번만 자동으로 가입을 요청하고, 성공하면 그룹 홈으로 보낸다.
- 비공개 자동 가입이 실패하면 지금처럼 코드가 채워진 입력칸 아래에 오류 한 줄을 보여 주고, 사용자는 거기서 다시 참여하기를 누를 수 있다.
- 이미 멤버면 서버가 그룹을 알려 주므로 지금처럼 그룹 홈으로 보낸다.

### 공유 문구 (내 판단)

- 비공개는 지금 문구(`social-room:inviteMessage.body`, 링크와 초대코드)를 그대로 쓴다.
- 공개는 초대코드 줄을 뺀 `그룹 스터디에 초대받았어요!` + 링크 문구를 새 키로 둔다. 영어도 같이 넣는다.

### 계측 (내 판단)

- 빈자리 초대 누름은 새 이벤트 `group_invite_shared`에 `visibility`(`public`·`private`)와 `source: "empty_seat"`를 싣는다.
- 링크 진입은 아래 "링크 진입 계측 보충"을 따른다.
- 비공개 자동 가입은 지금처럼 `group_room_joined`의 `via: "invite_link"`로 남는다.

## 제약

- 아키텍처 경계와 개인정보 원칙은 바뀌지 않는다. 링크에는 그룹 ID만 실리고 개인 정보는 없다.
- 모든 사용자 문구는 ko·en 카탈로그로 넣는다(i18n 린트).
- 색·간격은 디자인 토큰을 쓴다. 파란 글자는 `text-primary`다.
- 테스트는 Kent Beck TDD로 하나씩 Red → Green → Refactor로 진행한다.

## 알려진 빈자리

- Android에서 공개 그룹 링크를 누르고 앱을 새로 설치한 사람은 첫 실행 때 그룹 탭이 열린다. 앱의 설치 경로 복원(`installReferrerInvite.ts`)이 숫자 4자리와 영문 6자리만 받기 때문이고, 고치려면 앱 빌드가 필요하다.
- 공부 중(세션 화면이 열린 상태)에 공개 그룹 링크를 누르면 소개 화면이 세션 위에 시트로 쌓인다. 셸의 `offerRouteToSession`과 `navigate-home`의 `inviteCode`가 `inviteCodeFrom`으로 숫자 4자리와 영문 6자리만 받아서 `go-<id>`를 가로채지 못하기 때문이다. 고치려면 앱 빌드가 필요하다.
- 앱을 깔지 않은 휴대폰 브라우저에서 공개 그룹 링크를 열면 지금 초대 안내 화면이 뜬다. 이 화면은 초대코드를 크게 보여 주는데, 공개 그룹은 보여 줄 코드가 없으므로 코드 칸 없이 앱 열기·스토어 버튼만 보인다. 앱 열기는 같은 `code=go-<id>` 값을 앱으로 넘긴다(내 판단).
- 컴퓨터 브라우저에서 공개 그룹 링크를 열면 지금 6자리 코드 안내 화면과 같은 제목·설명만 보이고 코드 칸과 버튼은 없다(내 판단).
- `groupRooms=1` 표시가 없는 예전 앱은 `InviteCodeJoinPage`를 여는데, 공개 그룹 링크는 코드 없는 링크처럼 빈 입력칸으로 연다(내 판단).

### 링크 진입 계측 보충 (내 판단)

- `invite_link_opened`는 지금처럼 `InviteCodeJoinPage`에서만 보내고 `invite_kind`만 더한다. 지금까지 쌓인 이벤트의 뜻을 바꾸지 않기 위해서다.
- 그룹 공부방 앱 안의 링크 진입은 `InviteJoinRoute`의 그룹 분기에서 새 이벤트 `group_invite_link_opened`(`invite_kind`: `group`·`public`)로 보낸다. 셸의 `invite_deep_link_opened`는 앱이 열린 사실만 세므로 겹치지 않는다.

## 만드는 사람에게 맡기는 것

- 링크 판별을 `parseInviteParam`에 `{ kind: "public"; groupId }`로 더할지, 별도 함수로 둘지.
- 공개 그룹 공유를 `shareInvite`를 일반화해 처리할지, 문구만 받는 새 함수로 둘지.
- `DeskGrid`·`TodayDesksCard`에 `onInvite`를 넘기는 방식과 `hideEmptySeatCopy`를 정리하는 방식.
- 자동 가입이 StrictMode 두 번 실행에서도 한 번만 나가게 막는 방법.

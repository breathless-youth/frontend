# 배경음(백색소음·앰비언트) 1차 설계 (2026-09-20, BY-682)

상태: **승인(2026-09-20)**. 티켓은 BY-681(스토리) → BY-682(1차, 이 브랜치) → BY-683(2차). 로드맵 근거는 `reports/05-MVP-구현-실행전략.md`의 부가 기능 ③ "백색소음 — 집중 유지용 배경음 재생".

## 결론

**백엔드 변경 없음, 네이티브 변경 없음. 새 npm 의존성은 shadcn 스위치·툴팁·탭이 쓰는 `@radix-ui/react-switch`·`@radix-ui/react-tooltip`·`@radix-ui/react-tabs` 셋.** 재생은 `apps/web`의 Web Audio API로 처리하고, 화이트·핑크·브라운 노이즈는 파일 없이 합성한다. 자연음(빗소리·카페)은 라이선스가 확인된 mp3 루프를 `public/sounds/`에 둔다(BY-689). lofi·음악은 허용 라이선스 트랙 확보가 어려워 BY-683으로 미룬다.

코드베이스 실측(2026-09-20)으로 확인한 전제 넷이 범위를 결정했다.

- 오디오 코드와 오디오 라이브러리가 저장소에 전혀 없다. 충돌할 기존 구현이 없다.
- 소셜룸 P2P는 영상 전용이다(`visionConfig.ts`의 `audio: false`, `peerMesh.ts`는 video 트랜시버만). 마이크도 상대 음성도 없으므로 믹싱·에코 문제가 없다.
- 세션은 백그라운드 진입 시 이미 일시정지된다(`useStudyRoomSession.ts`의 백그라운드 연결부, `systemPauseSource.ts`). 따라서 **백그라운드 재생·`UIBackgroundModes`·Android 포그라운드 서비스가 필요 없다.** 이 사실이 범위를 가장 크게 줄였다.
- WebView는 `mediaPlaybackRequiresUserAction={false}`와 `allowsInlineMediaPlayback`이 이미 켜져 있다(`RemoteWebViewHost.tsx`). 빠진 것은 iOS 무음 스위치를 무시하는 속성 하나뿐이다.

## 1. 사용자 흐름

1. 세션 화면 우상단 배경음 버튼을 탭하면 오른쪽에서 사이드 시트가 열린다.
2. 카탈로그의 모든 소리가 아이콘·이름 줄과 그 아래 슬라이더로 보이고, 조작하기 전에는 전부 0이다.
3. 슬라이더를 올리면 그 소리가 난다. 0으로 내리면 꺼진 것으로 본다. 겹쳐 켜는 개수에 상한은 없다.
4. 이름 줄을 누르면 켜고 끈다. 끄면 슬라이더가 0으로 가고, 다시 켜면 직전에 듣던 음량으로 돌아온다. 그 음량은 세션 안에서만 기억한다.
5. 일시정지(수동·백그라운드)에 소리가 멈추고 재개에 다시 난다. 종료와 화면 이탈에 정지된다. 멈춘 동안 슬라이더를 올려도 조용한 것이 고장으로 읽히므로, 제목 옆 안내 툴팁이 그 이유를 알려 준다.
6. 비집중이 감지되면 전체 음량이 1초에 걸쳐 40%로 내려가고, 집중으로 돌아오면 원래대로 복귀한다. 시트의 스위치로 끌 수 있고 기본은 켜짐이다.
7. 다음 세션 시작 시 마지막 믹스가 비어 있지 않으면 자동으로 재생된다.
8. 브라우저 단독 배포에서도 같은 흐름이다. 네이티브 브리지가 없어도 예외가 없다.

화면 문구는 "배경음"으로 통일하고 개별 항목만 "백색소음" 등으로 부른다.

## 2. 아키텍처

`apps/web/src/features/ambient-sound/`에 담는다. 계산은 순수 모듈, 컴포넌트는 그리기만 한다.

```
슬라이더 조작 ───┐
세션 상태 ───────┤→ useAmbientSound ─→ AmbientPlayer(Web Audio) ─→ 스피커
localStorage ────┘        │
                          ├→ ambientSoundStore(마지막 믹스·연동 토글)
                          └→ usageRef(사용 시간) → study_session_ended
```

| 모듈                                | 역할                                                                         |
| ----------------------------------- | ---------------------------------------------------------------------------- |
| `catalog.ts`                        | `SoundId`, 카탈로그 타입, `public/sounds/catalog.json` 파서, `DEFAULT_LEVEL` |
| `mix.ts`                            | 믹스 모델과 순수 변환 함수(레벨 조정, 카탈로그 순서 정렬)                    |
| `noiseSynth.ts`                     | 화이트·핑크·브라운 샘플 생성                                                 |
| `ambientPlayer.ts`                  | Web Audio 구현과 테스트용 메모리 구현                                        |
| `ambientSoundStore.ts`              | 설정 저장. `onboardingGuideStore.ts` 패턴을 따른다                           |
| `ambientUsage.ts`                   | 재생 누적 시간 계산(순수)                                                    |
| `useAmbientSound.ts`                | 세션 상태를 플레이어 명령으로 옮기는 훅                                      |
| `components/AmbientSoundButton.tsx` | 우상단 원형 버튼                                                             |
| `components/AmbientSoundSheet.tsx`  | 오른쪽 사이드 시트. 공용 `ui/sheet.tsx` 위에 세션 색을 입힌다                |
| `components/soundIcons.ts`          | 소리 id → lucide 아이콘. 모르는 id 는 스피커로 떨어진다                      |

핵심 규칙 셋이다.

- **믹스가 진실이다.** UI도 저장소도 플레이어도 `Mix` 값 하나를 주고받는다. 플레이어는 `applyMix(mix)`를 받아 현재 그래프와의 차이만 반영한다.
- **헤드룸과 집중 연동은 게인 노드를 따로 쓴다.** 소리별 게인 → 헤드룸 게인 → 덕킹 게인 → 리미터 → 출력. 한 노드에 겹치면 서로의 램프를 취소한다. 덕킹은 1초, 헤드룸은 150ms 라, 덕킹이 도는 중에 소리 하나만 꺼도 남은 구간이 지워지고 150ms 만에 목표에 닿는다. 노드를 나누면 각자 자기 시간축을 갖고 곱은 그래프가 해 준다.
- **클리핑은 출력단 리미터가 막는다.** 아래 제곱합 예산은 실효값을 다루는 근사라 순간 피크가 같은 방향으로 겹치는 경우까지 보장하지 못한다. 마지막에 `DynamicsCompressorNode` 를 한 단 두고, 평소 소리는 threshold 아래라 그대로 지나간다.
- **합성 노이즈는 종류마다 시드가 다르다.** 같은 시드면 핑크·브라운이 화이트와 같은 난수열을 거른 것이라 서로 상관을 갖고, 비상관 전제가 깨진다.
- **헤드룸 게인이 겹침을 감당한다.** 소리 버퍼는 저마다 피크가 1이라 여러 개를 최대로 겹치면 출력단에서 깨진다. 노이즈끼리는 상관이 없어 합의 실효값이 게인 제곱합의 제곱근으로 자라므로, 그 제곱합에 헤드룸의 제곱을 곱한 값을 0.75 아래로 묶는다. 소리가 셋 이하일 때는 이 식이 0.5를 그대로 돌려줘 예전 고정값과 음량이 같고, 넷째부터만 줄어든다.
- **헤드룸은 실제로 나는 소리만 센다.** 믹스가 아니라 재생 중인 보이스를 세므로, 파일을 못 받아 실패한 소리 때문에 나머지가 조용해지지 않는다. 보이스가 시작·정지하거나 레벨이 바뀌는 즉시 다시 재며, 느린 파일 하나를 기다리느라 늦어지지 않는다.
- **브라우저 단독에서도 같은 코드다.** 브리지·네이티브 의존이 없고, `AudioContext`가 없는 환경에서는 메모리 플레이어로 대체돼 예외가 나지 않는다.

### 믹스 모델

```ts
type Mix = Readonly<Partial<Record<SoundId, number>>>; // 값은 1~100 레벨
```

소리는 키가 존재하면 켜진 것이다. 레벨 0은 키를 지우는 것과 같게 정규화한다. 순수 함수만 둔다.

| 함수                       | 규칙                                                                                             |
| -------------------------- | ------------------------------------------------------------------------------------------------ |
| `setLevel(mix, id, level)` | 0~100으로 자르고, 0이면 키를 지운다. 켜는 개수에 상한이 없어 이것 하나가 켜고 끄는 유일한 통로다 |
| `activeIds(mix, catalog)`  | 카탈로그 순서로 정렬한 켜진 소리 목록. 저장과 분석이 이 순서를 쓴다                              |

아이콘 토글은 훅이 `setLevel`로 만든다. 끌 때는 그때 음량을 기억했다가 0을 주고, 켤 때는 기억한 값을 돌려준다. 기억한 적이 없으면 `DEFAULT_LEVEL`이다. 이 기억은 세션 안에서만 살아 있고 저장하지 않는다.

### 저장 모델

키는 `focuson.ambientSound.v1`이고 값은 JSON 한 덩어리다.

```json
{ "mix": { "white": 60, "rain-trp": 40 }, "duckEnabled": true }
```

`onboardingGuideStore.ts`의 교체 가능한 저장소 패턴을 그대로 복사한다. 인터페이스, localStorage 구현, 메모리 구현, 교체 함수, 리셋 함수 다섯이 한 파일에 있다. 서버 저장으로 바꿀 때 구현체만 갈아 끼운다.

sessionStorage를 쓰지 않는 이유는 `socialRoomNotice.ts` 상단 주석과 같다. 탭 화면과 세션 화면이 별도 WebView라 sessionStorage가 공유되지 않는다.

읽기는 방어적으로 한다. 접근 자체가 throw할 수 있고(프라이버시 모드), 저장된 JSON이 깨졌거나 카탈로그에 없는 소리 id를 담고 있을 수 있다. 어느 경우든 기본값으로 떨어뜨리고 예외를 밖으로 내지 않는다.

## 3. 재생 엔진

오디오 그래프는 한 줄로 고정한다. 켜진 소리마다 `AudioBufferSourceNode(loop)` → 소리 게인 → 헤드룸 게인 → 덕킹 게인 → 리미터 → 출력.

재생 시간 계측은 `applyMix` 의 resolve 가 아니라 **들리는 상태가 바뀌는 순간**에 맞춘다(`onPlaybackChanged`). 세 가지를 모두 잡아야 한다.

- 보이스가 시작하는 순간. resolve 를 기다리면 파일 하나가 늦게 오는 동안 이미 나고 있던 합성음의 시간이 빠진다.
- 페이드아웃이 **끝나는** 순간. 끄는 순간에 끊으면 켜고 끌 때마다 150ms 씩 빠진다. 그래서 꺼지는 중인 개수를 따로 세고, `source.onended` 로 진짜 종료를 받는다. 보이스 자체는 곧바로 지워야 다시 켤 때 새로 시작된다.
- 우리가 부르지 않은 멈춤(전화·알람)과 그 복구 시도. 알리지 않고 되살리기만 하면, 복구가 막힌 동안 통화 시간이 통째로 배경음 사용 시간에 더해진다.

| 명령                     | 동작                                                                                                                                                                                              |
| ------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `applyMix(mix)`          | 현재 그래프와의 차이만 반영한다. 새로 켜진 소리는 버퍼 준비 후 150ms 페이드 인, 꺼진 소리는 150ms 페이드 아웃 뒤 정지, 레벨만 바뀐 소리는 게인 램프. 불러오지 못한 소리를 `{ failed }`로 돌려준다 |
| `setDucked(bool)`        | 덕킹 게인만 1초 선형 램프로 0.4 와 1 사이로 옮긴다. 헤드룸은 건드리지 않는다                                                                                                                      |
| `suspend()` / `resume()` | `AudioContext`를 멈추고 되살린다. 그래프를 유지하므로 재개가 즉시다                                                                                                                               |
| `dispose()`              | 소스를 멈추고 컨텍스트를 닫는다                                                                                                                                                                   |
| `getState()`             | `idle` · `playing` · `suspended` · `blocked`                                                                                                                                                      |

**깨우기는 버퍼 작업보다 먼저 나가야 한다.** iOS 사파리는 사용자 조작의 호출 스택 안에서 부른 `resume`만 받아들인다. 파일을 받고 디코딩한 뒤에 부르면 그때는 조작이 끝나 있어 무시되고, 컨텍스트가 `suspended`로 남아 소리가 나지 않는다. 합성음도 마찬가지다. 버퍼 생성 자체는 동기여도 `await`를 한 번 거치는 순간 제스처 밖이다. 그래서 `applyMix`는 보이스를 만지기 전에 `tryResume()`을 먼저 걸고, 그 약속을 끝에서 기다린다.

`AudioContext`는 첫 `applyMix`가 빈 믹스가 아닐 때 게으르게 만든다. WebView는 자동 재생이 허용돼 세션 시작 직후 소리가 나고, 브라우저 단독에서는 슬라이더 조작 안에서 첫 `applyMix`가 일어나 제스처 조건을 만족한다. `resume()` 뒤에도 `suspended`면 `blocked`로 두고 다음 사용자 탭에서 다시 시도한다. 별도 안내 시트은 만들지 않는다.

버퍼 준비는 소리 종류로 갈린다. 합성 3종은 `noiseSynth`가 채운 4초 배열을 `createBuffer`에 넣고, 파일은 `fetch` 후 `decodeAudioData`를 거친다. 결과는 인스턴스 안 `Map`에 캐시하고 진행 중인 디코딩은 Promise를 공유해 같은 소리를 두 번 받지 않는다. 실패한 소리는 믹스에서 빠지고 `failed`로 보고된다.

인터럽션은 `statechange` 구독으로 잡는다. 우리가 부르지 않았는데 멈추면(iOS의 전화·알람) 상태를 `suspended`로 바꾸고, 훅이 세션 복귀와 다음 사용자 탭에서 `resume()`을 시도한다.

노이즈 생성은 다음 세 가지다. 화이트는 균등난수, 핑크는 Paul Kellet 근사 필터, 브라운은 누설 적분이다. 생성 결과는 최대 진폭이 1을 넘지 않게 정규화한다. 난수는 결정적 시드를 쓴다. 테스트가 같은 입력에 같은 출력을 요구하고, 스크립트 환경에서 `Math.random()`을 쓰지 않는 편이 재현에 유리하다.

테스트용 `createMemoryPlayer()`는 같은 인터페이스로 명령을 배열에 기록만 한다. 훅과 시트 테스트는 이것을 주입하고, Web Audio 구현은 최소한의 가짜 `AudioContext`를 주입해 명령 순서를 확인한다.

mp3 인코더 패딩 때문에 루프 경계에 클릭이 들리면 `loopStart`와 `loopEnd`를 안쪽으로 당기는 보정을 넣되, 스파이크 S5 결과가 나오기 전에는 넣지 않는다.

## 4. 세션 연동

`useAmbientSound`가 세션 상태를 플레이어 명령으로 옮긴다.

| 세션 쪽 사건                                                    | 플레이어 명령                        |
| --------------------------------------------------------------- | ------------------------------------ |
| 세션 시작(`phase === "studying"`, 저장된 믹스가 비어 있지 않음) | `applyMix(저장된 믹스)`              |
| `sessionState.kind === "PAUSE"`                                 | `suspend()`                          |
| 일시정지 해제                                                   | `resume()`                           |
| `sessionState.kind === "DISTRACTION"` 이면서 연동이 켜짐        | `setDucked(true)`                    |
| `FOCUS`로 복귀                                                  | `setDucked(false)`                   |
| 세션 종료(`phase !== "studying"`) 또는 언마운트                 | `dispose()`                          |
| 컨텍스트가 스스로 멈춤                                          | 세션이 진행 중이면 `resume()` 재시도 |

일시정지와 비집중이 겹칠 수 없다. `SessionState`가 배타적 유니온이라 한 번에 하나다.

비집중 판정 자체가 유지 시간(`detection.ts`의 `enterMs`·`exitMs`)을 이미 거치므로 깜빡임 방지 로직을 새로 만들지 않는다. 1초 램프가 남은 거슬림을 없앤다.

### 사용 시간 계측

`study_session_ended`에 `ambient_sound_used`와 `ambient_sound_sec`를 실으려면 재생 시간이 세션 훅까지 가야 한다. 두 훅 사이에 순환이 생기지 않게 `RoomPage`가 `useRef`로 그릇을 만들어 양쪽에 넘긴다. `useAmbientSound`가 값을 갱신하고 `useStudyRoomSession`은 종료 시점에 읽기만 한다. 누적 계산은 `ambientUsage.ts`의 순수 함수가 맡는다.

## 5. 화면 배치

시안(BY-685)은 아직 없다. 이번 범위는 **세션 안에서 조정만 되면 되고 기존 화면과 어울리게 놓는 것**이 지시다. 따라서 다음을 지킨다.

- 컨트롤 바에 네 번째 버튼을 넣지 않는다. 세로 바는 `244px` 고정이고 버튼 하나를 더하면 `314px`이 되어 폭 `320px` 기기의 좌우 여백 안에 들어가지 않는다.
- 대신 세션 레이어 **우상단**에 지름 44px 원형 버튼을 절대 배치한다. 세로는 상태 필이 상단 중앙이고 좌우가 비어 있어 그 높이에 그대로 둔다.
- **가로에서는 상태 필 아래로 내린다.** 가로 1행 3열은 비어 있지 않고 순공시간·총공부시간(`SessionTimer`)이 오른쪽 끝에 붙어 있어, 같은 높이에 두면 겹친다. 내리는 값은 `90px` = 레이어 위 패딩 18 + 1행 높이 60(필 38 + `mt-2` 8 + 서브 문구 14) + 간격 12이다.
- 세로에서도 같이 내리지 않는 이유는, 그 아래가 가운데 정렬된 52px 타이머 자리라 320px 기기에서 오른쪽 끝이 몇 px 겹치기 때문이다.
- 버튼의 색·반경·흐림은 컨트롤 바 버튼과 같은 값을 쓴다. 새 토큰을 만들지 않는다.
- 아이콘은 Figma 자산이 없으므로 이미 설치된 `lucide-react`의 음표 아이콘을 자리 표시로 둔다. 손으로 SVG를 그리지 않고, PR 본문의 "자산 필요"에 적는다.
- 시트는 공용 `ui/sheet.tsx`(shadcn, `@radix-ui/react-dialog` 기반)를 쓴다. 색은 `--session-dialog-*`를 읽어 항상 다크다.
- **포털은 반드시 세션 서브트리 안으로 보낸다.** shadcn 원본은 `document.body`로 포털하는데 `--session-*`는 `main`에만 주입돼 포털 밖에서 풀리지 않아 색이 통째로 빠진다. 같은 문제를 `ui/toast.tsx`가 폴백 값으로 우회하고 있다. 그래서 `SheetContent`에 `container` prop을 뒀고 `RoomPage`가 `main`의 ref를 넘긴다.
- **닫을 때 포커스를 돌려줄 자리를 직접 넘긴다.** Radix는 `Sheet.Trigger`를 쓸 때만 포커스를 되돌리는데, 진입 버튼이 세션 레이어 안에 따로 있어 Trigger로 감쌀 수 없다. 안 넘기면 포커스가 body로 빠져 키보드 사용자가 처음부터 탭을 돌아야 한다.
- **시트가 열려 있는 동안에는 `inert`를 걸지 않는다.** Radix가 포커스 트랩·바깥 차단·`aria-hidden`을 스스로 하고, 여기에 `inert`를 겹치면 닫힐 때 포커스를 돌려줄 버튼이 이미 `inert`라 복귀가 조용히 실패한다. 손으로 만든 종료 확인 다이얼로그에는 지금대로 `inert`를 건다.
- `SheetContent` 에 `aria-modal="true"` 를 직접 단다. Radix 가 만들어 주지 않는데 `nativeModalOverlay.ts` 의 네이티브 탭 바 차단이 이 속성의 존재 여부만 본다. 빠지면 시트 아래 탭 바가 계속 눌린다. 공용 `ui/dialog.tsx` 도 같은 이유로 달고 있다.
- **닫는 길은 셋이다.** 제목 줄의 X, 바깥 탭, Escape.
- **제목 옆 안내 툴팁은 여는 요청을 무시하고 닫는 요청만 받는다.** 시트가 열릴 때 Radix가 첫 포커스를 이 버튼에 주는데 툴팁은 포커스에도 열린다. 그대로 두면 시트를 열자마자 툴팁이 떠 있고, 그 상태의 Escape가 시트가 아니라 툴팁을 닫아 먹통처럼 보인다. 여는 것은 탭·클릭만 맡는다.
- **툴팁은 포털을 쓰지 않는다.** `ui/sheet.tsx`의 `container`와 같은 이유로 `document.body`로 나가면 세션 색이 풀린다. 툴팁은 작아 제자리에 그려도 잘리지 않는다.
- 목록의 오른쪽에 여백을 둔다. 없으면 스크롤바가 슬라이더 끝을 덮는다.
- 이름 줄과 슬라이더는 8px 겹쳐 한 덩어리로 읽히게 한다. 겹치는 부분은 슬라이더가 가져가므로 잘못 눌러도 음량이 조금 바뀔 뿐 소리가 꺼지지는 않는다. X 를 절대 배치하지 않고 제목 줄에 두는 이유는 시트 패딩이 안전 영역을 포함한 계산식이라, 절대 배치하면 노치가 있는 기기에서 자리가 어긋나기 때문이다.
- 딤은 `overlayClassName` 으로 `--session-dim` 을 넘긴다. shadcn 기본값인 전역 `--dim` 은 라이트 테마에서 40% 라 카메라 위에서 뒤가 비친다.
- 등장·퇴장 모션은 넣지 않는다. `tailwindcss-animate`가 없어 shadcn 원본의 `animate-in` 유틸이 동작하지 않고, Figma에도 모션 스펙이 없다.
- 터치 타겟은 44px 이상이다. 스위치의 트랙은 24px 라 보이지 않는 `after`로 위아래를 덧대 44px를 만든다. 부모 줄에 높이를 주는 것으로는 버튼 자신의 탭 영역이 넓어지지 않는다. 슬라이더는 `<input type="range">`에 `aria-label`을 붙인다. 모션은 `motion-reduce`에서 끈다.
- 진입 버튼은 소리를 토글하지 않고 시트을 열므로 `aria-haspopup="dialog"`와 `aria-expanded`를 쓴다. `aria-pressed`는 보조기기에 토글로 읽혀 실제 동작과 어긋난다. 재생 여부는 이름으로 전한다.
- 닫기는 공용 `ui/button.tsx`, 집중 연동은 `ui/switch.tsx`를 쓴다. 스위치는 shadcn 원본 그대로 `@radix-ui/react-switch` 위에 올리고 색만 서비스 토큰으로 바꿨다. 이 기능에서 새로 받은 의존성은 이것 하나다.
- 시트 패널은 세로 flex 라 기본 `flex-shrink` 가 살아 있다. 소리가 늘어 내용이 길어지면 제목·스위치·닫기 버튼이 함께 눌려 찌그러지므로, 줄어들 수 있는 것은 소리 목록 하나뿐으로 두고(`min-h-0` + `overflow-y-auto`) 나머지에 `shrink-0` 을 건다.

시안이 확정되면 두 컴포넌트의 클래스만 고친다. 로직은 움직이지 않는다.

## 6. 분석

이벤트 이름은 기존 관례대로 스네이크 케이스이고 속성은 원시값만 싣는다.

| 이벤트                       | 속성                                                                     | 시점                                            |
| ---------------------------- | ------------------------------------------------------------------------ | ----------------------------------------------- |
| `ambient_sound_changed`      | `sounds`(쉼표로 이은 id), `sound_count`, `source`(`dialog`·`auto_start`) | 켜고 끄는 변화마다. 레벨만 바뀌면 보내지 않는다 |
| `ambient_sound_duck_toggled` | `enabled`                                                                | 연동 토글                                       |
| `study_session_ended`        | `ambient_sound_used`, `ambient_sound_sec` 추가                           | 기존 이벤트 확장                                |

브리지의 `track-event`는 네이티브에서 웹으로 오는 방향이라 여기 쓰지 않는다. 웹은 `lib/amplitude.ts`에서 직접 보낸다.

개인정보처리방침은 고치지 않는다. 배경음 선택은 이미 고지된 "화면 이동 및 클릭 기록"의 범위 안이고, 새로 수집하는 항목도 새 수탁자도 없다.

| `ambientPlayer`      | 단위     | 가짜 컨텍스트로 명령 순서, 차이만 반영, 실패 소리 보고, dispose 정리, 소리를 몇 개 겹쳐도 전력 합이 1 이하, 리미터 설정값 고정, 멈춘 채 만들어진 컨텍스트, 느린 로딩 중 헤드룸 반영, 덕킹 램프가 헤드룸에 취소되지 않음, 보이스 시작·정지 알림 |

| `ui/switch`          | 컴포넌트 | 역할·상태, 탭·스페이스·엔터, 포커스, disabled, 탭 영역 덧댐                                                                                                                                                                                    |
| `AmbientSoundDialog` | 컴포넌트 | 조작 전 슬라이더가 전부 0, 아이콘과 이름이 나란히, 줄 토글, 상한 안내 없음, 저장 입력 없음, 연동 스위치, X·바깥 탭·Escape 로 닫힘, 큰 닫기 버튼은 없음                                                                                         |

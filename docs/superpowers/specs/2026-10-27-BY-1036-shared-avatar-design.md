# BY-1036 공용 아바타 설계

상위 BY-1031(프로필 사진)의 하위 작업이다. 프로필 사진을 소셜룸과 랭킹에 보여 주기 전에, 화면마다 따로 있는 이니셜 아바타 세 개가 사진을 받을 수 있는 공용 컴포넌트를 쓰게 바꾼다. 사진 데이터는 BY-1035·BY-1037에서 들어오므로 이번 작업에서는 화면이 바뀌지 않는다.

## 현재 상태

- `ProfileAvatar`는 프로필 화면에서 72px `bg-primary` 원에 입력 중인 닉네임의 첫 글자를 보여 준다.
- `RoomAvatarFallback`은 소셜룸 타일에서 카메라가 꺼졌을 때 56px 흰색 10% 원을 그리고, 넓은 창에서는 원과 글자를 타일 폭(`cqi`)에 비례시킨다.
- `RankAvatar`는 랭킹 시상대와 주변 목록에서 32·46·56px 원을 그리고, 나와 남을 바탕색으로 구분하며 파란 줄 위에서는 색을 뒤집는다.
- 세 곳 모두 옆에 닉네임이 함께 보인다. 프로필과 랭킹은 아바타를 `aria-hidden`으로 숨기지만, 소셜룸 타일은 숨기지 않아 스크린리더가 첫 글자와 닉네임을 차례로 읽는다.
- 랭킹은 탭 웹뷰가 새 문서로 여는 화면이라 정적 import로 첫 번들에 들어간다.

## 결정

- 공용 컴포넌트는 shadcn Base UI 레지스트리의 Avatar(`@base-ui/react/avatar`)를 `components/ui/avatar.tsx`로 받아 쓴다. `Avatar`·`AvatarImage`·`AvatarFallback` 세 부품을 둔다.
- 랭킹이 첫 번들이라 Base UI Avatar 코드가 모든 탭의 첫 로딩에 실린다.
  > 사용자가 이 대가를 알고 shadcn을 택했고, 엔트리 청크 gzip 크기 변화를 측정해 PR에 남긴다.
- 공용 컴포넌트에는 둥근 모양과 `overflow-hidden`만 두고 크기·색·글자 크기는 쓰는 쪽이 `className`으로 정한다. 세 화면의 모양 규칙이 서로 달라 variant로 모으지 않는다.
- `ProfileAvatar`·`RoomAvatarFallback`·`RankAvatar`는 래퍼로 남기고 안쪽만 공용 `Avatar`로 바꾼다. 크기 맵, 나 강조, 타일 비례 같은 고유 규칙은 각 래퍼에 그대로 둔다.
- 래퍼에 `src` prop은 이번에 넣지 않는다. 사진 필드가 타입에 생기는 BY-1037에서 함께 넣는다.
- 아바타는 `aria-hidden`이고 사진은 `alt=""`다. 옆 닉네임과 같은 이름을 스크린리더가 두 번 읽지 않게 한다. 소셜룸 타일 아바타도 이번에 숨긴다.
- 이니셜만 보이는 지금 화면이 그대로여야 하므로 Figma 시안은 고치지 않는다.
- `focusmakers-design/references/shadcn-map.md`의 Avatar 행을 "있음, BY-1036"과 Base UI 기반으로 고친다.

## 테스트

- 공용 `Avatar`는 사진 주소가 없으면 이니셜을 보여 준다.
- 사진이 로드되면 사진을 보여 준다.
- 사진 로드가 실패하면 이니셜을 보여 준다.
- 기존 `RankAvatar`·`RoomAvatarFallback` 테스트는 바뀐 내부 구조로 그대로 통과한다.
- 프로필, 소셜룸, 랭킹 화면을 dev와 라이트·다크로 비교해 모습이 같은지 확인한다.

## 범위 밖

- 사진 업로드와 각 화면에 사진 주소를 넘기는 일은 BY-1037에서 한다.
- `colorIndex`별 팔레트는 디자인이 정해지지 않아 `ProfileAvatar`의 한 가지 색을 유지한다.

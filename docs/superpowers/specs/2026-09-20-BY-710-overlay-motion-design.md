# BY-710 세션 오버레이 등·퇴장 모션

## 배경

세션 화면 위에 뜨는 오버레이가 모션 없이 즉시 나타났다 사라진다. 배경음 시트를 열면 오른쪽 패널이 툭 튀어나오고, 닫으면 그 자리에서 사라진다. 공용 다이얼로그도 마찬가지다.

이 저장소에는 `index.css`에 `@keyframes`를 쓰고 `animate-[이름_200ms_ease-out]`으로 붙이는 패턴이 이미 일곱 군데 돌고 있다. 토스트, 월 달력, 컨트롤 바 아이콘이 그렇게 움직인다. 오버레이에도 같은 방식을 쓸 수 있었지만, Radix 기반 컴포넌트의 열림·닫힘 상태와 짝지으려면 손으로 쓸 코드가 상당히 늘어난다. 그래서 `tw-animate-css`를 받기로 했다.

## 착수 전 확인한 사실

### `tailwindcss-animate`가 아니라 `tw-animate-css`다

티켓 제목은 `tailwindcss-animate` 적용이었다. 그 패키지는 Tailwind v3용 JS 플러그인이고 2023년 이후 릴리스가 없다. shadcn/ui는 2025년 3월에 이 패키지를 버리고 v4 대응물인 `tw-animate-css`로 바꿨다. 이 저장소는 Tailwind v4.1.16에 `tailwind.config` 없이 `index.css`의 `@theme inline`만 쓰는 CSS-first 설정이라 정확히 그 상황에 해당한다.

쓰는 유틸리티 이름은 `animate-in`, `fade-in`, `slide-in-from-right`처럼 그대로여서 티켓이 의도한 결과는 달라지지 않는다.

저장소 스킬 `tailwind-v4-shadcn`은 `tw-animate-css`를 두고 "존재하지 않는다"고 적어 뒀는데 사실과 다르다. npm에 `1.4.0`이 올라와 있다. 이 스킬 문서는 별도로 고쳐야 한다.

### 패키지에 모션 축소 처리가 없다

`tw-animate-css` 안에는 `prefers-reduced-motion` 관련 규칙이 하나도 없다. 직접 써 넣어야 한다.

### 인자 없는 `zoom-in`은 배율 0이다

`zoom-in` 유틸은 `--tw-enter-scale`을 `0`으로 놓는다. 저장소 스킬 `animate`가 "무에서 나타나는 것은 금지"로 못박은 그 경우다. 반드시 `zoom-in-95`처럼 값을 붙여 쓴다.

### 기본값이 약하다

기본 지속시간은 `0.15s`, 기본 이징은 브라우저 `ease`다. 둘 다 `animate` 스킬 기준에 못 미친다. 다행히 `--tw-duration`과 `--tw-ease`를 읽도록 만들어져 있어 Tailwind의 `duration-*`, `ease-*` 유틸로 덮을 수 있다.

## 범위

### 이번에 다루는 것

- 공용 `sheet.tsx`의 패널과 딤에 등·퇴장 모션을 넣는다.
- 공용 `dialog.tsx`의 본체와 딤에 등·퇴장 모션을 넣는다.
- 모션 축소 환경에서 움직임만 빼고 페이드는 남기는 규칙을 `index.css`에 한 번 적는다.

배경음 시트는 공용 `sheet.tsx`를 그대로 쓰므로 따로 손대지 않아도 같이 움직인다.

### 이번에 다루지 않는 것

세션 종료 확인 다이얼로그와 카메라 켜기 확인 다이얼로그는 제외했다. 둘 다 Radix가 아니라 손으로 만든 오버레이이고, 호출부가 `{열림 && <다이얼로그 />}` 꼴이라 닫히는 순간 React가 DOM에서 바로 걷어낸다. 퇴장 모션을 보여주려면 애니메이션이 끝날 때까지 언마운트를 미루는 장치를 직접 만들어야 하는데, 이 두 컴포넌트를 shadcn 기반으로 바꾸는 별도 티켓이 잡혀 있다. 그 작업을 하면 Radix가 기다림을 대신해 주므로, 지금 만든 장치는 그때 버려진다. 교체 티켓에서 모션까지 한 번에 붙인다.

## 설계

### 이징 토큰

저장소에 이징 토큰이 하나도 없다. `index.css`의 `@theme`에 하나 추가한다.

```css
--ease-overlay: cubic-bezier(0.23, 1, 0.32, 1);
```

`animate` 스킬이 지정한 강한 ease-out 값이다. 브라우저 기본 `ease-out`은 너무 약해서 쓰지 말라고 같은 스킬이 못박고 있다.

토큰은 하나만 만든다. 시트용과 다이얼로그용을 따로 두면 한쪽은 쓰이지 않는다.

### 시트

`sheetVariants`의 side별 variant에 들어오는 방향과 나가는 방향을 짝지어 넣는다. 오른쪽에서 들어온 패널은 오른쪽으로 나간다. 지속시간은 300밀리초다.

딤은 페이드만 한다. 패널과 같은 시간으로 맞춰 함께 걷힌다.

### 다이얼로그

`zoom-in-95`와 `zoom-out-95`에 페이드를 겹친다. 지속시간은 200밀리초다.

모달은 트리거에 매달린 팝오버가 아니므로 `transform-origin`을 중앙 그대로 둔다. `animate` 스킬이 명시한 예외다.

### 모션 축소

`tw-animate-css`의 enter·exit keyframes는 이동량과 배율을 CSS 변수에서 읽는다. 그 변수만 중립값으로 덮으면 애니메이션 자체는 계속 돌면서 움직임만 사라지고 페이드는 남는다.

```css
@media (prefers-reduced-motion: reduce) {
  *,
  ::before,
  ::after {
    --tw-enter-translate-x: 0;
    --tw-enter-translate-y: 0;
    --tw-exit-translate-x: 0;
    --tw-exit-translate-y: 0;
    --tw-enter-scale: 1;
    --tw-exit-scale: 1;
  }
}
```

기존 저장소가 쓰던 `motion-reduce:animate-none` 방식을 여기서는 쓰지 않는다. 이유가 둘이다.

첫째, 애니메이션을 통째로 없애면 Radix가 기다리는 `animationend`가 오지 않는다. Radix는 그 경우를 스스로 처리하지만, 같은 방식을 손으로 만든 컴포넌트에 옮겨 쓰면 닫힘이 깨진다.

둘째, 모션을 끈 사람에게도 오버레이가 떴는지 걷혔는지는 알려 줘야 한다. 움직임만 빼고 페이드는 남기는 것이 `animate` 스킬의 기준이기도 하다.

전역으로 한 번 적어 두면 앞으로 `animate-in` 계열을 쓰는 모든 곳에 자동으로 적용된다.

## 테스트

이 작업은 대부분 클래스 문자열을 붙이는 일이라 단위 테스트로 잡히는 부분이 좁다. 애니메이션이 실제로 어떻게 보이는지는 jsdom에서 확인할 수 없다.

착수 당시에는 `sheetVariants`의 방향 짝만 검증할 계획이었다. 외부 채점에서 핵심 계약이 빠졌다는 지적을 받아 세 파일 열세 건으로 넓혔다.

- `sheet.test.tsx`는 네 방향의 들어오는 방향과 나가는 방향이 같은지, 열린 상태로 그린 패널과 딤이 같은 지속시간을 갖고 양쪽 모두 나가는 애니메이션을 지니는지, 딤은 페이드만 하고 미끄러지지 않는지 본다.
- `dialog.test.tsx`는 같은 항목에 더해 배율이 0이 아닌 값에서 시작해 같은 값으로 돌아가는지 본다.
- `reducedMotion.test.ts`는 `index.css`를 읽어 모션 축소 블록이 이동량과 배율만 중립화하고 애니메이션을 끄지 않으며 불투명도 변수를 건드리지 않는지 고정한다.

닫는 모션이 끝난 뒤에 요소가 걷히는지는 테스트로 잡지 않았다. Radix는 `getComputedStyle(node).animationName`을 보는데 jsdom은 CSS를 계산하지 않아 늘 빈 값을 돌려주고, 그래서 애니메이션 유무와 무관하게 즉시 언마운트된다. `getComputedStyle`을 mock해 가짜 이벤트를 쏘면 통과는 시킬 수 있지만 실제 CSS가 적용됐다는 사실은 증명하지 못한다. 이 계약은 브라우저에서 확인했다.

나머지는 화면 검증으로 확인한다.

## 완료 조건

- 시트가 옆에서 들어오고 닫을 때 같은 방향으로 나간다.
- 다이얼로그가 살짝 커지며 나타나고 닫을 때 반대로 사라진다.
- 딤이 페이드로 따라붙는다.
- 닫는 모션이 끝난 뒤에 요소가 걷힌다.
- 모션 축소 환경에서 움직임과 크기 변화가 사라지고 페이드만 남는다.
- 라이트와 다크 스크린샷, 모션 축소 확인이 첨부된다.

# BY-936 세션·소셜룸 태블릿 배치 설계

상위 티켓 BY-641(태블릿 반응형)의 세 번째 하위 작업이다. BY-934에서 정한 기준(`sm` 600 · `md` 840 · `lg` 1200 · `xl` 1600, `landscape-compact`)을 써서 공부하는 동안 오래 보는 두 화면에 태블릿 배치를 넣는다.

## 배경

- BY-934 이후 태블릿 가로·세로는 폰 세로 배치를 넓게 늘려 받는다.
- 솔로 세션은 타이머 52px, 버튼 54px라 거치해 두고 멀리서 보기에 작고, 과목 시트가 화면 전폭(1180px)으로 열린다.
- 소셜룸은 폰 기준 정사각 타일이라 태블릿 가로 3~4명에서 타일이 590px로 커져 스크롤이 생기고, 2명은 303px 두 장이 가운데에 쌓여 좌우가 빈다.

## 소셜룸 열 수 계산

입력은 인원 수 `n`(2~6), 격자에 쓸 수 있는 폭 `w`와 높이 `h`, 타일 간격 `gap`이다. `cols`를 1부터 `n`까지 돌며 `rows = ceil(n / cols)`, `size = min((w - gap*(cols-1)) / cols, (h - gap*(rows-1)) / rows)`를 구하고 `size`가 가장 큰 `cols`를 고른다. 같으면 열이 적은 쪽을 고른다.

iPad 기준 결과(여백 위·좌우 16px, 아래 바 자리 112px, 간격 8px):

| 인원 | 가로 1180×820 | 세로 820×1180 |
| ---- | ------------- | ------------- |
| 2    | 2×1, 570px    | 1×2, 522px    |
| 3    | 3×1, 377px    | 2×2, 390px    |
| 4    | 2×2, 342px    | 2×2, 390px    |
| 5~6  | 3×2, 342px    | 2×3, 345px    |

간격은 폰의 4px 대신 8px을 쓴다. 타일이 커져 4px로는 타일끼리 붙어 보였다. `RoomGrid.tsx`의 `TILE_GAP_PX`와 타일 묶음의 `sm:not-landscape-compact:gap-2`가 같은 값이어야 한다. 폰 세로·가로 거치의 간격은 그대로 4px이다.

큰 태블릿은 아래 바 자리가 136px이다(아래 "큰 태블릿 단계"):

| 인원 | 가로 1376×1032 | 세로 1032×1376 |
| ---- | -------------- | -------------- |
| 2    | 2×1, 668px     | 1×2, 608px     |
| 3    | 3×1, 442px     | 2×2, 496px     |
| 4    | 2×2, 436px     | 2×2, 496px     |
| 5~6  | 3×2, 436px     | 2×3, 402px     |

## 큰 태블릿 단계

13인치 iPad(1032×1376, 1376×1032)에서 태블릿 크기도 작게 보인다는 사용자 피드백으로 한 단계를 더 둔다.

조건은 새 variant `short-side-lg`로, 폭과 높이가 모두 1000(62.5rem) 이상일 때다. 11인치(820×1180)와 mini는 짧은 변이 1000보다 작아 걸리지 않고, 폰과 폰 가로 거치도 그대로다. 폭만 보면 노트북 창도 걸려 높이까지 본다. 이 조건은 태블릿 조건에 덧씌우는 방식이라 태블릿 클래스 뒤에 `short-side-lg:` 클래스를 더한다.

| 항목                  | 태블릿     | 큰 태블릿  |
| --------------------- | ---------- | ---------- |
| 순공 타이머           | 96px       | 120px      |
| 총 시간               | 22px       | 28px       |
| 컨트롤 바·옆 버튼     | 64px       | 80px       |
| 상태 필 글자          | 16px       | 20px       |
| 과목 시트 최대 폭     | 480px      | 560px      |
| 소셜룸 바 버튼        | 64px       | 80px       |
| 시간 배지·이름·목표   | 16·17·14px | 20·21·17px |
| 소셜룸 격자 아래 여백 | 112px      | 136px      |

값은 태블릿의 약 1.25배이고 바 패딩·간격·아이콘·필 높이도 같은 비율로 키운다. 소셜룸 바가 110px로 커져 격자 아래 여백을 바 높이와 아래 띄움(17px)보다 크게 136px로 늘린다. 격자 크기는 `RoomGrid.tsx`가 실제 안쪽 여백을 읽어 계산하므로 여백 상수를 따로 두지 않는다. 시트를 열 때 타이머가 올라가는 거리는 타이머의 실제 높이를 받으므로 그대로 동작한다. 1376×1032에서 시트 윗변이 279px, 올라온 타이머 아랫변이 271px이다.

두 조건이 같은 속성을 다툴 때는 `short-side-lg` 규칙이 빌드 CSS에서 태블릿 규칙보다 뒤에 나와 이긴다. 선택자 특정성이 같아 순서로 정해진다.

## 건드리는 곳

- `routes/RoomPage.tsx`: 옆 버튼 위치, 타이머 슬롯
- `features/study-session/components/SessionTimer.tsx`: 글자 크기
- `SessionControlBar`·`AmbientSoundButton`·`SessionSideActions`: 64px
- `SubjectSheet.tsx`: 시트 최대 폭과 손잡이 자리
- `features/live-room/roomGrid.ts`(열 수 함수), `components/RoomGrid.tsx`(크기식·재마운트 경계), `RoomControlBar.tsx`, `RoomTile.tsx`(배지·글자)
- `useTileFlipAnimation.ts`의 재측정 경계

## 테스트

- 열 수 함수 단위 테스트: 인원 1~6 × 가로·세로·좁은 창.
- 클래스 문자열을 단언하는 기존 테스트(`sessionLandscape`, `LiveRoomPage`, `RoomPage`)는 값만 맞춘다.
- 실제 배치는 Playwright로 402×874, 874×402, 820×1180, 1180×820, 1366×1024를 `dev`와 비교한다. 큰 태블릿 단계는 1032×1376, 1376×1032를 더 본다.

## 범위 밖

- 과목 UI를 버튼 + 옆 시트로 바꾸는 작업(별도 티켓).
- 앱 셸 회전·iPad 상단 탭 바(BY-935), 나머지 화면 최대 폭(BY-937).

# BY-582 딥링크 진입을 탭 셸로 합류시키기

2026-09-02 승인. 초대 링크 딥링크 진입 시 하단 탭 바가 영영 나타나지 않는 문제의 설계다.

## 문제

- 딥링크 라우트 `apps/mobile/app/social/join.tsx`가 `(tabs)` 밖의 스택 화면이라 탭 바가 없는 구조다.
- 참여 이후 모든 이동이 그 웹뷰 안 웹 라우팅으로만 일어나서, 소셜 홈에 돌아와도 탭 바가 없고 홈·기록·설정으로 갈 수 없다.
- 원칙 위반: 딥링크 화면은 사용자가 손으로 이동한 것과 같은 내비게이션 트리 위에 있어야 한다(백스택 합성). 셸 밖 복제 화면은 고아 상태를 만든다.

## 해법

딥링크 라우트를 목적지가 아니라 리다이렉터로 바꾼다. 모든 진입 경로(유니버설 링크, App Links, Install Referrer, 향후 커스텀 스킴)가 같은 라우트를 타므로 한 곳만 고치면 된다.

### 변경 1: `app/social/join.tsx`

- 웹뷰 호스팅을 제거하고 `code` 파라미터를 실어 `/(tabs)/social`로 `<Redirect>`한다.
- `Redirect`는 현재 항목을 대체하므로 뒤로가기에 고아 화면이 남지 않는다.

### 변경 2: `app/(tabs)/social.tsx`

- `useLocalSearchParams`로 `code`를 읽는다.
- `code`가 있으면 `path="/social/join"`에 `extraQuery={{ code }}`로 코드 프리필을 유지한다.
- `code`가 없으면 기존대로 `path="/social"`을 로드한다.
- `key`를 `code ?? "home"`으로 두어 파라미터 변화 시 웹뷰를 재마운트한다 (`RemoteScreen`이 `extraQuery`를 마운트 시점에 고정하기 때문).
- 이후 흐름은 전부 웹 라우팅이고, 탭 바는 웹의 기존 `set-tab-bar` 규칙(`nativeTabBar.ts`)이 제어한다. 소셜 홈 도달 시 탭 바가 자동 복귀한다.

### 변경 3: `app.json` 스킴 배열

- `"scheme": "focuson"`을 `["focusmakers", "focuson"]`으로 확장한다.
- `focusmakers`가 대표 스킴이고 `focuson`은 구빌드 호환용이다. BY-583 선행 준비를 이 티켓의 새 빌드에 함께 실어 배포 횟수를 줄인다.

## 확정한 결정

- 탭 사용 중 새 딥링크가 오면 웹뷰를 재마운트해 새 join을 로드한다. 보던 화면은 버린다(링크를 눌렀다는 것은 그 방에 가겠다는 의도다).
- 합류 후 라우트에 남는 `code` 파라미터는 정리하지 않는다. 재마운트는 key 변화 때만 일어나 실사용 영향이 없고, `setParams` 정리는 즉시 재마운트를 유발해 join 화면을 파괴한다. 상태 복원 엣지는 수용한다.

## 테스트

- 유닛: `(tabs)/social`이 `code` 유무에 따라 올바른 `path`와 `extraQuery`로 `RemoteScreen`을 렌더한다.
- 유닛: `social/join` 라우트가 `code`를 실어 소셜 탭으로 리다이렉트한다.
- 실기기: 딥링크 진입 후 join 프리필, 입장, 종료, 소셜 홈에서 탭 바 복귀를 확인한다.

## 범위 밖

- 인앱 브라우저 스킴 핸드오프는 BY-583이다.
- 카톡 3중 전송·지연은 BY-584다.
- 재입장 시 이전 코드 잔존(웹 측)은 BY-581이다.

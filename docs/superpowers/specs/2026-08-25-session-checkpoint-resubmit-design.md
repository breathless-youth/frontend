# 세션 측정 데이터 로컬 저장과 비정상 종료 후 재제출 (BY-433)

- 날짜: 2026-08-25
- 티켓: BY-433 — [FE] 세션 측정 데이터 로컬 저장과 비정상 종료 후 재제출
- 연관: BY-431(유예 재입장 공부시간 표시), 팀원 분석 문서(2026-08-24),
  구 설계 2026-07-27 vision 파이프라인 §7(번들 웹뷰 전제라 사장된 체크포인트 설계의 현재
  아키텍처 재해석)

## 문제

세션 측정 데이터(시작 시각, 타임라인, 이벤트)가 전부 메모리에만 있어, 강제종료·크래시·OOM·
유예 만료 등 비정상 종료 시 그때까지 측정한 기록이 통째로 사라진다. 서버는 세션을 실시간
추적하지 않으므로(마지막 순공시간 숫자 하나만 앎) 서버가 대신 저장할 수 없다. 세션 제출 API
`POST /api/study-sessions`는 `(userId, startedAt)` 멱등 재제출을 이미 지원한다.

## 접근 비교

| 접근                         | 내용                                                               | 판단                                                                   |
| ---------------------------- | ------------------------------------------------------------------ | ---------------------------------------------------------------------- |
| A. 공유 훅에 체크포인트 연결 | 순수 저장 모듈 + `useStudyRoomSession` 주기 저장 + App 부팅 재제출 | **채택** — 솔로룸·라이브룸이 훅을 공유해 한 곳 수정으로 양쪽 커버      |
| B. 화면별 저장               | RoomPage·LiveRoomSession 각각                                      | 탈락 — 같은 로직 중복                                                  |
| C. 네이티브 브리지 파일 저장 | iOS 웹 데이터 정리에도 생존                                        | 탈락 — 브리지 확장·네이티브 작업 필요, 범위 초과. 필요해지면 후속 검토 |

## 설계 (접근 A)

### 1. 저장 모듈 — `apps/web/src/features/study-session/sessionCheckpoint.ts` (신규)

- localStorage 키 `focusmakers.pendingSession.v1.<startedAtMs>`.
- 값 `PendingSessionRecord`: `{ userId, startedAtMs, lastSeenMs, studySec, focusSec, events }`.
  `events`는 서버 전송 형식(`StatusEventPayload[]`, `toStatusEvents` 결과) 그대로 저장한다 —
  재제출 때 변환이 필요 없다.
- API: `saveCheckpoint(record)` / `listCheckpoints(): PendingSessionRecord[]` /
  `deleteCheckpoint(startedAtMs)`.
- 모든 storage 접근은 try/catch로 감싸 예외 시 조용히 무시한다. 시크릿 모드 등에서 저장
  기능만 꺼지고 세션 측정은 정상 동작한다. 손상된 JSON·형식이 안 맞는 레코드는 목록에서
  걸러낸다.

### 2. 훅 연결 — `useStudyRoomSession.ts`

- `studying` 중 기존 200ms tick 안에서 **10초마다** 저장하고, 상태 전이(`applyState`)
  시에도 저장한다.
- `userId`가 `null`이면 저장하지 않는다 — 어차피 제출할 수 없는 세션이다.
- 제출 성공(`done`) 시 자기 체크포인트를 삭제한다. `unsaved`(userId 없음)는 애초에 저장된
  것이 없다.
- 제출 실패(`error`) 상태에서는 유지한다 — "다시 제출"을 누르지 않고 떠나도 다음 실행 때
  재제출된다.

### 3. 재제출 러너 — `resubmitPendingSessions.ts` (신규) + `App.tsx` 부팅 1회 effect

- 부팅 때 보관분 목록을 읽어 각각 `submitStudySession({ userId, startedAtMs,
endedAtMs: lastSeenMs, studySec, focusSec, events })`로 제출하고, **제출에 성공한 건수를
  반환**한다.
- `App`은 성공 건수가 1 이상이면 기존 `Toast` 컴포넌트로
  `"저장하지 못했던 공부 기록을 저장했어요"`를 1회(3초) 띄운다(SocialHomePage의 고정 래퍼
  패턴). 실패는 알리지 않는다 — 다음 실행에서 조용히 재시도한다.
- 성공 → 삭제. `400` → 삭제하고 로그만 남긴다. 그 외 실패(네트워크 등) → 유지, 다음 실행에서
  재시도한다.
- 부팅 시점에는 진행 중인 세션이 없어 현재 세션과 충돌하지 않는다. 이후 시작되는 세션은
  `startedAtMs`가 달라 러너 대상이 아니다.
- 서버 검증(`focusSec ≤ studySec ≤ 세션길이 − PAUSE 합`)은 자동 충족된다 — 저장값이
  `lastSeenMs` 시점의 측정값이라 기존 `buildSessionRequest` 클램프와 모순이 없다.

### 확정한 결정

| #   | 결정                         | 내용                                                                                                                                            |
| --- | ---------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | 저장 주기                    | 10초 + 상태 전이 시. 최대 손실 약 10초 (구 설계 §7 값 유지)                                                                                     |
| 2   | 비정상 종료 세션의 종료 시각 | 마지막 체크포인트 시각 `lastSeenMs`                                                                                                             |
| 3   | 재제출 실패 처리             | `400`은 삭제하고 로그만, 그 외 실패는 보관 유지 후 다음 실행 재시도                                                                             |
| 4   | 사용자 노출                  | 재제출 성공 시 토스트 `"저장하지 못했던 공부 기록을 저장했어요"` 1회. 실패는 알리지 않음 (당초 "조용히 저장"에서 2026-08-25 티켓 개정으로 변경) |

### 한계 (수용)

- iOS가 저장 공간 부족 시 웹사이트 데이터를 정리하면 보관분이 유실된다. 발생 빈도가 낮아
  수용한다. 막으려면 네이티브 저장소(브리지 경유)가 필요하며 별도 건이다.
- localStorage 쓰기가 디스크에 커밋되기 전(수 초 이내) 프로세스가 죽으면 마지막 1회 저장이
  유실될 수 있다. 손실은 저장 주기 1~2회분으로 한정된다.
- 브라우저가 storage 접근을 막는 환경에서는 저장·재제출이 조용히 꺼진다(세션 측정은 정상).

## 테스트 계획

1. `sessionCheckpoint` 단위 — 저장·목록·삭제 라운드트립, 손상 JSON 무시, storage 예외 시 무해.
2. `useStudyRoomSession` — 10초 경과 시 저장, 상태 전이 시 저장, 제출 성공 시 삭제,
   `userId` 없으면 저장 안 함, 제출 실패 시 유지.
3. `resubmitPendingSessions` — 성공 시 제출+삭제, `400` 삭제, 네트워크 실패 유지, 여러 건
   순차 처리.
4. App 부팅 — 마운트 1회에 러너가 호출되고, 성공 건수가 1 이상이면 토스트 문구가 보이며
   0이면 보이지 않는다.

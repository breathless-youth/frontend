# BY-1150 로그아웃과 탈퇴 설계

- 티켓: BY-1150 (로그인은 BY-1147, 그룹 탭 게이트는 BY-1149)
- 근거: 위키 `product/specs/BY-383-소셜로그인-인증인가.md`(POST /api/auth/logout, DELETE /api/users/me, 로그인 상태 복구 플로우), `product/voice-tone.md`, 백엔드 `AuthController.logout`·`UserController.deleteAccount`·`DeleteAccountRequest`
- 작성: 2026-11-06
- 2026-11-07 사용자 후속 결정: 설정에서 로그인·로그아웃·계정 삭제를 마쳐도 설정에 남고, 하단 성공 토스트를 표시한다.

## 왜

로그인이 생기면서 앱 안에서 로그아웃과 계정 삭제를 할 수 있어야 했다. 계정 삭제는 Apple 5.1.1(v)와 Google Play 정책상 심사 필수 요건이다. 두 요청 모두 토큰을 다루므로 토큰의 유일한 소유자인 앱 셸이 처리하고, 웹은 설정 화면과 확인 창만 맡았다.

## 흐름

1. 설정 맨 아래 `계정` 섹션의 `로그아웃` 또는 `계정 삭제`를 누르면 확인 창이 떴다. 로그아웃은 기록이 계정에 남는다고, 삭제는 모든 기록이 바로 지워지고 되돌릴 수 없다고 알렸다. 삭제 확인 버튼은 위험 색으로 칠했다.
2. 확인하면 웹이 브리지 `logout` 또는 `delete-account`를 로그인 공급자와 함께 보냈다. 진행 중에는 확인과 취소를 막고, 같은 순간의 두 번째 누름은 ref로 막았다.
3. 로그아웃은 셸이 이 기기의 refresh로 `POST /api/auth/logout`(API-Version 1)을 보내고, 응답과 상관없이 저장된 토큰을 지운 뒤 `POST /api/users`로 새 비회원이 됐다. 소셜 계정으로 바뀐 기기 UUID는 연결이 풀려 있어 새 비회원이 생겼다.
4. 삭제는 셸이 `DELETE /api/users/me`(API-Version 1)를 보냈다. 애플 계정이면 먼저 애플 로그인 창을 다시 띄워 받은 `authorizationCode`를 `appleClient: "IOS"`와 함께 본문에 실었고, 다른 공급자는 본문이 없었다. 계약대로 204만 지운 것으로 보고, 그때만 로그아웃처럼 토큰을 지우고 새 비회원이 됐다.
5. 셸은 새 비회원 토큰의 `auth-token`을 먼저 보내고 `logout-result` 또는 `delete-account-result`로 답했다. 그다음 분석 sink를 모두 떼고 `logout_completed` 또는 `account_deleted`를 남긴 뒤, 모든 탭 웹뷰를 다시 띄우고 설정 탭에 남는다.

## 범위 밖

Android의 애플 계정 탈퇴(`appleClient: "ANDROID"`), 비회원의 모든 데이터 삭제, PC 웹 로그아웃, Play 계정 삭제 안내 URL, 개인정보처리방침 수정은 이번에 하지 않았다. Android 셸에는 애플 로그인이 없어 애플 계정으로 로그인한 Android 기기가 생기지 않는다. 그래도 애플 공급자로 탈퇴 요청이 오면 셸은 서버에 보내지 않고 `UNKNOWN` 실패로 답했다.

## 확인하지 못한 것

실기기의 애플 다시 로그인 창, 다시 띄운 문서가 셸이 남긴 완료 이벤트를 실제로 Amplitude에 보내는지, 다시 띄운 뒤 화면 전환 모습은 단위 테스트로만 확인했다.

# BY-846 wasm·모델 사전 압축 업로드 설계

## 목표

- 스테이징 CloudFront가 압축 없이 보내는 MediaPipe wasm과 Vision 모델을 brotli로 보내게 한다.
- 운영 컷오버(BY-798) 전에 Vercel과 같거나 더 작은 전송량을 맞춘다.

## 현재 상태 (2026-10-02 측정)

CloudFront 자동 압축은 1,000~10,000,000바이트이면서 정해진 MIME 유형인 파일만 대상으로 한다. wasm은 10MB를 넘고, 모델의 `application/octet-stream`은 대상 유형이 아니라서 둘 다 압축 없이 나간다. MediaPipe 로더 `.js`(320KB)는 이미 CloudFront가 brotli로 보낸다.

| 파일                               | 원본   | gzip -9 | brotli 11 | 운영 Vercel |
| ---------------------------------- | ------ | ------- | --------- | ----------- |
| `vision_wasm_internal.wasm`        | 11.5MB | 3.4MB   | 2.4MB     | 3.2MB       |
| `vision_wasm_nosimd_internal.wasm` | 10.8MB | 3.3MB   | 2.3MB     | 3.1MB       |
| int8 모델                          | 4.6MB  | 3.4MB   | 3.2MB     | 3.4MB       |
| 얼굴 모델                          | 3.8MB  | 3.3MB   | 3.1MB     | 3.3MB       |
| fp32 모델                          | 13.8MB | 12.5MB  | 12.3MB    | 12.6MB      |

## 확정한 결정

| 항목             | 결정                                                                                                                                                                                                                                                                                                |
| ---------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 압축 형식        | brotli 최고 단계(11)로 미리 압축해 같은 경로에 올린다. 앱 웹뷰(iOS WKWebView, Android Chromium)와 최신 브라우저는 HTTPS에서 모두 brotli를 푼다. gzip은 wasm이 1MB 더 크고, 원본·br·gzip을 함께 올려 CloudFront Function으로 고르는 방식은 우리 사용자에게 얻는 것 없이 함수·캐시 키·테스트만 늘린다 |
| 대상             | `dist`의 `mediapipe/` 아래 `.wasm`과 `.map`을 뺀 `models/*`. 업로드 단계가 br로 올리는 범위와 정확히 같게 둔다. 범위를 넘게 고르면 압축만 되고 어느 업로드에도 실리지 않는다. 로더 `.js`는 CloudFront가 이미 압축하고, mp3는 이미 압축된 형식이라 뺀다                                              |
| 압축 도구        | `apps/web/scripts/precompressAssets.js`. Node 내장 `zlib`이라 새 의존성이 없다. 같은 이름으로 덮어쓴다(`dist`는 업로드에만 쓴다)                                                                                                                                                                    |
| 업로드           | 빌드 다음에 압축 단계를 둔다. 압축한 파일만 `--content-encoding br`로 따로 올리고, 나머지 업로드 순서(해시 자산 → 나머지 → `index.html`)는 그대로 둔다                                                                                                                                              |
| 이미 캐시된 기기 | 경로가 같아도 풀어낸 내용이 같아서 문제없다. 엣지 캐시는 배포 끝의 `/*` 무효화가 비운다                                                                                                                                                                                                             |
| 다음 배포        | `aws s3 sync`는 크기와 함께 수정 시각도 비교하므로, 새로 빌드한 파일은 배포마다 다시 올라간다. brotli 결과는 입력이 같으면 같은 바이트라 내용은 바뀌지 않고, 늘어나는 것은 업로드 시간 몇 초다                                                                                                      |
| Vercel           | 운영 Vercel 빌드는 이 단계를 거치지 않아 영향이 없다                                                                                                                                                                                                                                                |
| 검증             | `verifyDeploy.js`의 wasm·모델 확인에 `content-encoding: br`을 추가한다. 운영이 Vercel인 동안 운영 주소로 돌리면 이 항목이 실패하고, BY-798 컷오버 뒤에는 통과한다                                                                                                                                   |

## 대가

- brotli를 못 푸는 요청(옵션 없는 `curl` 같은 도구)도 압축된 바이트를 받는다. 우리 사용자 경로(앱 웹뷰, 브라우저)에는 해당하지 않는다.

## 측정

| 구분          | 방법                                                                                                                                                                                                                   |
| ------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 전송량        | `curl -H 'accept-encoding: br, gzip'`로 파일별 받은 바이트. 지금 스테이징, 운영 Vercel, 배포 뒤 스테이징                                                                                                               |
| A23 진입 시간 | 같은 날 같은 와이파이. 기존 측정 도구 방식(CDP, 캐시 비우고 첫 진입)으로 스테이징 `/room/1`을 열어 Resource Timing에서 wasm·모델의 받은 크기와 다운로드 완료 시각을 각 5회. AS-IS는 배포 전, TO-BE는 머지 뒤 배포 다음 |
| 감지 시작     | 머지 뒤 스테이징 `/room/1`을 데스크톱 브라우저와 A23에서 열어 압축된 wasm·모델로 감지가 시작되는지 확인한다. 헤더 확인만으로는 풀어 쓰는 동작까지 보장하지 못한다                                                      |
| 기기          | A23은 다른 세션이 쓸 수 있어 측정 전에 실행 중인 측정 프로세스와 앞 화면을 확인한다                                                                                                                                    |

## 범위 밖

- 운영 배포 잡과 운영 주소 확인(BY-798).
- S3에 쌓이는 옛 해시 파일 정리(수명 주기 규칙, 인프라 후속).

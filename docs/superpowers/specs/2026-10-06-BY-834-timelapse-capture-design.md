# BY-834 타임랩스 촬영과 기기 보관 설계

## 배경

- 기능 명세는 AI 위키 `product/specs/BY-822-타임랩스.md`이고, 이 문서는 그중 촬영과 기기 보관(BY-834)의 구현 설계다.
- 싱글룸 세션 동안 10초마다 사진을 찍어 IndexedDB에 두고, 세션이 끝나면 영상에 쓸 360장만 남긴다.
- 재생·목록(BY-888), 설정 화면(BY-887), 영상 파일과 공유(BY-889)는 이 문서가 만든 저장소와 설정 모델을 읽는다.

### 코드 조사에서 명세와 달랐던 점

- 워커는 얼굴 랜드마크 전체를 메인 스레드로 보내고 메인 스레드의 `faceLandmarker.ts`가 버린다(`workerProtocol.ts`의 face `result`). 명세의 "얼굴 좌표는 지금처럼 워커 밖으로 나가지 않는다"는 지금 코드와 다르다. 이 설계는 스티커를 워커 안에서 입히므로 타임랩스 때문에 좌표가 새로 나가는 곳은 없다. 위키 문구는 정정 후보로 남긴다.
- 사물 모델과 얼굴 모델은 각자 `createImageBitmap`으로 프레임을 따로 뜬다. 얼굴 모델은 사람이 잡힌 틱 중 2틱에 한 번(`FACE_FRAME_DIVISOR`)만 돈다.
- 세션을 구분하는 클라이언트 id는 없고 세션 시작 시각 `startedAtMs`가 그 역할을 한다. 웹뷰만 다시 뜨면 `useActiveSessionRestore`가 같은 `startedAtMs`로 세션을 이어받는다. 앱을 다시 켜면 `closeStaleSession`이 서버에서 세션을 끝내고 `startedAt`을 돌려준다.
- 아이폰 세로 카메라는 1280×720을 주므로 9:16으로 자르면 405×720이다.
- 워커나 `createImageBitmap(video)`를 못 쓰는 기기는 메인 스레드에서 `<video>`로 바로 추론한다(`mediapipeModule.ts`).

## 접근 비교

| 안      | 내용                                                                                                              | 평가                                                                                                            |
| ------- | ----------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------- |
| A(채택) | 비전 런타임 안에서 찍는다. 얼굴 모델 요청에 사진 요청을 붙이고, 추론이 도는 곳이 자르기·스티커·JPEG 압축까지 한다 | 스티커가 얼굴 모델이 본 프레임에 정확히 입혀진다. 압축이 워커에서 돈다. 워커 메시지와 런타임 핸들을 고쳐야 한다 |
| B       | 메인 스레드에서 `<video>`를 캔버스에 떠서 찍는다                                                                  | 스티커가 최대 2초 전 얼굴 위치에 입혀져 얼굴이 드러날 수 있다. 저사양 기기에서 메인 스레드가 압축으로 막힌다    |

## 구조

```
RoomPage (싱글룸, 플래그 on)
  └ timelapseRecorder ── 세션 시작 때 설정 스냅샷 ── timelapseSettings (localStorage)
        │ photoTap { due(atMs), save(photo, atMs) }
        ▼
  focusDetector.processFrame (1초 루프, 사물 결과 뒤)
        ├ 가림 켬 + 사람 있음 + 이번 틱 얼굴 모델 돎 → face.detect(video, ts, photoSpec)
        ├ 가림 켬 + 사람 있음 + 얼굴 모델 못 돎       → 찍지 않음
        └ 그 밖 (사람 없음, 가림 끔)                  → object.capture(video, photoSpec)
        ▼
  런타임 핸들 (워커 / 메인 스레드 예비 경로)
        자르기 → 가림이면 랜드마크 상자에 스티커 → JPEG Blob
        ▼
  timelapseStore (IndexedDB)
```

### 파일

| 위치                                      | 역할                                                                                                                   |
| ----------------------------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| `features/timelapse/timelapseSettings.ts` | 설정 모델, 키 `focuson.timelapse.v1`, `ambientSoundStore.ts`와 같은 모양(파서·기본값·메모리 저장소)                    |
| `features/timelapse/photoFrame.ts`        | 자르기 계산, 랜드마크 → 스티커 상자, 캔버스 그리기와 JPEG 압축. 워커와 메인 스레드가 함께 쓴다                         |
| `features/timelapse/captureSchedule.ts`   | 촬영 차례 판정, 720장 솎기와 간격 두 배, 고르게 n장 고르기                                                             |
| `features/timelapse/timelapseStore.ts`    | IndexedDB 저장소                                                                                                       |
| `features/timelapse/timelapseRecorder.ts` | 세션 생애주기와 저장소 연결, photoTap 제공. 감지기가 세션 시작 시각이 정해지기 전에 만들어져 훅이 아니라 평범한 객체다 |
| `vision/mediapipePort.ts` 외 런타임       | 얼굴 `detect`의 사진 요청, 사물 핸들의 `capture`                                                                       |

### 런타임 변경

- 얼굴 `detect` 메시지에 선택 항목 `photo`(비율, 가림 여부, 긴 변 상한, 품질)를 더한다.
- 워커는 추론 직후 같은 프레임으로 사진을 만들고 face `result`에 `photo: Blob`을 담아 보낸다.
- 추론 없이 자르고 압축만 하는 `capture` 메시지를 더한다. 사물 핸들이 세션 내내 살아 있으므로 사물 핸들에 둔다.
- 스티커 PNG는 워커가 첫 사진 요청 때 한 번 받아 `ImageBitmap`으로 둔다.
- 메인 스레드 예비 경로는 `HTMLCanvasElement`로 같은 `photoFrame` 함수를 부른다.
- photoTap을 넘기지 않으면 지금과 같은 메시지만 오가므로 소셜룸은 바뀌지 않는다.

## 저장과 생애주기

### 저장 구조

- DB `focuson-timelapse`, 버전 1.
- `timelapses` 저장소는 키 `startedAtMs`에 상태(`recording`·`ready`), 설정 스냅샷, 현재 촬영 간격, 다음 순번, 장 수, 세션 요약을 둔다.
- 세션 요약은 끝난 시각, 공부·순공 시간, 타임라인 구간이다(복구로 끝난 세션은 구간이 없다).
- `photos` 저장소는 키 `[startedAtMs, 순번]`에 JPEG Blob과 찍은 시각을 둔다.

### 촬영

- 세션을 시작하면 `startedAtMs`로 기록을 만들고, 같은 키의 `recording` 기록이 있으면 이어 쓴다.
- 촬영 간격은 10초에서 시작한다.
- 720장이 되면 순번 순서로 한 장 걸러 지우고 간격을 두 배로 늘린다.
- 일시정지·백그라운드에는 감지 루프가 멈추므로 촬영도 멈춘다.
- 사진은 찍을 때마다 바로 저장한다.

### 종료와 복구

- `endAndSubmit`이 끝나면 기기에서 잰 순공이 1분 이상인 세션은 고르게 360장을 남기고 `ready`로 바꾼다.
- 순공이 1분 미만인 세션은 기록과 사진을 지운다.
- `closeStaleSession` 응답이 오면 `startedAt`이 같은 `recording` 기록을 같은 규칙으로 정리한다.

### 보관 정리

- 기록이 `ready`가 될 때와 세션을 시작할 때 정리한다.
- `ready` 기록은 최신 7개만 남기고 7일이 지나면 지운다.
- `recording` 고아 기록은 7일이 지나면 지운다.

### BY-888로 넘기는 것

- D-Day와 연속 공부 일수는 재생하는 쪽이 결과 화면에서 기록한다.
- 이 티켓은 기기 안에 있는 값만 저장한다.

### 실기기

- 요청 로그로 사진이 네트워크로 나가지 않는지 센다.
- 720장일 때 용량과 저장 시간을 측정한다.
- A23에서 감지 주기가 밀리지 않는지 확인한다.
- iOS에서 `OffscreenCanvas.convertToBlob`과 워커 경로가 도는지 확인한다.

## 알려진 한계

- 사람이 없다고 본 프레임과 실제로 찍는 프레임 사이에 수백 ms 틈이 있어 그 사이 들어온 얼굴은 가림이 켜져 있어도 가려지지 않는다. 명세가 촬영 때 얼굴 검출을 추가로 돌리지 않도록 정해서 이 틈은 막지 않는다.
- 가림이 켜졌는데 얼굴 모델이 세션 내내 꺼져 있으면 사람이 없는 장면만 남는다.
- 가림이 켜진 세션에서 사람은 잡혔는데 얼굴 모델이 얼굴을 찾지 못하면(옆모습, 낮은 신뢰도, 일부 가려짐) 명세가 가림을 얼굴을 찾은 장면에만 적용하도록 정해 그 사진은 스티커 없이 저장된다.
- 사물 모델이 사람을 놓친 프레임은 가림 없이 찍는 경로로 가서 그대로 저장된다.

# BY-913 초대 링크를 브라우저로 열었을 때 앱 참여 안내

## 배경

초대 링크(`/social/join?code=NNNN`)를 앱이 없는 사람이 카카오톡 인앱 브라우저나 일반 브라우저로 열면 초대코드 입력 화면이 그대로 보였다.
브라우저에는 토큰 출처가 없어 `useUserId()`가 `null`이고, 그래서 주 버튼 `참여하기`는 코드를 다 입력해도 꺼져 있었다.
실제로 쓸 수 있는 `앱에서 참여하기`는 그 아래 회색 ghost 버튼이었다.
Amplitude 세션 리플레이에서 사용자가 브라우저에서 4자리를 입력하는 모습이 보였다.

## 결정

| 항목           | 결정                                                                                                   |
| -------------- | ------------------------------------------------------------------------------------------------------ |
| 대상           | 브리지가 없는 모바일 브라우저(`storePlatform !== null`). 인앱·일반 브라우저, iOS·Android 모두 해당한다 |
| 제외           | 앱 웹뷰(신·구 앱)와 PC 브라우저는 지금 화면을 유지한다                                                 |
| 화면 구성      | 입력칸, 꺼진 `참여하기`, ghost 버튼을 없애고 코드를 읽기 전용으로 보여 준다                            |
| 주 버튼        | `앱에서 참여하기`를 primary(`variant="default"` + `shadow-sb-cta`)로 둔다                              |
| 코드 없음      | 코드가 없거나 4자리가 아니면 코드 칸을 빼고 문구만 바꾼다                                              |
| 코드 복사 버튼 | 두지 않는다                                                                                            |

### 코드를 지우지 않고 보여 주는 이유

iOS는 스토어를 거치면 초대코드가 앱에 전달되지 않는다(`storeLink`의 iOS 분기는 페이지 이동만 한다).
iOS 미설치자는 설치 뒤 코드를 직접 입력해야 하므로, 웹 화면에 코드가 남아 있어야 다시 찾지 않아도 된다.
Android는 Install Referrer로 코드가 복원된다.

## 문구

| 위치      | 코드 있음                           | 코드 없음                                   |
| --------- | ----------------------------------- | ------------------------------------------- |
| 제목      | `그룹 스터디에 초대받았어요`        | `그룹 스터디에 초대받았어요`                |
| 코드 칸   | 4칸 읽기 전용                       | 없음                                        |
| 보조 문구 | `앱에서 이 코드로 참여할 수 있어요` | `앱에서 초대코드를 입력해 참여할 수 있어요` |
| 버튼      | `앱에서 참여하기`                   | `앱에서 참여하기`                           |

보조 문구에 "설치한 뒤"를 넣지 않았다.
앱이 이미 깔려 있는데 인앱 브라우저의 자동 열기가 막힌 사람도 이 화면을 본다.

## 구현

- `InviteCodeJoinPage` 안에서 `storePlatform !== null`일 때 안내 화면을 그린다.
- 코드 칸은 방 생성 화면(`InviteCodeSharePage`)과 같은 `CODE_CELL_CLASS`를 쓰고, 묶음에 `role="group"`과 `aria-label="초대코드 NNNN"`을 붙인다.
- 버튼 동작은 기존 ghost 버튼과 같다(`trackStoreLinkRedirected` 뒤 `openInApp`).
- 버튼과 인앱 브라우저 첫 로드의 자동 앱 열기는 같은 `handoffCode`(4자리면 그 코드, 아니면 빈 문자열)를 쓴다. 그래서 미완성 코드 링크는 코드 없는 링크처럼 자동 열기를 하지 않는다.
- `trackInviteLinkOpened`와 뒤로 가기 헤더는 바꾸지 않는다.
- 공용 컴포넌트는 만들지 않는다. 방 생성 화면과 겹치는 마크업이 열 줄 남짓이다.

## 테스트

- 모바일 브라우저와 코드가 있으면 읽기 전용 코드 묶음과 `앱에서 참여하기`만 보이고 입력칸과 `참여하기`는 없다.
- 모바일 브라우저와 코드가 없으면 코드 묶음이 없고 코드 없음 문구가 보인다.
- PC 브라우저는 기존 입력 화면을 본다.
- 인앱 브라우저라도 미완성 코드면 첫 로드에 앱 열기를 시도하지 않는다.
- 기존 테스트 "코드 입력이 바뀌어도 openInApp을 다시 부르지 않는다"는 삭제한다. 모바일 브라우저에는 입력칸이 없어 코드가 바뀔 일이 없고, 중복 발사는 StrictMode 테스트가 계속 막는다.

## 범위 밖

- PC 브라우저 화면은 이번에 바꾸지 않는다.
- 모바일 브라우저에 `?userId=N`을 붙여 여는 개발용 브라우저 단독 경로도 안내 화면이 된다. 실제 사용자 경로가 아니라서 별도로 예외 처리하지 않는다.

## 시안

Figma V2 파일의 초대코드 입력 시안 옆에 모바일 브라우저 안내 화면을 라이트·다크 프레임으로 추가한다.

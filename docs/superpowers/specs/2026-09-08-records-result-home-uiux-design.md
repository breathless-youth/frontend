# 기록 탭 · 공부 결과 · 홈 UI/UX 개선 설계

작성 2026-09-08. 대상 티켓 BY-557, 560, 564, 566, 567, 568과 합의로 포함한 BY-574, 565, 562. 홈 개선은 신규 티켓으로 만든다.

## 목표

Figma V1.4 `S10 · 기록 & 세션 완료 축하` 섹션의 시안 8장과 팀원이 공유한 React 프로토타입(`공부완료-standalone.html`)에 맞춰 세 화면을 다시 만든다.

- 공부 결과 화면에 도장 모션과 스트릭 점화 화면을 넣어 성취감을 준다.
- 기록 탭에 주간 막대 추이, 월간 농도 달력, 세션 상세 시트를 넣는다.
- 홈 화면을 같은 톤으로 고치고 스트릭 컴포넌트를 결과 화면과 공유한다.
- 디자인 작업용 스킬(`animate`, `review-animations`, 저장소 스킬 `focusmakers-design`)을 도입한다.

## 확정된 결정

### 용어

| 현재                                           | 확정                      |
| ---------------------------------------------- | ------------------------- |
| 집중률, N% 집중                                | 유지, 표기는 `집중률 N%`  |
| 기간 평균 라벨                                 | `평균 집중률`             |
| 집중 시작(홈 CTA)                              | 유지                      |
| 집중 측정 중(세션 화면)                        | `순공시간 측정 중`        |
| 비집중(범례·카드)                              | `휴식`, 횟수는 `휴식 N회` |
| 최장 집중                                      | `최장 순공시간`           |
| 코드 식별자 `FOCUS`, `DISTRACTION`, `focusSec` | 유지                      |
| 약관·개인정보 문서                             | 제외                      |

- 용어집은 `docs/domain-glossary.md`와 `.ai` 레포 제품 용어집 두 곳을 고친다.
- 탭 순서는 앱 현행 홈·소셜·기록·설정을 유지한다. 시안의 순서가 틀렸다.
- 주 시작 요일은 월요일로 통일한다.

### 의존성

`@radix-ui/react-tabs`(주간/월간 토글), `vaul`(바텀 시트), `@radix-ui/react-collapsible`(휴식 카드 펼침), `@radix-ui/react-progress`(홈 게이지가 남을 때만)를 쓰는 단계에서 추가한다. `recharts`와 `react-day-picker`는 보류한다. 애니메이션 라이브러리는 추가하지 않는다.

### 공부 결과 화면 흐름

```
완료(도장 프레스 → 발바닥 자국) → [탭 또는 3.5초] 상세 펼침(순공·총 공부·집중률·타임라인·휴식 카드)
  ├─ 오늘 첫 도장이면: CTA `계속` 하나 → 스트릭 화면(자동 점화) → `홈으로` / `기록 보러가기`
  └─ 아니면: CTA `홈으로` / `기록 보러가기`
```

- 스트릭 점화는 자동이다. 프로토타입의 꾹 누르기는 쓰지 않는다.
- 인트로 명언 화면, 캔버스 컨페티, 타임라인 구간 탭 상세는 넣지 않는다.
- reduced-motion이면 도장은 정지 상태, 상세는 바로 펼침, 스트릭 화면은 점화된 상태로 시작한다.
- 소셜 룸 결과에도 같은 흐름을 적용한다. 도장 기준이 세션 단위라 룸 종류와 무관하다.

### 자정 분할 세션의 도장 판정

서버는 자정을 넘긴 세션을 어제(D)와 오늘(D+1) 두 건으로 나눈다. 도장 기준은 세션 한 건의 순공 10분 이상(`focusSec >= 600`)이다.

| D / D+1               | 새 도장 | 스트릭 화면 | 표현                                                                                 |
| --------------------- | ------- | ----------- | ------------------------------------------------------------------------------------ |
| 10분 이상 / 10분 이상 | 둘 다   | 표시        | 어제 칸이 먼저, 오늘 칸이 이어서 찍힌다. 부제 "자정을 넘겨 이틀치 도장을 찍었어요"   |
| 10분 이상 / 10분 미만 | 어제만  | 표시        | 어제 칸만 찍히고 오늘 칸은 빈 링. 부제 "어제 도장 완료, 오늘도 10분만 하면 이어져요" |
| 10분 미만 / 10분 이상 | 오늘만  | 표시        | 오늘 칸만 찍힌다. 어제가 빈 칸이면 서버 스트릭 값을 그대로 보여준다                  |
| 10분 미만 / 10분 미만 | 없음    | 미표시      | 완료 화면에 "10분 이상 순공하면 도장이 찍혀요" 한 줄                                 |

- 그날의 첫 도장인지는 `GET /api/stats?date=D`의 세션 목록에서 이번 세션 id를 뺀 나머지에 순공 10분 이상 세션이 없으면 첫 도장으로 본다. 백엔드 변경은 없다.
- "N일째"는 제출 직후 다시 조회한 `GET /api/stats/streak`의 `streak` 값이다.
- 일별 통계나 스트릭 조회가 실패하면 스트릭 화면을 생략하고 `reportHandled`로 남긴다. 틀린 스트릭 화면을 보여주지 않기 위해서다.
- 더 깔끔한 방법인 제출 응답의 `streakUpdated` 필드는 BY-562에서 백엔드에 제안한다.

### 기록 탭

- 주간·월간 모드와 선택일은 컴포넌트 state로 둔다. 딥링크 요구가 없고 search param으로 두면 허용 목록과 분석 노출까지 끌려온다.
- 기간 집계는 `GET /api/stats/period`의 `dailyList`와 `compareDailyList`로 만든다. 주간 막대, 월간 3단계 농도(1시간 미만 / 1~3시간 / 3시간 이상), "지난주보다 N시간 M분 늘었어요" 문구가 전부 이 응답에서 나온다.
- 선택일 타일과 세션 목록은 기존 일별 통계 조회를 그대로 쓴다.
- 스트릭 배너는 기록 탭에서 빠지고 홈과 결과 화면으로 간다.
- 세션 상세 시트는 `GET /api/study-sessions/{id}`로 타임라인을 받는다.

### 자산과 모션

- 자산은 도장 PNG, 포메 기본·점화 표정 PNG(표시 크기의 3배인 528px WebP), 발바닥 SVG(`currentColor`)다. 원본과 모션 타이밍 표는 `~/Downloads/공부완료-standalone-extracted/`에 있다.
- 모션은 CSS keyframes에 transform과 opacity만 쓴다. 숫자 카운트업은 requestAnimationFrame이다. keyframes는 `index.css`에 두고 사용처에서 `animate-[...]`와 `motion-reduce:animate-none`을 붙인다.
- 도장 빨강 `#E5342A`와 따뜻한 배경 그라디언트는 토큰에 없다. 1단계에서 프리미티브 매핑이나 시맨틱 토큰 추가를 시안 의견으로 낸다.

### 시안 처리

- 시안은 Figma 라이브러리 컴포넌트와 시맨틱 변수로 다시 조립한다. 원본 프레임은 손대지 않고 임시 섹션에 만든다.
- 사용자 최종 승인분만 V1.4 섹션으로 옮긴다.
- 스트릭 도장 칸은 Done, New, Today, None, Future 다섯 상태로 만들어 코드의 상태와 1:1로 맞춘다.

## 검증

- 단계마다 typecheck, lint, 해당 파일 vitest를 돌린다.
- 화면은 402px 브라우저에서 확인한 뒤 Expo Dev Client 실기기로 확인한다.
- 모션은 `review-animations` 스킬로 점검하고 OS의 동작 줄이기 설정에서 정지 대안을 확인한다.
- 접근성은 `accessibility-audit` 스킬로 44px 터치 타겟, aria, 대비를 점검한다.

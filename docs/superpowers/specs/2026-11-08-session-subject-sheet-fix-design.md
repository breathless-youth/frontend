# 세션 과목·할 일 시트 터치 복구와 순서 변경

사용자 제보: 운영 Android와 iPhone의 세션에서 새 과목 버튼·시트 내부 버튼·바깥 영역 닫기가 모두 동작하지 않으며 할 일 시트도 같다.

## 확인한 원인과 수정

실제 `SessionPage`와 `SessionSubjectPanel`을 조합한 브라우저 재현에서, 바깥 Radix 모달이 `body`의 포인터를 막은 상태로 Base UI 바텀시트가 그 모달 밖에 포털을 만들었다. 입력 클릭을 바깥 과목 화면이 가로챘다. 단독 시트 테스트는 이 조합을 포함하지 않았다.

`SessionPage`의 모달 콘텐츠를 중첩 시트용 포털 컨테이너로 제공한다. 명시적으로 전달한 컨테이너와 세션 밖 시트의 기존 body 기본값은 유지한다. 입력·내부 버튼·바깥 닫기가 동작하고, 시트만 닫으면 측정과 과목 페이지는 유지돼야 한다. 실제 카메라를 켜거나 운영 계정에 과목을 생성하는 방식으로 검증하지 않는다.

## 사용자 추가 요청

- 세션 과목 화면 왼쪽 아래 버튼을 `순서 변경`에서 `할 일 추가`로 바꾼다.
- 별도 순서 편집 모드 대신 플래너처럼 길게 누르고 끌어 과목 순서를 바꾼다.
- 길게 눌러 여는 과목 메뉴에서는 `할 일 추가`를 없앤다. 이름 변경·제거·삭제는 유지한다.
- 짧게 누르는 공부 과목 선택/멈추기, 할 일 완료와 스크롤은 유지한다.
- 드래그 취소·잘못된 영역 놓기에는 저장하지 않는다. 바뀐 순서만 저장한다.
- 세로와 가로 화면에 모두 적용한다.

## 검증 범위

중첩 모달의 입력·버튼·바깥 닫기 회귀는 수정 전 실패와 수정 후 통과를 확인한다. 실제 React 화면의 과목 생성·오늘 등록·할 일 생성·시트 닫기·순서 변경을 합성 API로 재생한다. 실제 iPhone/Android 실행 여부는 브라우저 결과와 구분해 기록한다. 초 단위 길이 표시 후속 수정은 별도 설계를 유지하며 덮어쓰지 않는다.

## 로컬 확인 결과

- 세로·가로·360px 화면에서 실제 과목 생성, 오늘 등록, 할 일 생성, 시트 재열기와 바깥 닫기를 확인했다. 합성 API만 사용했고 운영 저장은 하지 않았다.
- 세로·가로의 Chromium 터치 이벤트로 길게 누르기와 순서 변경을 확인했다. 따라오는 카드의 화면 좌표·fixed 위치·세션 배경색, 순서 저장 1회를 확인했다.
- 독립 리뷰에서 다른 손가락의 포인터 종료, 길게 누르기 전 바깥에서 놓기, 카드의 세션 색 변수, fixed 스타일 우선순위 문제를 찾아 회귀와 함께 수정했다.
- 입력·포커스·Tab·Escape·바깥 닫기와 바깥 모달 종료 후 잠금 해제를 확인했다. 실제 iPhone/Android 앱 조작 검증은 포함하지 않는다.
- 왼쪽 버튼은 세로에서 측정 중인 과목, 가로에서 보고 있는 과목을 할 일 입력의 기본값으로 사용한다. 과목 머리를 끌기 시작점으로 사용해 할 일 체크·편집과 스크롤을 보존한다.

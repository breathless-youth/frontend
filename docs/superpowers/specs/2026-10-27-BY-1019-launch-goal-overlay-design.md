# BY-1019 스플래시 직후 목표 문구 오버레이 설계 (PoC)

## 목표

앱 콜드 스타트 때 네이티브 스플래시가 걷히면 같은 배경과 로고 위치로 RN 오버레이를 이어 그리고,
사용자가 프로필에 적은 목표 문구와 닉네임을 보여 준다. 오버레이는 홈 로드 시간을 가린다.

OS 스플래시(iOS LaunchScreen, Android 12+ SplashScreen API)는 빌드 때 넣은 정적 이미지만 그릴 수
있어 사용자별 문구를 넣을 수 없다. 그래서 스플래시 다음 화면을 스플래시처럼 보이게 만든다.

## 결정 (사용자 승인, 2026-10-27)

| 항목           | 결정                                                                                    | 이유                                                                                   |
| -------------- | --------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------- |

| 배치           | 로고는 스플래시 자리 그대로, 아래에 목표 문구·구분선·닉네임, 맨 아래 점 3개와 로딩 문구 | 움직이는 것이 문구뿐이라 스플래시와 이어진다. Figma V1.4 `2733:7194` 참고              |

## 구조

| 파일                                      | 역할                                                                        |
| ----------------------------------------- | --------------------------------------------------------------------------- |
| `lib/launchGoal.ts` (신규)                | SecureStore 저장값 읽기, 프로필을 받아 `goal`·`nickname` 저장하기           |
| `lib/firstScreenLoaded.ts` (신규)         | 첫 웹뷰 로드 신호. 켜기와 구독                                              |
| `components/LaunchGoalOverlay.tsx` (신규) | 오버레이 화면, 최소·최대 노출, 페이드                                       |
| `components/RemoteScreen.tsx`             | `onLoadEnd`에서 첫 로드 신호를 켠다                                         |
| `app/_layout.tsx`                         | 저장값 읽기를 스플래시 걷는 조건에 넣고, 오버레이를 그리고, 갱신을 호출한다 |

### 흐름

1. 루트 레이아웃이 마운트되면 저장값 읽기를 시작한다. 스플래시는 폰트, 업데이트 판정, 저장값 읽기가 모두 끝나야 걷힌다. 홈 스켈레톤이 한 프레임 보였다가 오버레이가 덮는 깜빡임을 막기 위해서다.
2. 저장값에 `goal`이 있고 판정이 `pass`면 `Stack` 위에 오버레이를 절대 위치로 그린다. 문구는 0.4초 동안 페이드인한다.
3. 어느 `RemoteScreen`이든 처음 `onLoadEnd`가 오면 `firstScreenLoaded` 신호가 켜진다. 푸시로 홈이 아닌 탭이 먼저 열려도 그 탭을 기다린다.
4. 최소 1.5초와 첫 로드가 모두 충족되거나 5초가 지나면 0.2초 페이드아웃 뒤 언마운트한다.
5. `ensureUserRegistered` 뒤에 프로필을 받아 저장한다. `AppState`가 `background`가 될 때도 받는다.

### 프로필 조회

- `apiFetch`(`endpoint: "profile"`)에 `Authorization: Bearer <accessToken>`를 붙인다.
- 401이면 `refreshAuth()` 뒤 한 번만 다시 시도한다.
- 성공 응답의 `goal`이 null이거나 빈 문자열이면 저장값을 지운다.
- 네트워크 오류나 그 밖의 실패는 저장값을 유지한다.
- 토큰이 없으면 호출하지 않는다.

### 화면

- 배경색은 스플래시와 같다(라이트 `#f8fafd`, 다크 `#0d1118`).
- 로고는 `splash-icon.png`·`splash-icon-dark.png`를 폭 240으로 화면 정중앙에 둔다.
- 목표 문구는 굵게 최대 2줄, 구분선 20×2, 닉네임은 작은 굵은 글씨다. 로고 아래에 놓는다.
- 맨 아래에 점 3개와 로딩 문구를 둔다. 점은 차례로 깜빡인다.
- 모션 줄이기 설정이면 페이드와 점 깜빡임 없이 그린다.
- 오버레이는 `pointerEvents="none"`이 아니다. 걷히기 전 아래 웹뷰를 누르지 못하게 한다.

## 테스트

- `launchGoal`: 성공 시 저장, `goal` null이면 삭제, 401 뒤 갱신해 재시도, 실패 시 저장 유지, 깨진 저장값은 없음으로 읽기.
- `LaunchGoalOverlay`: 1.5초 전에는 로드가 끝나도 남아 있다, 1.5초 뒤 로드가 끝나야 걷힌다, 로드가 없으면 5초에 걷힌다, 걷힌 뒤 언마운트된다.
- 로고 위치 일치와 배경색은 iOS·Android 실기기에서 눈으로 확인한다.

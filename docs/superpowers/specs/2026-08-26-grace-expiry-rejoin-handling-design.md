# 소셜룸 유예 만료 복귀 처리와 재입장 초기화 취급 (BY-440)

- 날짜: 2026-08-26
- 티켓: BY-440 — [FE] 소셜룸 > 유예 만료 복귀 처리와 재입장 초기화 취급
- 연관: BY-431(유예 재입장 공부시간 표시 — 이 티켓이 기획 변경으로 되돌린다),
  BY-433(세션 로컬 저장·재제출 — 그대로 활용), BY-436(`socialRoomNotice` — 그대로 활용),
  BY-427(입장 프리뷰 모달 제거 — 전제)

## 배경

기록은 구간별 별도 세션으로 저장된다. 서버 중복 방지가 갱신이 아니라 무시 방식이라 한 건으로
합칠 수 없다. 그런데 룸 화면 시간은 이전 값에 이어 붙어(BY-431) 화면에는 12분, 기록에는
7분처럼 어긋나 보인다. 화면과 기록이 항상 일치하도록 처리를 다음으로 바꾼다:

- 유예(30초) 안 복귀: 세션이 살아 있으므로 기존과 동일. 일시정지 복귀, 수동 재개로
  멈췄던 시간부터 잇는다. 코드 변경 없음.
- 유예를 넘긴 복귀: 자동 종료·제출 후 소셜 탭으로 이동, 저장 안내 토스트.
- 재입장(앱·웹뷰가 죽어 입장 플로우를 다시 밟는 경우): 처음부터 시작과 동일 취급.

백엔드 변경 없음.

## 설계

### 1. 유예 넘김 복귀 — 자동 종료·제출·소셜 탭 이동

#### 감지: `useBackgroundGraceWatch` (신규, `apps/web/src/features/live-room/`)

- `systemPauseSource` 어댑터를 구독한다. `onLeave`에서 숨은 시각을 기록하고 `onReturn`에서
  벽시계 경과를 계산해, `GRACE_MS = 30_000`(서버 유예와 같은 값) 이상이면 만료 콜백을
  1회 부른다. `enabled`(세션 `phase === "studying"`)가 아니면 감시하지 않는다.
- 기존 `usePauseAutoEnd`(수동·백그라운드 공용 20분)는 손대지 않는다 — "트리거로 임계값을
  가르지 않는다"가 확정 정책이다. 이 훅은 일시정지가 아니라 숨은 시간만 보므로, 카메라를
  끄고(수동 일시정지) 화면을 보고 있는 경우를 오판하지 않는다.
- 클라이언트 30초 판정은 안전한 하한이다. 서버 유예는 연결 끊김 감지 시점(백그라운드
  진입보다 뒤)에 시작하므로, 서버가 만료됐는데 클라이언트가 세션을 계속 잇는 경우는 없다.
- `systemPauseSource` 어댑터에 `pageshow` 복귀 구독을 추가한다(2026-08-26 codex 지적).
  iOS WKWebView는 `visibilitychange` 없이 `pagehide`만 발화할 수 있는데, 복귀 짝인
  `pageshow`가 없으면 그 경로에서 복귀 재계산과 유예 판정이 통째로 빠진다.

#### 만료 시 처리 (`LiveRoomSession`)

1. `channel.disconnect()` 먼저 — STOMP 자동 재연결이 재구독·발행으로 서버 상태를 건드리는
   경쟁을 끊는다.
2. `endAndSubmit(autoEndReason("BACKGROUND"))` — 기존 종료·제출 경로 그대로. 백그라운드
   구간은 PAUSE라 공부시간에서 이미 빠져 있고, 제출 직전 체크포인트 저장(BY-433)도 그대로
   탄다.
3. 기존 done 이동 effect를 확장한다. 만료 여부는 종료 사유(`endReason`)가 아니라 유예
   감시가 만료 콜백에서 기록한 상태(`graceExpired`)와 이동 시점 재판정(`isExpiredNow()`,
   숨김 시작 시각을 구독 해제 후에도 ref로 보존)의 합으로 판정하고, 만료였으면
   `markSocialRoomNotice(문구)` 후 `/social`로 이동한다. 재판정을 두는 이유: 숨어 있는
   동안 공용 20분 감시자가 먼저 종료를 끝내면 세션이 끝나며 감시가 풀려 복귀 콜백이
   오지 않는데, 그 순서에서도 안내·이동이 빠지면 안 된다(2026-08-26 codex 재채점 지적).
   - 성공(`done`): `자리를 오래 비워서 여기까지의 공부 기록을 저장했어요`
   - 실패(`error`): `자리를 오래 비워서 공부를 종료했어요. 기록은 잠시 후 자동으로 저장돼요`
     — 실패해도 이동한다. 보관분이 다음 실행에서 재제출된다(BY-433).
   - 순공 1분 미만(`focusSec < SUB_MINUTE_SEC`): 성공·실패 구분 없이
     `자리를 오래 비워서 공부를 종료했어요.` 줄바꿈 `1분 미만 공부는 기록에 표시되지 않아요`
     (두 문장은 줄을 바꿔 보여준다 — 2026-08-26 실기기 확인 피드백).
     순공 1분 미만은 기록 목록·합산에 표시되지 않는 정책(2026-07-27 확정)이라 저장을
     약속하면 화면이 거짓말이 된다(`sessionCopy.SUB_MINUTE_EXIT_DESCRIPTION`과 같은 원칙).
     제출 자체는 순공시간과 무관하게 수행한다 — 백엔드는 모든 세션을 저장하는 것이 계약이다.
   - 안내는 BY-436의 `socialRoomNotice`(1회성 소비)를 쓰되 저장소를 localStorage로 바꾼다
     (2026-08-26 실기기 확인 피드백). 앱은 탭·세션 화면이 각각 별도 웹뷰라 sessionStorage가
     공유되지 않고, 세션 웹뷰가 임시로 그린 소셜 홈에서 토스트가 떴다가 네이티브 탭 전환에
     잘려 깜빡였다. 세션 웹뷰의 내부 이동은 `noticeHandoff` router state로 표시해 네이티브
     셸에서는 소비하지 않고, 도착지인 진짜 소셜 탭 웹뷰가 한 번만 띄운다. router state로
     문구 자체를 싣는 방식은 웹뷰 리로드 시 토스트가 반복되는 문제로 이미 기각됐다.
   - 종료 사유로 판정하지 않는 이유(2026-08-26 codex 지적): 카메라를 끈 채(수동 일시정지)
     20분 넘게 숨었다 돌아오면 공용 20분 감시자가 최초 트리거 `MANUAL` 사유로 먼저
     종료시킬 수 있다. 사유만 보면 이 경우 안내가 빠지고 실패 시 이동도 빠진다. 유예
     감시의 만료 콜백은 같은 복귀 이벤트에서 이어서 돌므로, 거기서 기록한 상태로 판정하면
     누가 먼저 종료시켰든 안내·이동이 나간다.

#### 제출 중복 방지 가드 (`useStudyRoomSession.endAndSubmit`)

20분 감시자와 새 훅이 같은 복귀 이벤트에서 동시에 발화할 수 있다. `endAndSubmit`에 제출
진행 중이면 건너뛰는 가드를 추가한다. 현재도 "다시 제출" 연타 시 중복 POST가 나가던 것을
함께 막는다(서버 멱등이라 사고는 아니지만 시도 계측이 부풀었다).

### 2. 재입장 처음부터 취급 (BY-431 표시 이어붙이기 제거)

- `LiveRoomSession`: `baseStudySeconds` state와 SNAPSHOT 캡처 effect를 제거한다.
  내 타일·뱃지·발행 모두 로컬 `focusSec`만 쓴다.
- `useRoomStatePublisher`: `focusSec`을 `number | null`에서 `number`로 되돌리고, 마운트 시
  1회 `studySeconds` 즉시 발행을 추가한다(카메라 초기 발행과 같은 패턴 — 연결 전이면 채널
  버퍼가 연결 직후 내보낸다). 재입장이면 서버 보존값을 0으로 덮어 다른 참가자 화면의 잔상이
  사라지고, 일반 입장은 서버 값도 0이라 무해하다. 살아 있는 세션의 소켓 재연결은 재마운트가
  아니므로 발동하지 않는다.
- `LiveRoomEntry`: `initialCameraOn`을 무조건 `false`로 — `graceRejoin`도 일반 입장과 같이
  카메라 끔(일시정지)으로 들어간다. 프리뷰 모달은 BY-427에서 이미 없다.
  `entryState.cameraOn`을 더 이상 읽지 않으므로, 다른 소비자가 없으면 필드도 정리한다.

### 3. 재제출 토스트의 1분 미만 집계 제외 (BY-433 후속, 2026-08-26 추가)

`resubmitPendingSessions`는 지금 순공시간과 무관하게 성공 건수를 반환하고, App이 1건
이상이면 `저장하지 못했던 공부 기록을 저장했어요`를 띄운다. 복구된 세션이 전부 순공 1분
미만이면 같은 거짓말이 된다. 재제출·삭제 동작은 그대로 두고, **반환 건수를 순공
1분 이상(`focusSec >= SUB_MINUTE_SEC`) 복구 건만 세도록** 바꾼다 — 전부 미달이면 조용히
저장만 하고 토스트를 띄우지 않는다.

### 4. 토스트 유지시간

`useToast`의 `DEFAULT_TOAST_DURATION_MS`를 3000에서 5000으로 변경한다(전역 — 2026-08-26
사용자 확정).

## 범위 밖 (수용)

- 백그라운드 없이 네트워크 단절만으로 서버 유예가 만료된 경우(복귀 감지가 발동하지 않는
  회색지대)는 기존 동작 그대로 둔다.
- 백엔드 변경 없음 — 유예 복원과 `graceRejoin` 응답은 그대로 두고 프론트가 취급만 바꾼다.

## 테스트 계획 (개요 — 상세 목록은 5-0 게이트에서 승인)

1. `useBackgroundGraceWatch` 단위 — 30초 경계(미만 무발화·이상 발화), 같은 구간 재발화
   방지, `enabled` 꺼짐 시 무발화.
2. `LiveRoomSession` — 만료 시 disconnect → 종료·제출 → 안내 마킹 → `/social` 이동
   (성공·실패 문구 각각), 기준값 이어붙이기 제거 후 표시가 로컬 값인 것.
3. `useRoomStatePublisher` — 마운트 시 `studySeconds` 1회 즉시 발행, 60초 주기 유지.
4. `LiveRoomEntry` — `graceRejoin`이어도 카메라 끔 입장.
5. `endAndSubmit` — 제출 진행 중 재호출이 중복 POST를 내지 않는 것.
6. `useToast` — 기본 유지시간 5초.
7. 유예 만료 안내 — 순공 1분 미만이면 성공·실패 모두 미달 문구로 갈리는 것.
8. `resubmitPendingSessions` — 1분 미만 복구 건은 반환 건수에서 빠지고 제출·삭제는 되는 것,
   1분 이상 건이 섞이면 그 수만 반환하는 것.

## 목적과 범위

홈에서 오늘 공부시간을 먼저 보고 과목을 고른 뒤 공부를 시작할 수 있게 한다. 처음에는 과목 만들기와 순공 5분의 시작 미션을 안내하고, 미션이 끝나면 날짜별 목표 진행률을 같은 자리에 표시한다.

이번 변경은 프론트 구현과 dev 대상 PR까지다. 서버 구현과 운영 배포는 포함하지 않는다. 플래너 전체 개편은 BY-1162 작업이 맡는다.

피그마 시안은 https://www.figma.com/design/nmpEKUAgMwMtLdxIIXGFUB?node-id=10195-23055 이다. 라이트·다크 16개 화면을 직사각형으로 작성했고 피그마 시안에서는 하단 탭바를 제외했다. 제품의 네이티브 탭바는 기존 셸이 계속 담당한다.

디자인 원본은 사용자가 제공한 Home Final v3 핸드오프와 2a~2h 시안이다. HTML을 React 코드로 복사하지 않는다. 아래 인터뷰 결정이 원본과 다른 곳은 인터뷰 결정을 우선한다.

| 서버 저장            | 미션 진행도와 목표는 계정에 저장해 재설치와 기기 변경 후에도 유지한다.  |

## 접근 방식

서버 저장을 전제로 한 프론트 구현과 백엔드 요청 정리를 선택했다. 기존 화면·라우팅·통계 조회를 재사용하고 미션과 목표 표시를 기능 컴포넌트로 분리한다. 목표는 기존 플래너 API와 캐시를 공유한다. 미션만 새 서버 명세가 필요한 부분으로 분리한다.

검토한 다른 방식은 홈과 플래너가 목표를 별도로 저장하거나 미션을 기기에만 저장하는 것이다. 별도 목표는 같은 날짜의 값을 두 군데에서 맞춰야 하고, 기기 저장만으로는 재설치와 기기 변경 후 유지라는 요구를 충족하지 못한다.

새 의존성이나 전역 상태 관리 도구는 추가하지 않는다. 기존 TanStack Query, 시맨틱 디자인 토큰, UI 프리미티브를 쓴다.

## 코드 기준과 진행 중인 작업

초기 연동은 별도로 커밋된 플래너 릴리즈 준비본 `04b76e15`([PR #487](https://github.com/breathless-youth/frontend/pull/487))을 기반으로 했다. 최신 dev와 통합할 때 후속 플래너·개인 기록 변경을 보존한다. 사용자의 원본 체크아웃과 진행 중인 다른 worktree는 수정하지 않는다.

목표 API 작업 BY-1165는 Jira에서 완료 상태다. 커밋된 플래너 FE의 `plannerApi`, `plannerQueries`, `PlannerGoalResponse`를 재사용했다. 개발 서버 Swagger 대조와 실제 목표 조회·저장 검증을 마쳤으며 운영 배포와 실기기 검증은 별도다.

이전 위키 초안 BY-949의 과목 목록 중심 홈, 05시 기준 홈, 선택 과목 자동 복원 금지 규칙은 이번 결정과 다르다. 새 홈은 이번 문서를 따르고, 기획·서버 명세의 정식 반영은 `.ai` 위키 변경안으로 정리한다.

## 화면과 이동

화면 순서는 D-Day와 날짜, 미션 또는 목표 띠, 오늘 공부시간 카드, 공부 시작 버튼, 플래너 카드, 타임랩스와 방해 앱 잠금 카드다. 연속 공부 카드와 친구 초대 배너는 이 레이아웃에 넣지 않는다. 기존 탭 바를 재사용한다.

- D-Day는 기존 조회·수정·삭제와 미설정 동작을 유지한다.
- 오늘 공부시간의 큰 숫자는 총 공부시간이며 `H:MM:SS` 형식으로 표시한다.
- 아래에는 순공시간과 서버가 계산한 집중률을 표시한다.
- 과목을 바꿔도 오늘 공부시간·순공시간·집중률은 전체 과목 합계다.
- 과목 이름 앞 점은 기존 과목색을 쓰고 시계 캐릭터는 항상 파란색이다.
- 과목 드롭다운에는 `과목 없음`과 `과목 추가` 경로를 둔다.
- 과목 추가와 미션의 이동하기는 플래너의 기존 과목 추가 흐름으로 연결한다.
- 플래너 카드는 홈에서 표시 중인 달력 날짜를 명시해서 연다.
- 남은 할 일 개수는 해당 날짜 플래너 응답을 기준으로 표시한다.
- 타임랩스 왼쪽은 목록, 오른쪽 톱니는 촬영 설정으로 이동한다.
- 타임랩스 개수는 기기 저장소의 실제 개수이며 서버 계정 데이터로 바꾸지 않는다.
- 앱 잠금은 기존 지원 여부·권한·설정 경로를 유지하고 실제 선택 개수를 표시한다.

모바일 셸의 탭바·권한·세션 스택을 웹에서 다시 만들지 않는다. 구 앱과 브라우저 폴백은 기존 규칙을 유지한다.

## 시작 미션

미션은 계정당 한 번 진행하며 날짜가 바뀌어도 초기화하지 않는다. 완료한 단계 수와 현재 단계의 조건 충족 여부를 구분한다. 조건을 채웠다고 자동으로 다음 단계로 넘기지 않는다.

| 상태                  | 링                       | 행동                                      |
| --------------------- | ------------------------ | ----------------------------------------- |
| 과목 만들기 진행      | 0%, 가운데 1/2           | 플래너로 이동한다.                        |
| 과목 만들기 조건 충족 | 0%, 가운데 1/2           | 완료 버튼으로 1단계를 확인한다.           |
| 순공 5분 진행         | 50%, 가운데 2/2          | 선택 과목으로 기존 공부 시작 흐름을 연다. |
| 순공 5분 조건 충족    | 50%, 가운데 2/2          | 완료 버튼으로 2단계를 확인한다.           |
| 미션 완료, 목표 없음  | 100%와 체크              | 목표 설정을 안내한다.                     |
| 미션 완료, 목표 있음  | 오늘 순공 대비 목표 비율 | 목표 진행률과 남은 시간을 표시한다.       |

1단계는 생성 시점이나 생성 화면과 관계없이 활성 과목이 1개 이상이면 조건을 충족한다. 개편 전에 만든 과목도 인정한다. 과목 20개가 이미 있는 계정에 새 과목 생성이나 삭제를 요구하지 않는다. 완료 버튼으로 1단계를 확인한 뒤에는 과목 수가 줄어도 완료를 취소하지 않는다.

최신 BY-1190 및 서버 명세에서 2단계는 `startsOn`(현재 2026-11-07) 이후 한 현지 달력 날짜의 측정 순공 합계 300초로 확정됐다. 같은 날의 여러 세션은 합산하며 서로 다른 날짜는 합산하지 않는다. 서버가 원본 MEASURED 세션의 날짜별 합계 중 최댓값을 `measuredFocusSec`으로 내려준다. 수동 기록은 제외한다. 자정을 걸친 세션은 기존 자정 분할값을 사용한다. 1단계 확인 전에 달성한 날도 인정한다. FE는 시간이나 과목 개수로 조건을 다시 계산하지 않고 `currentStep`과 `eligible`을 사용한다. 초기 문서의 여러 날짜 누적·공개 시각 분할 조건은 이 확정 계약으로 대체한다.

미션 완료 요청은 중복 탭과 여러 기기 재시도에 안전해야 한다. 조건 판단과 저장 결과는 서버가 결정하고, FE는 응답이 성공한 후 다음 단계로 전환한다. 실패하면 현재 단계를 유지하고 다시 시도할 수 있게 한다.

미션 조회 실패를 새 사용자나 완료 상태로 바꾸지 않는다. 홈 통계와 공부 시작은 계속 쓸 수 있고 미션 영역만 재시도를 표시한다.

## 목표와 날짜

목표 단위는 초로 유지하고 UI에서 1,800초씩 조절한다. 빠른 선택은 4·6·8·10시간이다. 홈 시트의 처음 기본 목표 적용 스위치는 시안대로 켜 둔다. 플래너의 기존 시트 기본 스위치 상태를 함께 바꾸지는 않는다.

같은 날짜 목표는 `PlannerGoalResponse`의 `goalSec`, `individualGoalSec`, `defaultGoalSec`를 쓴다. 개별 목표가 있으면 기본 목표보다 우선한다. 기본 목표 변경은 개별 목표를 덮어쓰지 않는다.

`null`은 미설정이고 명시적인 0은 기본 목표를 적용하지 않는 그날의 0시간 목표다. 둘을 저장·조회 단계에서 합치지 않는다. 진행률은 유효 목표가 0보다 클 때만 계산한다. 0시간은 미션 완료 후 목표 설정 안내를 표시하고, 기본 목표로 되돌리거나 0으로 나누지 않는다.

홈은 `localDateKey()`에 해당하는 달력 날짜를 명시해서 플래너 목표를 읽고 쓴다. 예를 들어 11월 7일 01:00에 홈은 11월 7일 목표를 표시한다. 기본 플래너는 여전히 11월 6일을 오늘로 판단하지만, 홈에서 플래너를 열면 11월 7일을 지정한다.

목표 값만 공유한다. 홈 진행률의 분자는 00시 기준 홈 순공시간이고 플래너의 05시 기준 순공시간을 가져오지 않는다. 같은 날짜라도 두 화면의 집계 구간이 다르다는 점은 의도된 동작이다.

홈이 열린 채 자정을 넘기거나 앱 복귀 때 날짜·시간대가 바뀌면 날짜를 다시 계산한다. 이전 날짜 응답을 새 날짜의 오늘 값으로 보여 주지 않는다. 자정을 넘긴 채 열린 목표 시트는 닫고 새 날짜로 다시 조회한다.

진행률은 0~100%로 표시하고 남은 시간은 0 미만으로 내려가지 않는다. 목표를 채우면 오늘 목표를 달성했어요를 표시한다. 숫자는 저장된 통계와 재조회 결과에 맞춰 갱신하며 공부하지 않는 홈에서 시간을 임의로 증가시키지 않는다.

날짜별 목표 저장과 기본 목표 저장은 현재 서로 다른 요청이다. 첫 요청만 성공하고 두 번째가 실패하면 이미 저장된 날짜 목표를 다시 조회하고, 기본 목표 저장 실패를 알린 채 재시도할 수 있게 한다. 전체 저장 성공으로 닫지 않는다.

## 과목 선택과 공부 시작

마지막 홈 선택은 계정별 기기 저장소에 보관한다. 계정 변경 시 다른 계정의 과목을 가져오지 않는다. 사용자가 `과목 없음`을 선택한 것도 보존한다. 선택 과목의 기기 간 동기화는 이번 요구에 포함하지 않는다.

서버 목록 조회에 성공했을 때 선택한 과목이 삭제된 것을 확인하면 과목 선택 상태로 되돌린다. 단순 조회 실패로 저장된 선택을 삭제하지 않는다.

공부 시작은 기존 `useFocusStart`와 `requestSessionStart`에 선택 과목을 전달하도록 확장한다. 처음 세션 가이드를 거쳐도 선택 과목이 유지돼야 한다. 진행 중이던 세션을 복구할 때는 복구 세션의 과목이 우선하며 홈 선택으로 덮어쓰지 않는다.

이미 구현 중인 `initialSubjectId` 전달과 `subjectStart=1` 기능 확인을 재사용한다. 해당 기능이 없는 구 앱에서는 기존 업데이트 안내를 쓰고, 선택한 과목을 잃은 채 과목 없이 시작됐다고 성공 처리하지 않는다.

## 데이터와 팝업 연결

목표 캐시 키는 플래너의 계정·날짜·시간대 키를 공유한다. 목표 변경 후 같은 계정 플래너 쿼리를 무효화하고 기존 `records-changed` 전달을 재사용한다. 화면 복귀와 네이티브 세션 종료 시 기존 통계 재조회도 유지한다.

오늘 공부시간·과목·목표·미션의 로딩과 실패를 분리한다. 목표나 미션 조회 실패 때문에 공부 시작 버튼을 막지 않는다. 저장 중에는 이중 저장을 막고, 조회가 되지 않은 값을 0이나 미설정으로 단정하지 않는다.

진행 중인 플래너 홈 통합의 공지 → 세션 복구 → 미완료 할 일 순서를 유지한다. 자동 안내 중에 목표 시트와 과목 메뉴를 겹쳐 열지 않는다. 시트가 열린 동안 뒤늦은 자동 안내는 대기시키고, 닫힌 뒤 기존 순서를 잇는다. 미완료 할 일의 05시 기준과 선택·재시도 상태도 유지한다.

시작 미션은 자동 팝업을 추가하지 않고 본문의 띠에서만 안내한다.

## 서버 준비 전 구현과 실제 연결

목표는 기존 API를 검증해서 연결한다. 새로운 미션 HTTP 경로나 공유 API 타입은 실제 Swagger가 나오기 전에 만들지 않는다. 미션 표시·상태 전환은 FE 화면 모델과 주입 가능한 데이터 경계로 구현하고 테스트에서 시안 8개 상태를 재현한다.

서버 준비 전에는 개발 환경 미리보기로 검증했다. BE dev 머지 후 실제 API와 기본 gateway를 연결했고 개발 서버의 미션 완료·목표 저장을 확인했다. 새 홈의 운영 공개는 별도 통합·배포 절차를 따른다. 운영에서 가짜 미션 데이터나 기기 저장을 계정 저장의 대체재로 쓰지 않는다.

## 디자인과 검증

기존 Pretendard, `.theme-soft-blue`, 카드 그림자와 반경 토큰을 사용한다. 기본 파란 시계와 노트 PNG는 제공된 480×480 투명 에셋을 사용한다. 색상별 시계 4종은 앱에 추가하지 않는다.

402×874 시안의 8개 상태를 기준으로 비교하고 작은 화면, 태블릿 `page-column`, 라이트·다크, 긴 과목명도 확인한다. 숫자에는 `tabular-nums`를 적용한다. 44px 터치 영역, 접근 가능한 메뉴·시트, 초점 복원, 링 라벨을 확인한다. 600ms 링 전환과 완료 버튼 모션은 reduced-motion 설정에서 멈춘다.

동작 검증은 미션 우선순위, 수동 기록 제외, 자정 변경, 0시간 목표, 저장 일부 실패, 계정별 과목 복원, 첫 세션 가이드와 기존 세션 복구를 다룬다. 스타일 클래스 문자열을 검증하는 테스트는 추가하지 않는다. 기존 네이티브 브리지·홈 팝업 회귀 테스트를 유지한다.

분석 이벤트는 기존 공부 시작·플래너 진입 계측을 유지한다. 새 미션 완료와 목표 저장 이벤트는 위키 명세가 확정된 뒤 실제 성공 시점에 연결한다. 자유 문자열·과목명·카메라 데이터는 이벤트 속성으로 보내지 않는다.

## 빌더에게 맡기는 것

- 컴포넌트와 훅을 나누는 세부 기준은 기존 디렉터리 관례를 따른다.
- 저장소 키의 이름과 UI 전용 상태 이름은 구현자가 정한다.
- 다크 색과 모바일 안전영역은 기존 디자인 토큰과 셸 동작에 맞춘다.
- 0시간 목표 표시, 자정에 시트 닫기, 홈 스위치 초기값과 플래너 스위치 분리는 이 초안에서 제안한 구현 판단이며 설계 검토 때 확인한다.

확정된 API와 개발 서버 검증 결과는 [백엔드 연동 확인](2026-11-07-home-v3-backend-requests.md)에 정리했다.

## 아이패드 반응형 보정

그룹 등 기존 탭과 같은 `page-column` 규칙을 적용했다. 폭600px 이상에서 공통 열은 최대640px이고, 창의 양변이1000px 이상이면720px이다. 안쪽 좌우20px을 제외한 카드 폭은600/680px이다. 폰·분할 창과 높이480px 미만인 가로폰은 기존 배치를 유지했다.

실제 홈은 이미 공통 규칙을 사용했으나 개발 미리보기의 루트 `px-5`가 `page-column`을 덮어 전폭으로 늘어났다. 미리보기의 좌우 여백을 안쪽 wrapper로 변경해 실제 홈과 맞췄다. 사용자 요청에 따라 아이패드 전용 Figma 시안은 추가하지 않았다.

# BY-1246 국가별 API 응답 시간 측정 설계

## 왜

서버는 AWS 서울 리전, TURN은 오사카 한 대에 있다. 첫 해외 시장은 싱가포르·말레이시아(영어)와 대만(번체 중국어)이다.
해외에서 앱이 얼마나 느린지 볼 숫자가 없었다. Sentry는 API 응답 시간을 측정하지만 IP를 보내지 않아 국가를 모른다.

## 목표

- 국가별 API 응답 시간과 TURN 중계 비율을 Amplitude 한 곳에서 본다.

## 하지 않는 것

- 랭킹 시각을 기기 시간으로 바꾸는 일(BY-1248)은 이번에 내지 않는다. 해외 기기는 랭킹 화면이 막혀 있고(`RankingPage`의 시간대 확인), 서버도 다른 시간대 사용자를 한국 랭킹에서 빼서 바꿔도 보이는 곳이 없다. 구현은 로컬 브랜치 `feature/BY-1248-overseas-ranking-local-time`에 커밋 하나로 보관했고, 해외에도 랭킹을 열 때 다시 가져온다.
- 랭킹 탭은 해외에서도 지금처럼 안내 카드를 보여준다. 탭을 숨기려면 네이티브 배포가 필요하다.
- 해외 TURN 추가, 서버 리전 변경, Sentry 시간대 태그.

## API 응답 시간

- `apiFetch`가 API 주소로 보낸 요청의 왕복 시간을 측정한다. 토큰을 기다린 시간은 넣지 않는다.
- 응답이 `ok`인 것만 모은다. 실패·취소·네트워크 오류는 응답 시간이 아니라 오류라 뺀다.
- 요청 도중 화면이 숨겨졌다면 멈춰 있던 시간이 섞이므로 그 요청은 뺀다.
- 페이지가 열린 뒤 최대 10개를 모은다. 10개가 차거나, 첫 표본 뒤 30초가 지나거나, 화면이 숨겨지면 `api_latency_sampled`를 페이지당 한 번 보낸다.
- 속성은 `median_ms`, `max_ms`, `sample_count`뿐이다. 주소·사용자 정보·응답 본문은 넣지 않는다. 국가는 Amplitude가 IP로 붙인다(`trackingOptions.ipAddress: true`).
- Amplitude가 초기화되지 않았으면 보내지 않는다. 앱 안에 분석 동의 설정은 없다.
- Amplitude 모듈은 보낼 때 동적으로 불러온다. 모든 API 호출이 지나는 `api.ts`가 분석 SDK를 끌고 오면 API를 쓰는 테스트가 무거워졌다(플래너 화면 테스트가 5초 제한을 넘었다).
- 탭마다 웹뷰가 따로 열리면 앱 실행 한 번에 여러 번 갈 수 있다. 국가별 중간값을 보는 데는 문제가 없어 그대로 둔다.

## 차트

- TURN 중계 비율은 이미 있는 `peer_connection_established`를 국가별로 나누고 `path = relay` 비율을 본다.
- 응답 시간 차트는 이벤트가 운영에 처음 들어온 뒤 만든다. 들어온 적 없는 이벤트는 차트에서 고를 수 없다.

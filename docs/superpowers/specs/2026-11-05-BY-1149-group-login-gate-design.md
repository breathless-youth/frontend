# BY-1149 그룹 탭 로그인 게이트 설계

- 티켓: BY-1149 (앱 쪽 로그인 요청은 BY-1147)
- 근거: 위키 `product/specs/BY-383-소셜로그인-인증인가.md`(S0 동작), `product/voice-tone.md` 로그인(S0) 문구, 백엔드 `docs/superpowers/specs/2026-11-03-social-login-design.md` 26·27·30·64행, 백엔드 소셜 로그인 ADR
- 작성: 2026-11-05

## 왜

로그인 기능이 들어간 앱에서는 비회원이 그룹 탭을 쓰지 못하고 로그인 화면(S0)을 먼저 봐야 한다. 서버는 비회원의 그룹 요청을 막지 않고, 로그인을 요구하는 판단은 앱이 한다(백엔드 설계서 26·27행). 그룹은 로그인보다 먼저 비회원 상태로 나가고, 로그인은 그 뒤 강제 업데이트와 함께 나간다(64행). 그래서 웹은 앱이 로그인을 할 수 있다고 알린 경우에만 막는다. 화면과 문구는 FE 몫이다(30행).

## 결정

| 항목               | 결정                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| ------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 판정               | `useGroupAccess()`가 `ungated`·`pending`·`member`·`guest` 중 하나를 준다                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| 막지 않는 앱       | `nativeSocialLoginProviders()`가 빈 목록이면 `ungated`다. 옛 앱과 브라우저는 지금처럼 비회원으로 그룹을 쓴다                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| 기다림             | 신원 대기나 프로필 받는 중이면 `pending`이고 아무것도 그리지 않는다. 신원 대기가 끝났는데 신원이 없으면 `ungated`로 통과시켜 그룹 탭의 신원 없음 처리에 맡긴다                                                                                                                                                                                                                                                                                                                                                                                                                                |
| 회원 판정          | 프로필 응답 `loginProvider`가 값이 있으면 `member`, 정확히 `null`이면 `guest`다                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| 필드 없는 서버     | 백엔드 배포 전 서버는 `loginProvider`를 보내지 않는다. 필드가 없으면 `member`처럼 통과시켜 모두가 갇히지 않게 한다                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| 프로필 오류        | 통과시킨다. 서버가 비회원을 막지 않으므로, 판정을 못 해 그룹 탭을 닫는 것보다 여는 쪽이 낫다. 프로필 화면들의 오류 처리와 달리 재시도 화면을 두지 않는다                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| 필드 타입          | 백엔드 Swagger에 아직 없어 `packages/types`에 넣지 않고 `useGroupAccess.ts` 안의 로컬 타입으로 둔다                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| 게이트 배치        | `/social/groups/*`·`/social/public/*` 10개 라우트를 `App.tsx`에서 레이아웃 라우트 `GroupLoginGate` 하나로 묶는다. 그룹 탭(`SocialTabRoute`)과 6자리 초대 참여(`InviteJoinRoute`)는 같은 게이트로 감싼다                                                                                                                                                                                                                                                                                                                                                                                       |
| 막지 않는 곳       | 그룹 표시 없는 예전 소셜 홈, 숫자 4자리 초대 링크 분기, `/blocks`                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| 돌아가기           | 게이트가 그 주소에 로그인 화면을 그리므로 로그인한 뒤 같은 주소가 그대로 그룹 화면을 그린다. 돌아갈 주소를 기억하지 않는다                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| 초대·푸시          | FE 해석으로 초대 링크와 푸시로 연 그룹 화면도 막는다. 비회원이 링크로 들어와도 같은 로그인 화면을 본다                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| 로그인 화면        | 가운데 스플래시 로고(라이트·다크 그림), 아래 Google·Apple·카카오 순서의 버튼 중 앱이 알린 것만, 그 아래 동의 문구와 이용약관·개인정보 처리방침 링크. 동의 문구는 화면 폭과 상관없이 약관 동의 앞에서 줄을 나눈다(문구 안 줄바꿈과 `whitespace-pre-line`). 두 링크는 흐름 안에서 44px 상자로 키워 줄이 나뉘어도 누르는 영역이 겹치지 않는다                                                                                                                                                                                                                                                    |
| 기록 이어가기 안내 | `studyDaysQuery`의 `totalDays > 0`일 때만 보인다. 받는 중이거나 실패하면 보이지 않는다                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| 뒤로 가기          | 탭 첫 화면(`/social`)이 아니면 `ScreenBackHeader`를 둔다. 탭 바가 없는 전체 화면 경로에서도 빠져나갈 수 있다                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| 결과 처리          | 진행 중엔 모든 버튼을 막고, 같은 순간의 두 번째 누름은 ref로 막는다. 화면이 내려간 뒤 온 결과는 버튼 상태와 토스트를 건드리지 않지만 성공 계측은 한다. 성공하면 처음 가입이든 기존 계정이든 어디로도 이동하지 않고, 앱이 모든 조회를 다시 불러와 게이트가 회원으로 바뀌면 그 자리에서 그룹 화면이 보인다. 처음 가입한 사람을 프로필 설정으로 보내라는 BY-383 명세는 2026-11-05 사용자 결정으로 따르지 않는다. 취소는 아무것도 하지 않는다. `ALREADY_LINKED`는 프로필을 다시 받는다. `SOCIAL_PROVIDER_UNAVAILABLE`은 `common:errors.retryLater`, 그 밖의 실패는 `login:errors.failed` 토스트다 |
| 문구               | 새 네임스페이스 `login`(ko·en). 문장은 렌더 때 `t`로 읽는다                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| 계측               | `login_screen_viewed { entry }`, `social_login_succeeded { provider, is_new_user }`, `social_login_failed { provider, reason }`. 실패 속성은 카탈로그 관례에 맞춰 `code` 대신 `reason`이고, 취소는 보내지 않는다                                                                                                                                                                                                                                                                                                                                                                              |
| 브랜드 색          | 버튼 색은 각 회사 지침을 따른 고정값이라 테마 토큰을 쓰지 않고 다크에서도 그대로 둔다. 로고는 Figma 버튼 노드의 벡터를 쓴다                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |

## 약관 링크 누르는 영역 실측

jsdom은 레이아웃을 계산하지 않아 링크 크기를 단위 테스트로 잴 수 없다. 클래스 문자열을 단언하는 테스트는 디자인 규칙(새 테스트는 상태·aria·텍스트만 단언)과 맞지 않아 두지 않고, 브라우저에서 잰 값을 여기에 남긴다.

- 방법: `pnpm --filter web dev`로 띄운 화면을 Playwright 헤드리스 Chromium(뷰포트 402×874)으로 열었다. `window.ReactNativeWebView`를 주입하고 `?groupRooms=1&socialLogin=GOOGLE,KAKAO,APPLE&userId=1`을 붙였다. 프로필 응답은 `loginProvider: null`로 가로챘다. 그런 다음 두 링크의 `boundingBox()`를 읽었다.
- 한국어 `/social`(2026-11-05 줄바꿈 고정 뒤): 이용약관 44×44(x 90, y 704), 개인정보 처리방침 86×44(x 147, y 704). 같은 줄에 있고 겹치지 않는다. 뷰포트 너비 320·375·744에서도 첫 줄은 "로그인하면 만 14세 이상임을 확인하고,", 둘째 줄은 "이용약관과 개인정보 처리방침에 동의하게 돼요" 한 줄이다.
- 영어 `/social`(같은 날): Terms of Service 90×44(x 150, y 704), Privacy Policy 74×44(x 266, y 704). 같은 줄에 있고 겹치지 않는다. 너비 375·744도 두 줄이다. 너비 320에서는 둘째 줄이 길어 Privacy Policy 앞에서 한 번 더 나뉘고, 두 링크는 위아래 줄에서 겹치지 않는다.
- 링크가 든 줄은 44px 높이가 되어 동의 문구의 줄 간격이 그만큼 넓어진다.

## 일부러 하지 않은 것

- 서버에서 비회원의 그룹 요청 막기(백엔드 설계서 27행).
- 로그인 화면을 앱 네이티브로 그리기. 다른 화면처럼 웹이 그린다.
- 로그아웃·탈퇴. 다른 티켓이 다룬다.

## 게이트 연결을 걷어냄

운영 중인 Android 앱 26.45.1이 이미 `groupRooms=1`과 `socialLogin`을 붙여 로그인을 할 수 있다고 알리고 있어서, 게이트가 운영 웹에 나가면 그 앱의 비회원에게 로그인 화면이 바로 열린다. 개인정보처리방침과 스토어 설정이 아직 남아 있고, 게이트를 그룹 탭 전체에 걸지 방 참가처럼 직접 들어오는 곳에만 걸지도 팀이 정하지 않아서 2026-11-06에 `App.tsx`·`SocialTabRoute`·`InviteJoinRoute`의 게이트 연결만 걷어냈다. 로그인 화면, `GroupLoginGate`, `useGroupAccess` 판정 훅, `login` 문구, 계측 이벤트는 유지했고 범위가 정해지면 다시 감싼다.

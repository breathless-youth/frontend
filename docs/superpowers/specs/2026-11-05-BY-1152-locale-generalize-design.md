# BY-1152 다국어 기반 일반화 설계

- 티켓: BY-1152 (후속 BY-1153 웹 일본어·번체 중국어 카탈로그, BY-1154 셸 문구)
- 앞선 설계: [BY-731 국제화 설계](./2026-10-01-BY-731-i18n-design.md)
- 설명 페이지: https://claude.ai/artifact/GSGUyze53AwS2X9VDrQZZk
- 작성: 2026-11-05

## 왜

BY-731은 "한국어가 아니면 영어"라는 두 갈래 규칙으로 언어를 정했다. 일본어와 번체 중국어를 더하려면 이 규칙을 언어 목록에서 고르는 방식으로 바꿔야 한다. 이번 티켓은 규칙과 그 규칙을 쓰는 자리만 바꾸고, 새 언어의 문구는 넣지 않는다. 그래서 한국어·영어 화면의 출력은 그대로다.

## 결정

| 항목               | 결정                                                                                                                                                                                                            |
| ------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 공용 규칙          | `packages/types/src/locale.ts`에 `AppLocale`(`ko`·`en`·`ja`·`zh-Hant`), `APP_LOCALES`, `negotiateLocale(선호 언어 목록, 지원 목록)`을 두고 웹과 셸이 같이 쓴다                                                  |
| 고르는 방법        | 기기 선호 언어 목록을 위에서부터 훑어 지원 목록 안의 첫 언어를 고른다. 맞는 것이 없으면 `en`이다. 대소문자는 무시하고 `_`는 `-`로 본다                                                                          |
| 태그 해석          | `ko*`는 ko, `ja*`는 ja, `en*`는 en이다. `zh`는 문자 체계가 `Hant`면 zh-Hant, `Hans`면 건너뛴다. 문자 체계가 없으면 지역이 TW·HK·MO일 때 zh-Hant이고, CN·SG이거나 지역이 없으면 건너뛴다. 나머지 언어도 건너뛴다 |
| Intl.Locale        | 쓰지 않는다. Hermes에 없어서 태그를 직접 나눈다                                                                                                                                                                 |
| 웹 지원 언어       | `SUPPORTED_LOCALES`는 이번에도 `ko`·`en`이다. ja·zh-Hant는 BY-1153이 카탈로그와 함께 켠다                                                                                                                       |
| 웹 언어 결정       | `?lang`, 지원 목록 안의 저장값, `navigator.languages` 순으로 본다. `navigator.languages`가 비어 있으면 `navigator.language`를 본다. 결과는 늘 지원 목록 안이다                                                  |
| index.html         | 번들보다 먼저 도는 인라인 스크립트에 같은 규칙을 따로 적는다. `indexHtml.test.ts`가 두 구현이 같은지 확인한다                                                                                                   |
| 시각 표기          | 한국어만 24시간제를 직접 지정하고, 나머지 언어는 그 언어의 CLDR 기본값을 따른다. 21:03은 ja `21:03`, zh-Hant `下午9:03`이다                                                                                     |
| 달력               | react-day-picker 로케일을 언어별 표(ko, enUS, ja, zhTW)에서 고르고, 표에 없으면 enUS다                                                                                                                          |
| 추천 과목          | 언어별 목록에서 고르고 목록이 없으면 영어 목록이다. 지금은 ko·en만 있다                                                                                                                                         |
| 카탈로그 검사      | 지원 언어마다 한국어 카탈로그와 비교하고, 복수형 범주는 `Intl.PluralRules`에서 읽는다                                                                                                                           |
| 셸 언어            | `getAppLocale()`이 `getLocales()`의 `languageTag` 목록 전체를 네 언어로 협상한다. 그래서 웹뷰 `?lang`에 ja·zh-Hant가 실릴 수 있다                                                                               |
| 셸 문구            | `copy`는 ko·en만 있고, 다른 언어는 `t()`가 영어 문구를 쓴다. BY-1154가 ja·zh-Hant 객체를 더한다                                                                                                                 |
| Remote Config 문구 | 한국어는 원래 키, 그 밖은 `<key>_en`·`<key>_ja`·`<key>_zh_hant`를 읽는다. 값이 비거나 읽기에 실패하면 그 언어의 기본 문구, 그것도 없으면 영어 기본 문구다                                                       |

## 일부러 그대로 둔 것

`isKoreanLocale`, 약관 화면, 수동 기록 시각, 랭킹 표기, `dateKey.ts`, `graphemes.ts`는 한국어 전용 동작이라 이번에 바꾸지 않았다. 셸의 `auth.ts`·`pushTokenRegistration.ts`·`app.json`·`app.config.ts`는 다른 티켓이 다룬다.

# BY-957 웹뷰 화면에 iOS 26 Liquid Glass 적용 설계

## 배경

iOS 26에서 시스템 Liquid Glass가 그려지는 곳은 하단 탭 바(`NativeTabs`) 하나였다. 뒤로가기, 일간·주간 같은 세그먼트, 스위치, 버튼은 모두 웹뷰 안의 HTML이라 glass를 입을 수 없었다. WebKit의 `-apple-visual-effect`는 비공개 API(`_setUseSystemAppearance`)로만 켜져 App Store 심사 2.5.1에 걸리고, Safari는 굴절 표현에 필요한 `backdrop-filter: url()`을 지원하지 않는다. 그래서 진짜 glass는 네이티브 뷰로만 만들 수 있다고 판단했다.

뒤로가기 헤더(`ScreenBackHeader`)에 `sticky`·`fixed`가 없어서 본문을 스크롤하면 뒤로 버튼이 화면 밖으로 사라지는 문제도 함께 다뤘다.

## 실험 결과

iOS 26.5 시뮬레이터와 iPhone 13 mini(iOS 26)에서 스파이크로 확인했다. 녹화와 캡처는 `reports/by-957/`에 있다.

| 가설                                                                                                                         | 판정 | 근거                                                                                                                               |
| ---------------------------------------------------------------------------------------------------------------------------- | ---- | ---------------------------------------------------------------------------------------------------------------------------------- |
| 떠 있는 층: 웹이 알린 내용을 RN 오버레이(`@expo/ui`)가 화면에 고정해 그리면 웹 콘텐츠가 굴절돼 보이고 누름이 웹으로 전달된다 | 참   | 스크롤 중 본문 글자가 glass 가장자리에서 휘어 보였다. 네이티브에서 웹까지 0에서 2ms가 걸렸다                                       |
| 그 자리 부품: Swift 모듈이 네이티브 컨트롤을 `WKWebView.scrollView` 안에 본문 좌표로 붙이면 스크롤 중 어긋나지 않는다        | 참   | 녹화 프레임에서 웹 글자와의 간격이 214px로 유지됐다. 실기기에서 스위치 2.7에서 3.0ms, 세그먼트 0.1에서 7ms 안에 웹이 누름을 받았다 |
| 단색 배경 위 그 자리 glass는 CSS와 구분하기 어렵다                                                                           | 참   | 멈춘 화면에서는 흰 원과 평범한 세그먼트로 보였다. 다만 사용자는 실기기에서 시스템 부품의 생김새를 가장 선호했다                    |

실험에서 알게 된 함정도 기록한다.

- SwiftUI segmented `Picker`는 평소 트랙이 불투명해서 `glassEffect`로 감싸야 아래가 비친다.
- `react-native-webview`의 ref는 명령형 핸들이라 `findNodeHandle`이 실패해서, 감싼 `View`의 태그로 찾고 Swift가 그 아래의 `WKWebView`를 찾는다.
- JS 숫자는 Swift 딕셔너리에서 `Int`로 바로 캐스팅되지 않아 `NSNumber`로 받는다.
- 시뮬레이터의 합성 터치는 스크롤뷰 안 `UISwitch`에 전달되지 않았지만 실기기에서는 동작했다.

## 결정

화면에 고정돼야 하는 요소는 떠 있는 층으로, 본문에 있는 요소는 그 자리 부품으로 바꾼다. 기록·랭킹 탭 위에 새 고정 바는 만들지 않는다. 하단 CTA와 기간 이동 줄은 실기기 검토 뒤 사용자 결정으로 기존 웹 디자인을 유지하고, 경위는 아래 "실기기 검토 뒤 바뀐 것"에 있다.

### 떠 있는 층 (`@expo/ui`)

| 대상            | 화면                                                                                                                                                               | 모습                                                                                    |
| --------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------- |
| 뒤로가기와 제목 | 이용약관, 개인정보처리방침, 오픈소스 라이선스, 문의하기, 인터뷰 신청, 프로필, 초대코드 입력, 수동 기록, 랭킹 기록, 타임랩스 설정, 타임랩스 목록, 방해 앱 잠금 설정 | 왼쪽 위 glass 원형 뒤로 버튼, 가운데 정렬 제목, 아래로 흐림                             |
| 뒤로가기        | 플래너                                                                                                                                                             | 왼쪽 위 glass 원형 뒤로 버튼. 가운데 날짜 이동 줄은 웹의 `PeriodNav`가 같은 줄에 그린다 |
| 닫기            | 초대코드 공유                                                                                                                                                      | 뒤로 버튼과 같은 자리·모양에 X 아이콘                                                   |

하단 CTA는 떠 있는 층에 넣지 않고 모든 화면에서 기존 웹 버튼으로 그린다.

뒤로가기 줄의 배치 값은 다음과 같다.

- 뒤로 버튼은 왼쪽에서 20px 떨어진다(본문 `px-5`와 같은 선).
- 뒤로 버튼은 44px glass 원이고 아이콘은 20px이다.
- 제목은 화면 가운데에 정렬하고, 버튼과 최소 12px 떨어진다.
- 오른쪽에 버튼과 같은 폭의 빈자리를 두어 제목이 정확히 가운데에 온다.
- 제목이 길면 양쪽 버튼 폭만큼 비우고 말줄임으로 자른다.

### 그 자리 부품 (로컬 Swift 모듈 `web-glass`)

| 대상                  | 화면                                                                                                 | 네이티브 부품                                                                                                                      |
| --------------------- | ---------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| 세그먼트              | 기록 일간·주간, 랭킹 종목, 랭킹 일간·주간·월간, 타임랩스 세로 9:16·가로 16:9, 랭킹 기록 화면 순위 칩 | `UISegmentedControl`. 비활성 항목도 반영한다                                                                                       |
| 스위치                | 타임랩스 설정, 방해 앱 잠금                                                                          | `UISwitch`. 켜짐 색은 브랜드색이다                                                                                                 |
| 카메라 권한 표시 토글 | 설정 탭                                                                                              | `UISwitch` 모양만 보이고 누름은 받지 않으며 VoiceOver에서도 빠진다. 웹 자리 끝 쪽에 맞추고, 행을 누르면 지금처럼 iOS 설정이 열린다 |
| 플래너 버튼           | 홈, 기록                                                                                             | 44pt glass 원형 `UIButton`. 웹 `IconPlanner`를 렌더한 템플릿 PNG를 `image`로 그린다                                                |
| 메달 버튼             | 랭킹                                                                                                 | glass `UIButton`. 메달 그림은 SF Symbol로 바꾸고 화살표는 삭제한다                                                                 |
| 길이 칩               | 수동 기록                                                                                            | glass 캡슐 `UIButton`. `disabled`로 막힌 상태를 흐리게 보인다                                                                      |

네이티브 부품은 크기가 작아도 가운데 기준 44pt 안의 누름을 받는다.

### 모든 기기에 적용하는 레이아웃 변경

- 홈과 기록 탭 플래너 버튼을 글자 없는 44px 원형 아이콘 버튼으로 바꾼다.
- 기록 탭의 `기록` 제목은 유지한다.
- 메달 버튼의 화살표를 삭제한다.
- 랭킹 종목 칩을 기간과 같은 세그먼트(`SegmentedControl`)로 바꾸고, 웹 대체 화면도 같은 세그먼트를 쓴다.
- 뒤로가기와 제목을 위쪽에 고정한다.
- 이용약관, 개인정보처리방침, 오픈소스 라이선스는 본문 첫 줄의 큰 제목 대신 위쪽 줄 제목을 쓴다.
- 초대코드 입력 화면은 위쪽 줄 제목을 `초대코드로 참여`로 두고 본문 제목을 `h2`로 낮춘다.

### 범위 밖

- 프로필 카테고리 칩, `랭킹 / 명예의 전당` 큰 글자 탭은 단색 배경 위라 바꾸지 않는다.
- 시트 안쪽처럼 따로 스크롤되는 영역 속 컨트롤은 그 자리 부품이 따라갈 수 없어 제외한다(랭킹 기록 시트의 순위 칩이 여기에 해당한다).
- 하단 CTA, 기록 탭의 달·주 이동 줄, 플래너의 날짜 이동 줄은 기존 웹 모양을 유지한다.
- 결과 화면의 인터뷰 안내 카드 X와 타임랩스 카드의 재생·일시정지 버튼도 기존 웹 버튼을 유지한다.
- 세션 화면 컨트롤, 유리 메뉴(랭킹 기록 필터, 플래너 과목 메뉴), 시트·대화상자의 시스템 전환은 후속 티켓으로 분리한다.

### 지원 표시

- 앱은 `glassChrome=<버전>`과 `glassControls=<종류 목록>`을 함께 붙이고, 지금 값은 `glassChrome=1`, `glassControls=segment,switch,button`이다.
- 웹은 알린 버전이 그릴 수 있는 고정 요소 모양과 목록에 있는 본문 부품 종류만 앱에 맡기고, 나머지는 CSS나 웹 원본으로 그린다.
- 원격 웹은 구버전 앱에도 바로 배포되므로, 앱이 모르는 것을 보내면 웹 원본은 숨었는데 앱은 메시지를 버려서 화면에서 사라진다.
- 앱 파서는 모르는 본문 부품 종류를 만나면 그 부품만 빼고 나머지를 그린다.
- `web-glass`에 새로 더한 네이티브 함수는 래퍼가 `?.`로 불러서, 그 함수가 없는 이전 Dev Client에서는 아무 일도 하지 않는다.
- 개발 빌드는 `apps/mobile/.env.local`에 `GLASS_CHROME_OFF=1`을 두면 두 표시를 붙이지 않아 같은 기기에서 CSS 대체 화면을 볼 수 있다.
- production과 staging 빌드는 `GLASS_CHROME_OFF`를 무시한다.

### 숨김 규칙

- 웹 시트나 대화상자가 열려 있으면(`useModalOverlayOpen()`) 두 층을 모두 숨긴다(네이티브 뷰는 항상 웹보다 위에 그려진다).
- 페이지 전환 애니메이션 중에는 그 자리 부품을 숨겼다가 전환이 끝나면 다시 보인다.

### 뒤로 가기 스와이프

WKWebView의 가장자리 스와이프는 이전 페이지 스냅샷을 웹뷰 안에서 밀어 넣는다. 떠 있는 층은 웹뷰 밖에 있어 함께 밀려나지 않으므로, 따로 처리하지 않으면 이전 화면 위에 지금 화면의 뒤로 버튼과 제목이 남는다. 그래서 iOS 내비게이션 바처럼 진행만큼 층을 흐리게 했다. 층을 스와이프와 함께 밀어내는 방식 대신 흐려지는 방식을 쓰는 것은 실기기 검토 뒤 사용자가 정했다.

- `web-glass`가 웹뷰의 뒤로 가기 쪽 가장자리 인식기에 대상을 붙여 `began`·`changed`·`ended`·`cancelled`와 진행률(이동 거리를 웹뷰 폭으로 나눈 값)을 알린다.
- 호스트는 진행하는 동안 층의 투명도를 `1 - 진행률`로 맞춘다.
- 손을 뗀 뒤 이동할지는 WebKit이 정하고 알려 주지 않는다.
- 손을 뗀 뒤 350ms 안에 이동(iOS 로드 시작, `backforward` 로드 끝)이 오면 새 화면이 `set-glass-chrome`을 보낼 때까지 층을 내리고, 오지 않으면 취소로 보고 다시 보인다.
- 이동한 뒤 1초 안에 새 화면이 알리지 않으면 고정 요소가 같은 화면으로 보고 이전 층을 다시 보인다.
- 다시 보일 때는 200ms 동안 서서히 나타나고, 모션 줄이기가 켜져 있으면 바로 보인다.
- 본문의 그 자리 부품은 스크롤뷰 안에 있어 스냅샷과 함께 움직이므로 따로 처리하지 않는다.

### 접근성

- 앱 모드에서 웹 원본은 보이지 않게 하고 스크린리더에서도 뺀다.
- 네이티브 부품에는 웹 원본의 `aria-label`이나 연결된 라벨 글자를 넘긴다.
- 모양만 보이는 카메라 권한 토글은 VoiceOver에서 빠지고 아래 웹 행이 읽힌다.
- 제목에는 header 속성을 준다.
- 누름 영역은 44px 이상을 유지하고, 네이티브 부품은 크기가 작아도 가운데 기준 44pt 안의 누름을 받는다.

## 대체 동작

| 환경                                      | 고정 요소                     | 본문 요소         |
| ----------------------------------------- | ----------------------------- | ----------------- |
| iOS 26 이상 앱                            | 네이티브 glass                | 네이티브 부품     |
| Android, iOS 26 미만, 구버전 앱, 브라우저 | 같은 자리에 CSS glass로 고정  | 지금 웹 모양 유지 |
| 개발 빌드의 `GLASS_CHROME_OFF=1`          | 같은 자리에 CSS glass로 고정  | 지금 웹 모양 유지 |
| iOS 투명도 줄이기                         | 시스템이 불투명하게 바꾼다    | 시스템이 처리한다 |
| `prefers-reduced-transparency`            | CSS 대체가 불투명 배경을 쓴다 | 해당 없음         |

위쪽 가장자리 흐림은 두 모드 모두 웹 CSS가 그린다. 테마 색을 그대로 따르고 iOS와 Android가 같은 모양이 된다.

## 오류와 경계 상황

- 모듈이 없는 구버전 Dev Client에서는 `glassChrome`이 붙지 않아 웹이 CSS로 그린다.
- 스와이프 관찰 함수가 생기기 전에 만든 Dev Client에서는 층이 흐려지지 않을 뿐 나머지는 그대로 동작한다.
- 자르는 선 함수가 생기기 전에 만든 Dev Client에서는 본문 부품이 위쪽 줄 밑에서 잘리지 않을 뿐 나머지는 그대로 동작한다.
- 형식이 잘못된 메시지는 기존 브리지와 같이 버린다.
- 앱보다 새 웹이 보낸 모르는 본문 부품 종류는 그 부품만 빼고 나머지를 그린다.
- 이미 사라진 항목의 누름은 무시한다.
- 웹뷰를 다시 띄울 때(재시도, 렌더러 사망 복구) 로드를 시작하면서 그 자리 부품을 모두 비우고, 웹이 로드 후 다시 등록한다.
- 네이티브 부품은 시스템 테마를 따르고 브랜드색은 디자인 토큰의 라이트·다크 값을 쓴다.
- 모션 줄이기가 켜져 있으면 숨김·표시 애니메이션을 쓰지 않는다.

## 알려진 한계

- 그 자리 부품은 웹 요소보다 늘 위에 그려져서, 앱은 위쪽 고정 줄 아래 끝에서 부품 층을 잘라 줄 위로 올라간 부품을 그리지도 누르지도 않는다.
- 다른 `fixed`·`sticky` 웹 줄은 자르지 않아서, 그 줄 아래로 스크롤되면 줄 위에 겹친다.
- 화면 높이가 짧은 기기에서 수동 기록 길이 칩이 아래쪽에 붙은 저장 줄 밑으로 스크롤되면 이 겹침이 생기며, 드물게 일어난다.

## 실기기 검토 뒤 바뀐 것

처음 구현은 하단 CTA, 기간 이동 줄, 결과 화면의 버튼 일부까지 네이티브로 그렸다. 실기기에서 써 본 뒤 사용자가 CTA와 기간 이동 줄은 기존 웹 디자인을 유지하기로 정해서 아래 항목을 되돌렸다.

- 수동 기록, 프로필, 초대코드 공유·입력, 결과 화면의 하단 CTA를 떠 있는 층에 그리던 경로를 삭제하고 모두 기존 웹 버튼으로 되돌렸다.
- 키보드가 열리면 하단 CTA를 숨기던 처리도 이 경로와 함께 삭제했다.
- 플래너 위쪽 줄의 네이티브 날짜 캡슐을 삭제하고, 웹의 `PeriodNav`를 위쪽 고정 줄 가운데에 그리게 했다.
- 기록 탭의 달·주 이동 줄을 그리던 그 자리 부품 종류 `period`를 삭제하고 기존 웹 모양으로 되돌렸다.
- 결과 화면의 인터뷰 안내 카드 X와 타임랩스 카드의 재생·일시정지 버튼을 기존 웹 버튼으로 되돌렸다.
- 결과 화면에 네이티브 부품이 남지 않아서, 페이지 스크롤로 바꿨던 구조를 안쪽 스크롤 상자와 아래에 고정한 웹 CTA를 쓰는 dev 브랜치 구조로 되돌렸다.

# SCR-S3-5 · S3-6 세션 — 가로(거치) 프리뷰 / 가로 심플

## Purpose

거치대에 기기를 눕혀 놓고 공부하는 사용자를 위한 세션 화면의 **가로 레이아웃**이다. S3-5는 S3-1(프리뷰)의 가로 배치, S3-6은 S3-4(심플 모드)의 가로 배치다.

**이 문서는 새로운 세션 상태를 정의하지 않는다.** 세션 상태 모델(집중·비집중·일시정지), 타이머 계산 규칙, 데이터 계약, 문구, 종료 플로우는 전부 세로 스펙과 동일하며 아래 두 문서를 단일 출처로 참조한다. 이 문서는 **가로에서만 달라지는 레이아웃·크기·요소 노출 차이**만 기록한다.

- 프리뷰·비집중: `frontend/docs/screens/SCR-S3-1-S3-2-session-preview-unfocused.md` (WG1)
- 일시정지·심플 모드: `frontend/docs/screens/SCR-S3-3-S3-4-session-paused-simple.md` (WG2)

> 위 두 문서는 이 문서와 병렬로 작성 중이다. 빌더는 **WG1·WG2 스펙을 먼저 읽고** 이 문서를 델타(diff)로 적용한다.

## Ownership Boundary

- 이 화면은 `apps/web`의 세션 화면 트리(`RoomPage.tsx` + `src/features/study-session/**`)에 **가로 브레이크포인트만 추가**한다. 새 라우트·새 페이지를 만들지 않는다.
- 카메라 캡처·Vision 추론·LiveKit은 이 화면의 책임이 아니다(어댑터 계층 경계 — `frontend/CLAUDE.md`).
- **기기 회전 허용 여부는 `apps/mobile`(네이티브 셸)의 책임이다** — 아래 "Current Limitations"의 P0 항목 참조. 웹은 뷰포트가 가로가 되었을 때 올바르게 그리는 것까지만 담당하고, WebView에 회전을 강제하는 네이티브 설정을 이 화면에서 건드리지 않는다.
- V1.0은 **싱글룸만** 존재한다. 이 화면에 멀티룸 참가자 그리드·LiveKit 관련 UI를 넣지 않는다.

## Data Contract

**가로 모드는 새로운 서버 데이터를 만들지 않는다.** `orientation`은 순수 클라이언트 뷰 상태이며 서버로 전송되지 않는다.

세션 제출 계약은 세로와 동일하게 `packages/types`의 기존 타입을 그대로 쓴다(상상 계약 금지):

- `StudySessionCreateRequest` — `userId` / `startedAt` / `endedAt` / `studySec` / `focusSec` / `events`
- `StatusEventPayload` · `StudyEventStatus` = `"PHONE" | "DEVICE" | "AWAY" | "PAUSE"`
- `StudySessionResponse` — 제출 응답(자정 KST 분할 시 배열)

가로 레이아웃이 참조하는 뷰 모델은 WG1/WG2가 정의하는 세션 프레젠테이션 상태를 **그대로 재사용**한다. 가로용 별도 상태 타입을 새로 만들지 않는다. 이 화면이 추가로 갖는 뷰 상태는 다음 하나뿐이다.

```ts
// 클라이언트 전용 뷰 상태 — 서버 계약 아님, packages/types에 넣지 않는다
type SessionOrientation = "portrait" | "landscape";
```

`useStudyRoomSession`(`apps/web/src/features/study-session/useStudyRoomSession.ts`)은 방향과 무관하다 — 훅에 orientation을 넣지 않는다. 방향 판정은 프레젠테이션 레이어(CSS 미디어쿼리 또는 뷰포트 훅)에서만 한다.

**백엔드 계약 미확인 — 상상 계약 금지**: 없음(이 화면은 새 필드를 요구하지 않는다).

## Interaction Contract

### 가로 진입/이탈 트리거 — **명시적 정책 없음**

`.ai` 전체를 검색한 결과 회전 감지·방향 전환 트리거에 대한 정책 서술은 존재하지 않는다. 확인된 기술은 다음 세 곳뿐이며 전부 "가로 레이아웃이 있다"는 사실 서술이다.

- `mvp-scope.md`: "**가로(거치) 모드** 지원 (프리뷰·심플 모두)"
- `design.md`: "프리뷰: 상태 필 상단 중앙 + 순공 타이머 우상단(35px, 총 병기) + 바 하단. 심플: 84px 발광 타이머 중앙. 규칙 동일"
- `user-flow.md`: "거치 사용. … 규칙은 세로와 동일"

→ **표준 CSS 미디어쿼리 / `orientation` 감지로 처리하고, 명시적 트리거 정책은 없는 것으로 기록한다.** 구현은 `@media (orientation: landscape)` 또는 뷰포트 종횡비 기준으로 하고, 방향 잠금 버튼·수동 토글 UI를 임의로 만들지 않는다(디자인에 그런 컨트롤이 없다).

### 미정 — 리더/사용자 확인 필요

- **화면 꺼짐·백그라운드 복귀 시 재개 방식(자동 재개 vs 수동 재개)**: `design.md` 백로그 6번 · `mvp-scope.md` 미확정 항목 · 6차 인터뷰 "보류"에 **"구현 시 결정, 임의 확정 금지"**로 명시돼 있다. 빌더는 **인터페이스만 만들고 동작은 `TODO`로 남긴다** — 기본값을 자동/수동 어느 쪽으로도 확정하지 않는다. (가로 고유 사안은 아니며 WG2와 동일한 지시다.)

## Implementation Notes For AI Agents

1. **선행 조건**: WG1(`SCR-S3-1-S3-2-session-preview-unfocused.md`)·WG2(`SCR-S3-3-S3-4-session-paused-simple.md`) 스펙과 그 구현이 먼저다. 가로는 그 위에 얹는 브레이크포인트다 — **가로를 먼저 구현하지 않는다.**
2. 구현 대상은 `apps/web/src/routes/RoomPage.tsx`와 `apps/web/src/features/study-session/**` **하나의 트리**다. 가로용 새 라우트·새 페이지를 만들지 않는다.
3. `useStudyRoomSession`의 타이머·제출 로직을 버리지 않는다(`RoomPage.tsx`에 "디자인 확정 시 이 파일만 새 화면으로 교체한다"는 주석이 있고 로직은 훅에 분리돼 있다). 훅은 방향을 모르는 상태로 유지한다.
4. Figma 절대좌표(`left/top`)를 그대로 베끼지 않는다. 다음 **관계**만 보존한다.
   - 상태 필: 상단 **중앙**(874 기준 중심 x=437 = 화면 중앙)
   - 프리뷰 타이머·총 병기: **우측 정렬**, 우측 여백 28px, 상단 여백 20px
   - 프라이버시 캡션: **중앙**, 컨트롤 바 바로 위(간격 21px)
   - 컨트롤 바: **하단 중앙**, 하단 여백 14px(바 하단 388 / 프레임 402)
   - 심플 타이머: **중앙**(수직으로는 정중앙보다 약간 위 — 타이머 블록 중심 y≈160 / 402)
5. `stripe`·`[ 전면 카메라 프리뷰 · 가로 ]` 라벨·`dynamic-island` rect는 **목업이므로 구현하지 않는다.** 실제 카메라 피드 영역이다.
6. 가로에서 iOS 상태바를 그리지 않는다(Figma가 의도적으로 뺐고, 실기기 OS 크롬이 담당한다). 안전 영역은 `env(safe-area-inset-*)`로 처리한다 — 가로에서는 좌우 인셋이 커진다(노치 쪽).
7. 컨트롤 바 버튼이 가로에서 44px로 줄어든다 — **44px 미만으로 더 줄이지 않는다**(접근성 최소치).
8. 아이콘(`icon/pause`·`icon/camera-flip`·`icon/exit`)은 세로 구현에서 만든 것을 그대로 쓴다. 새로 그리지 않는다.
9. 심플 모드 토글은 컨트롤 바 영역을 **제외한** 화면 탭이다 — 가로에서도 동일. 컨트롤 바 히트 영역이 탭 토글을 삼키지 않게 한다.
10. V1.2+ 범위(S0 로그인, S7~S11 소셜/멀티룸)를 이 화면에 넣지 않는다.
11. **[WG4 인계 · 필독] S3-7 종료 확인 다이얼로그와 S3-8 자동 종료 안내는 세션 레이아웃 컨테이너(`RoomPage.tsx`의 `SESSION_LAYER_LAYOUT` div)의 자식이 아니라 형제로 넣고 `pointer-events-auto`를 직접 준다.** 자식으로 넣으면 세 가지가 동시에 깨진다(qa-WG3가 프로브를 삽입해 실측 재현):
    1. 가로에서 그리드 자동 배치로 row1/col1(좌상단)에 앉아 중앙 모달이 구석에 그려진다
    2. row1 트랙이 커지면서 `1fr`인 row2가 줄어 심플 타이머(S3-6)의 수직 위치가 밀린다
    3. 레이어의 `pointer-events-none`을 상속해 확인·취소 버튼이 클릭을 받지 못한다

    세로에서도 같은 컨테이너가 `flex-col`이라 흐름 자식이 되어 컨트롤 바를 밀어낸다 — **가로 전용 문제가 아니다.** 전체화면 오버레이는 `main` 바로 아래 `absolute inset-0`이 맞다. 같은 내용이 `RoomPage.tsx`의 `handleRequestExit` 주석에도 있으나, 스펙을 코드보다 먼저 읽을 WG4 빌더를 위해 양쪽에 남긴다.

## Accessibility Requirements

- 컨트롤 바 버튼 터치 타겟: 가로에서 44×44px — **최소치 정확히 충족**. 시각 크기를 줄이더라도 히트 영역은 44px 이상 유지한다.
- 상태는 **색 단독으로 전달하지 않는다** — 상태 필은 항상 `점 + 텍스트` 조합이다(`design.md` 상태 컬러 보조 규칙 ①). 가로에서 공간이 좁다는 이유로 상태 필 텍스트를 지우지 않는다.
- 타이머는 `tabular-nums`로 렌더해 자릿수 흔들림을 막는다(voice-tone §2).
- 가로 프리뷰 타이머 35px / 총 병기 13px / 캡션 11px는 세로보다 작다 — 폰트 확대(브라우저 zoom, iOS Dynamic Type) 시 우상단 타이머와 상태 필이 겹치지 않도록 상단 영역을 flex로 배치하고 고정 좌표를 쓰지 않는다.
- 상태 변화(집중→비집중→일시정지)는 스크린리더에 알린다 — 상태 필에 `aria-live="polite"`. 단 **비집중 해제 시에는 문구 없이 색만 복귀**한다는 규칙(voice-tone §3)에 맞춰 해제 알림을 남발하지 않는다.
- 심플 모드 타이머 글로우는 장식이다 — 대비는 글로우가 아니라 `#4593FC` 텍스트 자체로 확보한다.
- 화면 회전 시 포커스가 사라지지 않게 한다(레이아웃만 바뀌고 DOM 트리는 유지되도록 구현).

## Current Limitations

1. **[P0 · 에스컬레이션] 현재 모바일 셸에서는 이 화면에 도달할 수 없다 — 설정 한 줄이 아니라 3단 결정이다.** (2026-07-26 qa-WG3 지적으로 원인 서술 보강. 아래 세 항목을 직접 확인했다.) 차단 요인이 **이 순서로** 존재한다.
   1. **WebView 라우트 자체가 없다.** `apps/mobile/app/_layout.tsx`에서 구 `room/[id]` 등록을 2026-07-25 기능 리셋 때 제거했고 아직 복구하지 않았다 — 해당 파일 주석에 "스터디룸은 WG 계열(apps/web) 완료 후 WebView 라우트로 다시 등록한다(ADR 0001)"로 명시돼 있다. **회전을 지금 풀어도 이 화면으로 가는 경로가 없다.**
   2. **앱 전체가 세로 고정이다.** `apps/mobile/app.json`의 `"orientation": "portrait"` — ①이 해결된 다음 단계의 차단 요인이다. 인과 자체는 정확하다.
   3. **"세션 화면에 한해 회전 허용"은 `app.json` 한 줄로 되지 않는다.** `orientation`은 앱 전역 설정이라 화면 단위 제어에는 `expo-screen-orientation`이 필요한데 `apps/mobile/package.json`에 **없다**(현재 expo 계열 의존성은 `expo`·`expo-router`·`expo-secure-store`뿐). **새 네이티브 의존성 추가는 리더 승인 사항**이다 — 선례: `apps/mobile/lib/cameraPermission.ts`가 카메라 권한 모듈을 같은 이유로 mock + TODO로 두고 "새 의존성 추가는 리더 승인 후"라고 명시하고 있다.

   → 결정 순서는 **① WebView 라우트 복구 → ② 회전 정책 결정(전역 허용 vs 세션 한정) → ③ 세션 한정이면 새 네이티브 의존성 승인**이다. 결정 주체는 리더 + `mobile-screen-builder`이며, 웹 스펙 작성자·웹 빌더가 임의로 정하지 않는다. 이 결정 전까지 S3-5/S3-6은 **브라우저에서만 검증 가능**하다.

2. **[불일치] 가로 심플 타이머 크기**: `.ai/product/design.md`는 "심플: **84px** 발광 타이머 중앙"이라고 적었으나, Figma `61:531`의 실측값은 **56px**(line-height 64)다. 56px는 `typography.display.lg`와 정확히 일치해 토큰 체계와도 맞는다. **둘 다 병기하고 "확인 필요"로 남긴다** — 임의로 하나를 고르지 않는다. 빌더는 **일단 Figma 실측 56px로 구현**하고(토큰과 일치하므로), 디자이너 확인 후 84px로 확정되면 교체한다.
3. **[미설계] 가로 비집중·일시정지 프레임이 Figma에 없다.** 집중 상태만 그려져 있다. wiki의 "규칙은 세로와 동일"에 근거해 세로 규칙을 적용하되, 서브 문구·캡션의 가로 배치는 확정 디자인이 아니다.
4. **[불일치] 심플 모드 배경색이 세로/가로에서 다르다**: S3-4 세로 `#0B0F14`, S3-6 가로 `#0A0F18`. 둘 다 토큰 미바인딩 하드코딩이며 의도된 차이인지 불명확하다. 구현은 **하나로 통일**하고(가로/세로에서 배경이 바뀌면 회전 시 깜빡임처럼 보인다) 어느 값으로 통일할지 확인받는다.
5. **[Figma 정리 필요] 가로 프레임이 공용 컴포넌트를 쓰지 않는다.** 컨트롤 바·카메라 프리뷰 배경·상태바·홈 인디케이터가 전부 로컬 프레임/원시 도형으로 복제돼 있다. Figma를 고치면 컴포넌트 변경이 가로에도 전파되므로 유지보수에 유리하다.
6. **[프로토타입 미커버] 가로 프레임에는 프로토타입 핫스팟(`hs/*`)이 없다.** `design.md`가 말하는 "인터랙션 39개"는 세로 플로우만 연결한다 — 가로 전환·가로에서의 종료 플로우는 프로토타입으로 검증되지 않았다.
7. **폰트**: Figma는 Pretendard 미설치로 **Inter 임시 적용** 중이다(`design.md`). 실측 타이포는 Inter 기준 값이며, Pretendard 교체 시 재검증이 필요하다.
8. **Vision 미연동**: 현재 `useStudyRoomSession`은 `studySec = focusSec`, `events = []`로 제출한다. 비집중·일시정지 상태는 아직 실제 데이터가 없어 가로에서도 **집중 상태만** 실동작으로 확인 가능하다.
9. **[정책 공백] 데스크톱 뷰포트가 폰 거치 레이아웃을 그대로 받는다.** (2026-07-26 qa-WG3 실측: 1440×900에서 확인.) 이 화면의 가로 판정은 `@media (orientation: landscape)` 하나뿐이라 **데스크톱 브라우저도 전부 "가로"로 판정**된다 — 218×68 축소 컨트롤 바, 우상단 35px 타이머, 11px 캡션이 1440px 폭에 흩어진다.
   - **스펙 위반도 구현 결함도 아니다.** Interaction Contract가 `orientation` 감지를 지시했고 구현은 그대로 따랐다. 레이아웃이 깨지지도 않는다(문구 오류·정보 잘림·도달 불가 요소 없음). 심각도 낮음.
   - 문제는 **정책이 없다는 것**이다. S3-5/S3-6은 Figma상 **874×402 폰 거치 전용 프레임**이고, 데스크톱 프레임은 Figma에 없으며 `.ai`에도 데스크톱 세션 화면 정책이 없다. 반면 `apps/web/CLAUDE.md`는 이 앱을 "독립 브라우저 서비스로도 배포 가능"으로 규정한다 — 그래서 도달 가능한 뷰포트인데 디자인이 없는 구간이 생긴다.
   - 이 문서는 이미 가로 판정을 "`@media (orientation: landscape)` **또는 뷰포트 종횡비 기준**"으로 열어 뒀으므로, 가로 조건에 **뷰포트 높이 상한을 함께 걸어** 폰 거치에 한정하는 선택지가 존재한다. **다만 이는 디자인 결정이므로 여기서 확정하지 않는다** — Review Checklist 항목으로만 올린다.
   - **WG5(S4 공부 결과)가 같은 판정 패턴을 상속하기 전에 결론이 나야 한다.**

### 결정 1 — 가로 심플 타이머는 **56px**

Figma 실측 `61:531`(56/64/bold)이 `typography.display.lg`와 정확히 일치하므로 토큰 체계와 맞는 쪽을 택했다. `design.md`의 84px은 채택하지 않았다. 84px으로 확정되면 `SessionTimer.tsx`의 `landscape:text-[56px] landscape:leading-[64px]` 한 줄만 고친다. (Review Checklist 2번은 여전히 열려 있다.)

### 결정 2 — 심플 배경은 **세로 값 `#0B0F14`로 통일**

Current Limitations 4의 세로/가로 불일치(`#0B0F14` vs `#0A0F18`)는 **이미 코드에 있는 세로 값을 양쪽에 재사용**하는 것으로 처리했다. 방향에 따라 전면 배경색이 바뀌면 기기를 돌릴 때 화면이 깜빡이는 것처럼 보이기 때문이다 — 회전은 레이아웃만 바꿔야 한다. 임의로 새 값을 만들지 않았다. 고칠 위치: `sessionTheme.ts`의 `--session-simple-base`.

### 결정 3 — 가로 비집중·일시정지(Figma 미설계)는 **세로와 같은 상대 위치**

Current Limitations 3에 따라 가장 보수적인 배치를 썼다. 새 배치를 발명하지 않았다.

- 비집중·일시정지 **서브 문구**: 세로와 같이 상태 필 바로 아래(`SessionStatusPill` 내부 구조 그대로, gap 8px).
- **일시정지 캡션**: 세로와 같이 프라이버시 캡션과 **같은 슬롯**(컨트롤 바 바로 위 중앙). 두 줄을 동시에 띄우지 않는 규칙도 그대로다.
- 상태 필과 우상단 타이머는 **서로 다른 그리드 열**에 있어 서브 문구가 길어져도 겹치지 않는다(헤드리스 874×402 렌더로 확인).

### 결정 4 — 컨트롤 바는 **하나의 컴포넌트 + `size` prop**

Figma가 가로에서 `Session / Control Bar` 인스턴스 대신 로컬 프레임을 복제해 뒀지만(Review Checklist 5번), 버튼 구성·순서·색·동작이 같으므로 코드에서는 통합했다. 치수를 컴포넌트 안에 하드코딩하지 않고 prop으로 열었다.

- `size="md"` — 세로 244×80 · 버튼 50 · gap 22 · 핸들 36×4 · 배경 55% · px24/pt16/pb12
- `size="sm"` — 가로 218×68 · 버튼 44 · gap 20 · 핸들 28×3 · 배경 62% · px22/pt13/pb9
- `size="responsive"`(기본) — 위 둘을 하나의 DOM에 얹고 `@media (orientation: landscape)`로 전환

아이콘도 버튼과 같은 비율(44/50 = 0.88)로 줄어든다 — Figma 가로 실측(pause 14×15.8 · flip 18 · exit 17)이 정확히 그 비율이다. 버튼은 가로에서 44px로 **접근성 최소치를 정확히 충족**하며 이보다 더 줄이지 않는다.

**컨트롤 바 배경 알파(55% → 62%)는 통일하지 않았다.** 이 차이는 Current Limitations가 아니라 위 델타 표에 **축소 변형의 일부로 명시**돼 있고, 전면 배경과 달리 작은 요소라 회전 시 깜빡임으로 보이지 않는다.

### 결정 5 — 방향 판정은 **CSS 미디어쿼리만** (`landscape:` 변형)

Interaction Contract의 "명시적 트리거 정책 없음"에 따라 `@media (orientation: landscape)`만 쓴다. 방향 상태·`matchMedia`·방향 잠금 UI를 만들지 않았고, `useStudyRoomSession`은 방향을 모르는 상태 그대로다. 회전 시 **DOM 트리가 유지**되어야 포커스와 진행 중인 세션이 살아남기 때문에 가로용 별도 컴포넌트·라우트를 만들지 않고 같은 자식들을 그리드 셀에 재배치만 한다(Accessibility 마지막 항목).

### WG4(S3-7·S3-8)로의 인계 — 다이얼로그는 레이아웃 레이어의 **형제**로

가로 그리드가 생기면서 오버레이 삽입 위치가 제약이 됐다. 종료 확인 다이얼로그·자동 종료 안내를 `SESSION_LAYER_LAYOUT` div의 **자식으로 넣으면 안 된다** — qa-WG3가 프로브를 실제로 삽입해 세 가지 파손을 재현했다.

1. 가로에서 그리드 자동 배치로 row1/col1(좌상단)에 앉는다 — 중앙 모달이 구석에 그려진다.
2. row1 트랙이 커지면서 `1fr`인 row2가 줄어 심플 타이머(S3-6)의 수직 위치가 밀린다.
3. 레이어의 `pointer-events-none`을 상속해 확인·취소 버튼이 클릭을 못 받는다.

세로에서도 같은 컨테이너가 flex 컬럼이라 흐름 자식이 되어 컨트롤 바를 밀어낸다 — 가로 전용 문제가 아니다. 전체화면 오버레이는 `main` 바로 아래 `absolute inset-0` 형제로 넣고 `pointer-events-auto`를 직접 준다. 같은 경고가 `RoomPage.tsx`의 `handleRequestExit` TODO에도 적혀 있다.

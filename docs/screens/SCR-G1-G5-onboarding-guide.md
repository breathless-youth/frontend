# SCR-G1~G5 온보딩 가이드 (5단계 코치마크)

## Purpose

FocusON을 처음 쓰는 사용자에게 "이 앱이 내 공부 시간을 어떻게 재는가"를 세션 화면 위 말풍선 코치마크 5단계로 설명하는 온보딩 플로우다. 정적 안내 화면(구 S6-1)은 폐기되고 이 가이드로 통합됐다(`.ai/product/design.md` "온보딩 가이드 (신규)" 행).

핵심은 **최초 '집중 시작' 탭 시 자동 실행**이라는 점이다 — 앱 최초 실행 시점이 아니다(2026-07-26 인터뷰 6차에서 "최초 실행 자동"을 정정). 사용자는 공부를 시작하려는 순간에 딱 한 번 이 안내를 보고, G5의 CTA "집중 시작하기" 또는 건너뛰기로 빠져나가면 **그대로 세션 시작 플로우가 이어진다**. 가이드는 세션 진입을 가로막는 관문이 아니라 지나가는 길목이다.

G1~G5는 5개의 독립 화면이 아니라 **하나의 플로우가 갖는 5개 스텝**이다 — 배경(세션 화면 목업)·하단 내비게이션·페이저 도트는 5스텝 공통이고, 스텝마다 바뀌는 것은 툴팁 내용·툴팁 위치·강조 대상·목업 배경의 상태뿐이다. 5개의 라우트를 만들지 않는다.

## Ownership Boundary

이 화면이 **하지 않는 것**:

- **카메라를 켜지 않는다.** 가이드는 카메라 권한 요청(S2-2)보다 **먼저** 실행된다(`mvp-scope.md` 최초 시작 플로우). 따라서 배경은 실제 카메라 프리뷰일 수 없고, `design.md`도 "배경은 실제 앱 다크 화면(카메라 프리뷰 아님)"으로 못박았다. Figma의 `Session / Camera Preview BG`도 컴포넌트 설명에 "목업 배경"이라고 명시돼 있다. 카메라·`getUserMedia`·권한 API를 이 화면에서 호출하지 않는다.
- **실제 세션 화면을 재사용하지 않는다.** 배경의 상태 필·타이머·컨트롤 바는 `apps/web`이 구현하는 S3-1~S3-8의 실제 컴포넌트가 아니라, 모바일 쪽에 별도로 만드는 **표시 전용 목업**이다. 두 앱은 컴포넌트를 공유하지 않는다(ADR 0001 — 스터디룸은 웹, 앱 셸은 모바일).
- **세션 집계 로직을 구현하지 않는다.** G1·G2에서 타이머가 움직이는 것은 시연용 로컬 카운터다. `@focuson/types`의 세션 제출 계약과 무관하며, 서버에 아무것도 보내지 않는다.
- **카메라 권한 요청 자체를 담당하지 않는다.** 가이드는 "끝났다"는 콜백만 내보내고, 권한 요청(S2-2)·거부 안내(S2-3)는 `SCR-S2-camera-permission.md`(MG2) 소유다. 아래 Interaction Contract의 플로우 오케스트레이션 참고.

### 타이머 색 실측표 (5스텝 전체 · 2026-07-26 `get_design_context` 노드 단위 확인)

**순공 타이머의 색이 스텝마다 다르다 — 값만 보고 구현하면 안 된다.** 각 텍스트 노드에 fill이 직접 지정돼 있고, dim에 의한 감쇠가 아니다.

| 스텝 | 순공 타이머 노드 | fill               | 총 공부 fill | 의미                              |
| ---- | ---------------- | ------------------ | ------------ | --------------------------------- |
| G1   | `68:906`         | `#FFFFFF`          | white 42%    | 집중 진행 중(프리뷰 기본색)       |
| G2   | `68:982`         | `#8b95a1`          | white 42%    | 순공 정지                         |
| G3   | `68:1061`        | `#4593fc` + 글로우 | white 42%    | 심플 모드 = 타이머 색이 상태 컬러 |
| G4   | `68:1124`        | `#8b95a1`          | white 42%    | 순공 정지                         |
| G5   | `68:1291`        | `#FFFFFF`          | white 42%    | 집중 진행 중(프리뷰 기본색)       |

읽어낼 수 있는 규칙:

- **총 공부 줄은 5스텝 전부 `white 42%`로 동일하다.** 색이 바뀌는 것은 **순공 타이머뿐**이다 — 이것 자체가 "순공만 멈춘다"는 교육 목적의 시각 장치다.
- 프리뷰 배경(G1·G2·G4·G5)의 기본 타이머색은 흰색이고, **정지 상태에서 `#8b95a1`로 전환**된다. `#8b95a1`은 `packages/design-tokens`의 `colors.text.tertiary`(= `sessionStateColors.PAUSE`)와 정확히 같은 값이다.
- 심플 모드 배경(G3)만 타이머색이 상태 컬러(`#4593fc` 집중)다 — `design.md` "심플 모드 … 타이머 색=상태 컬러" 및 6차 확정 "세션 오버레이 색 … 집중 #4593FC"와 일치한다.
- ⚠️ **G2의 회색은 `design.md`와 어긋난다 — 확인 필요.** G2는 **비집중** 스텝인데, `design.md` 6차의 "세션 오버레이 색" 행은 _타이머_ 비집중색을 `#FF9E1B`(오렌지)로 규정한다. Figma는 오렌지가 아니라 `#8b95a1`을 썼다. 다만 같은 문서의 자동 비집중 행은 "오렌지 필 + **타이머 흐림 처리**"라고 쓰여 있어, 회색이 그 "흐림 처리"의 구현일 수도 있다. **둘 다 기록하고 임의로 한쪽을 고르지 않는다.** 상태 필은 G2에서 분명히 오렌지이므로, 어긋나는 것은 타이머 색 하나뿐이다.

  | **S3-2 비집중**   | `59:315` | **`#8b95a1`**    |
  | **S3-3 일시정지** | `59:359` | **`#8b95a1`**    |

  즉 Figma는 **비집중과 일시정지의 타이머 색을 구분하지 않고** 둘 다 `#8b95a1`을 쓰며, 두 상태의 구분은 **상태 필**(오렌지 도트 vs 회색 도트)이 전담한다. 온보딩 G2·G4는 그 규칙을 그대로 따랐을 뿐이다. 따라서 이 사안은 온보딩 화면 하나의 문제가 아니라 **`design.md`의 "세션 오버레이 색" 규정 vs Figma 파일 전체의 실제 구현**이 갈리는 디자인 시스템 레벨 쟁점이고, 확정되면 S3-2·S3-3(WG1·WG2)까지 함께 바뀐다. 리더에게 에스컬레이션했다.

  이 판정은 **서로 독립적인 두 방법으로 확인됐다** — ① `get_design_context`의 노드 fill 값(위 표) ② 세 노드를 각각 렌더해 픽셀 실측(`figma-qa-verifier`). 픽셀 실측에서 세 PNG의 배경·글리프 픽셀 수가 완전히 동일하게 나왔다 = **같은 텍스트 노드의 세 상태이고 오직 fill만 다르다**는 뜻이라, "Figma가 두 상태의 타이머 색을 구분하지 않는다"는 것은 추정이 아니라 확정된 사실이다. 이 결론이 WG1·WG2 구현 방향을 좌우하므로 근거를 남겨둔다.

- **⚠️ 이 문서의 타이머 색 값을 `apps/web`(S3-1~S3-8) 구현 근거로 인용하지 말 것.** 여기 적힌 값은 **온보딩 목업**의 실측값이다. 세션 화면을 구현할 때는 반드시 해당 화면의 자체 프레임(위 표의 노드)과 그 화면의 스펙 문서를 근거로 삼는다 — 목업 상수를 실제 세션 화면으로 옮기면, 위 괴리가 확정될 때 고쳐야 할 지점이 두 앱으로 흩어진다.

## Data Contract

**서버 API를 호출하지 않는다.** `packages/types/src/index.ts`에 이 화면과 대응하는 타입은 없고, 필요하지도 않다. 온보딩 가이드는 서버 상태가 아니라 **로컬 기기 상태 하나**만 필요로 한다.

### 필요한 로컬 상태: "가이드를 이미 봤는가" 플래그 1개

- 의미: 최초 '집중 시작' 탭에서 가이드를 자동 실행할지 판정하는 값. 앱 재실행 후에도 유지되어야 하므로 메모리 state로는 불충분하다 — **로컬 영속 저장이 필요하다.**
- ⚠️ **저장소 종류는 미정 — 리더/사용자 확인 필요.** `.ai`(design.md·mvp-scope.md·user-flow.md·6차 인터뷰 노트)와 Figma 어디에도 "최초 1회"의 저장 방식이 명시돼 있지 않다. 따라서 이 스펙은 **특정 라이브러리를 확정 계약으로 지정하지 않는다.**
  - 빌더에게 요구하는 것은 딱 두 가지다: (1) 앱 재실행 후에도 살아남는 영속 저장일 것, (2) 읽기/쓰기가 **하나의 모듈 뒤에 캡슐화**되어 나중에 저장소를 교체해도 화면 코드가 바뀌지 않을 것.
  - 저장소 구현체 선택은 **빌더 재량**이며, 선택한 근거를 코드 주석으로 남긴다. (참고 사실: `apps/mobile`은 현재 `expo-secure-store`로 기기 UUID를 저장하고 있고(`lib/deviceId.ts`), `@react-native-async-storage/async-storage`는 설치돼 있지 않다. 이건 **관찰된 현황일 뿐 확정 계약이 아니다** — 온보딩 플래그는 비밀 값이 아니므로 보안 저장소가 적절한지도 확인되지 않았다.)
  - 최소 인터페이스만 스펙으로 고정한다:

```ts
// 저장소 구현체는 미확정 — 이 인터페이스 뒤에 숨긴다.
// packages/types에 넣지 않는다(서버 API 계약이 아니다).
export interface OnboardingGuideStore {
  /** 가이드를 이미 봤으면 true. 저장값이 없으면 false. */
  hasSeenGuide(): Promise<boolean>;
  /** 가이드 플로우가 끝났을 때(완료·건너뛰기 모두) 호출 — 멱등. */
  markGuideSeen(): Promise<void>;
}
```

- **플래그를 언제 세우는가**: 가이드 플로우가 **어떤 경로로든 종료될 때**(G5 CTA 완료 / 건너뛰기 둘 다). 근거: 6차 인터뷰가 "건너뛰어도 세션은 이어서 시작"으로 확정했으므로, 건너뛰기를 "안 본 것"으로 처리하면 다음 '집중 시작'에서 가이드가 다시 떠 확정 플로우와 어긋난다. **wiki에 명시적으로 쓰여 있는 문장은 아니고 확정 사항에서 도출한 것이므로, 리뷰 항목으로 남긴다.**
- 홈 가이드 카드·설정에서의 **재진입은 이 플래그를 바꾸지 않는다**(이미 `true`인 상태에서 다시 보는 것뿐).

**백엔드 계약 미확인 — 상상 계약 금지**: "온보딩 완료 여부"를 서버에 동기화한다는 결정은 어디에도 없다. `UserRegisterRequest/Response`에도 관련 필드가 없다. 임의로 API를 만들거나 `packages/types`에 타입을 추가하지 않는다.

### 3. 플로우 종료 — 이후 동작

`.ai/notes/2026-07-26-디자인-반영-인터뷰-6차.md`의 확정 문장을 그대로 인용한다:

> **온보딩 가이드 노출**: ~~최초 실행 자동~~(인터뷰 중 정정) → **최초 '집중 시작' 탭 시 자동 실행**. 플로우: 집중 시작 → 가이드(G1~G5) → G5 CTA 또는 건너뛰기 → 카메라 권한 요청(최초 1회) → 세션 시작. **건너뛰어도 세션은 이어서 시작.** 홈 가이드 카드·설정 진입점은 유지

따라서 **진입 경로 A(최초 '집중 시작')**에서의 종료 동작은:

1. `markGuideSeen()` 호출 (완료·건너뛰기 동일)
2. 가이드 화면 닫기
3. **카메라 권한 요청(S2-2)으로 진행** — 최초 1회. 권한 요청·거부 안내(S2-3)는 이 화면이 아니라 `SCR-S2-camera-permission.md`(MG2) 소유다. 이 화면은 "가이드가 끝났다"는 콜백만 부모(플로우 오케스트레이션)에 넘기고, 다음 단계를 직접 호출하지 않는다.
4. 권한 허용 시 세션 시작. **완료든 건너뛰기든 여기서 갈라지지 않는다** — 둘 다 세션으로 이어진다.

- ⚠️ **진입 경로 B·C(다시 보기)에서 G5 "집중 시작하기"를 눌렀을 때의 동작은 미정 — 리더/사용자 확인 필요.** 6차 인터뷰는 "홈 가이드 카드·설정 진입점은 유지"라고만 하고, 재진입 시 CTA가 (a) 그대로 세션을 시작하는지 (b) 가이드만 닫고 원래 화면으로 돌아가는지 정하지 않았다. CTA 문구가 "집중 시작하기"로 고정돼 있어 (a)가 자연스러워 보이지만 **임의 확정하지 않는다.** 빌더는 종료 콜백에 진입 경로를 실어 보내는 인터페이스만 만들고, 재진입 경로의 분기 동작은 TODO로 남긴다.
- ⚠️ **가이드 도중 시스템 뒤로가기(Android 하드웨어 백 / iOS 스와이프 백)의 처리도 미정.** "건너뛰기와 동일 처리"가 자연스럽지만 근거 문서가 없다. 위와 같이 인터페이스만 만들고 TODO로 남긴다.

### 4. 배경 목업의 동작

`design.md` 확정 사항: "배경은 실제 앱 다크 화면(카메라 프리뷰 아님), **타이머 실시간 진행(G2는 순공만 정지 시연)**, 상태 필은 링 확산 페이드(ringOut) 강조".

- 타이머는 실시간으로 올라간다(시연용 로컬 카운터). 표기는 `HH:MM:SS` 고정, 총 공부는 `총 HH:MM:SS` 병기 — `voice-tone.md` §2 표기 규칙.
- **순공 정지는 두 가지로 동시에 표현된다: ① 값 고정 ② 색 전환(`#FFFFFF` → `#8b95a1` = `colors.text.tertiary`).** 위 "타이머 색 실측표" 참고. 값 하나에만 시연을 걸어두면 안 된다 — 실시간 카운터가 도는 화면에서 "이 숫자는 지금 멈춰 있다"를 값만으로 알아채기는 어렵고, Figma도 그래서 색을 함께 바꿨다.
- **G2에서는 순공 타이머만 멈추고 총 공부 타이머는 계속 흐른다.** 이것이 `mvp-scope.md` 세션 상태 모델의 "비집중 = 순공 정지 / 총 진행"을 눈으로 보여주는 장치다. Figma 예시값(순공 `00:00:12` 회색 vs 총 `00:00:22` white 42%)이 정확히 이 관계를 표현한다 — 값·색 어느 쪽도 빠뜨리지 않는다.
- **⚠️ G4는 색과 값이 서로 어긋나 있다 — 정적 프레임에서는 드러나지 않는 모순이다.** G4 순공 타이머는 이미 정지색(`#8b95a1`)인데, **값은 정지를 전혀 표현하지 않는다.** 근거는 스텝별 순공↔총 격차다:

  | 스텝                  | 순공       | 총 공부    | 격차                          |
  | --------------------- | ---------- | ---------- | ----------------------------- |
  | G1(집중)              | `00:00:19` | `00:00:22` | 3초                           |
  | **G4(일시정지 설명)** | `00:00:20` | `00:00:23` | **3초 — G1·G5와 동일**        |
  | G5(집중)              | `00:00:20` | `00:00:23` | 3초                           |
  | G2(비집중)            | `00:00:12` | `00:00:22` | **10초 — 순공이 멈춰 벌어짐** |

  G2는 격차가 벌어져 "순공이 멈췄다"를 값으로 보여주는데, **G4는 집중 스텝들과 똑같은 3초 baseline**이다. 즉 G4에서 정지를 표현하는 것은 **색뿐**이다. 정지 프레임에서는 티가 안 나지만, 실시간 카운터를 붙이면 **"회색인데 초가 계속 올라가는 숫자"**가 되어 사용자에게 모순으로 보인다(구현 중 실제로 확인됨).
  - **빌더는 이 모순을 임의로 해소하지 않는다.** 우선 Figma 실측 그대로(순공 회색 + 값 진행, 총 white 42% + 값 진행) 구현하고, 색·값 처리를 상수/플래그로 분리해 확정 시 한 곳만 고치면 되게 둔다. 코드 주석에 "의미가 확정됐다"고 단정해 쓰지 말고 아래 Review Checklist 항목을 가리키는 TODO를 남긴다.
  - 확정이 필요한 범위는 **총 공부 값 하나가 아니라 순공 값까지 포함한 3가지**다 — Review Checklist 참고.

- 상태 필 강조는 링 확산 페이드(ringOut). 구체 duration/easing 값은 Figma `6. Spec — Motion & Handoff`(node `14:7`)를 이번 스펙에서 조사하지 않았다 — 아래 Current Limitations 참고.

## Accessibility Requirements

- **"건너뛰기"의 탭 영역**: Figma에서 건너뛰기는 하단 힌트 텍스트(12px, 높이 14px) 안의 "· 건너뛰기" 부분이다. 시각적 크기와 무관하게 **터치 영역은 최소 44×44px**을 확보한다(투명 히트슬롭 확대). 텍스트만 그대로 옮기면 접근성 기준 미달이 된다 — 가장 놓치기 쉬운 항목이다.
- "이전"(66×48)·"다음"/"집중 시작하기"(288×48)는 48px 높이로 이미 44px 기준을 충족한다.
- **페이저 도트는 장식이다.** 진행 상태를 색·크기로만 전달하지 않도록, 플로우 컨테이너에 `accessibilityLabel`로 "5단계 중 N단계"를 함께 제공한다(`design.md` 상태 컬러 보조 규칙 "색상 단독 전달 금지"의 정신을 따른다).
- **제스처 대체 경로**: 탭/스와이프로만 넘길 수 있으면 안 된다 — "이전"/"다음" 버튼이 항상 화면에 있으므로 이 요건은 디자인에서 이미 충족됐다. **버튼을 제거하고 제스처만 남기지 않는다.**
- **스크린 리더 순서**: 툴팁(타이틀 → 본문) → 페이저 진행 → 내비게이션 버튼 → 건너뛰기 순으로 읽히게 한다. 배경 목업(타이머·상태 필·컨트롤 바)은 dim 아래의 장식이므로 `accessibilityElementsHidden`/`importantForAccessibility="no-hide-descendants"`로 스크린 리더에서 제외하되, **그 스텝의 강조 대상만은 예외로 읽히게 한다**(G1 타이머, G2 상태 필, G4 컨트롤 바) — 툴팁이 가리키는 대상을 스크린 리더 사용자도 알아야 한다.
- **폰트 확대**: 툴팁 본문이 2~4줄로 늘어나도 카드가 잘리지 않아야 한다. Figma 실측 높이(98/117/92/98)는 고정값이 아니라 최소값으로 취급한다.
- **명암비**: 본문 `rgba(255,255,255,0.65)` on `rgba(25,31,40,0.97)`는 Figma 확정값이다. 임의로 더 낮추지 않는다.
- **타이머 숫자**: `tabular-nums`(고정폭 숫자)를 적용해 초가 바뀔 때 좌우로 흔들리지 않게 한다(`voice-tone.md` §2 표기 규칙).

- **G3 프레임에 상태 필이 없다.** `design.md`의 심플 모드 정의는 "**상태 필·컨트롤 바 유지**"인데, Figma G3(`68:1057`)에는 `Session / Status Pill` 인스턴스가 아예 없다(S3-4 원본 프레임 `60:404`에는 있다). Figma가 코치마크 배경을 단순화한 것인지, 심플 모드 정의가 바뀐 것인지 확인되지 않았다 — **임의로 한쪽을 고르지 않고 병기한다. 확인 필요.** 빌더는 우선 Figma 그대로(상태 필 없음) 구현하고 주석으로 이 괴리를 남긴다.
- **G4의 강조 표현이 wiki와 다르다.** `design.md`는 "G4 하단바·일시정지(**바 링 하이라이트 + 위치 힌트 셰브런**)"라고 쓰여 있으나, Figma G4(`68:1118`)에는 링 스트로크도 셰브런 노드도 없고 대신 **컨트롤 바를 y756 → y409로 끌어올려** dim 위에 얹는 방식으로 강조했다. 두 표현을 모두 기록한다 — **확인 필요.** 빌더는 Figma 방식(끌어올림)으로 구현하되, 링/셰브런으로 확정되면 교체할 수 있게 강조 방식을 컴포넌트 prop으로 분리한다.
- **G4의 프라이버시 캡션 노드가 `hidden=true`다.** 의도적 숨김인지 정리 누락인지 불명 — Figma 그대로 렌더하지 않는다.
- **모션 수치 미조사**: 상태 필 ringOut 확산 페이드, 심플 모드 글로우 1~2초 잔향, 스텝 전환 트랜지션의 duration·easing 값을 이번 스펙에서 확정하지 못했다. Figma `6. Spec — Motion & Handoff`(node `14:7`)에 값이 있을 수 있으나 이번 조사 범위에 넣지 않았다. 빌더는 자연스러운 기본값으로 구현하고, 값이 확정되면 교체할 수 있게 상수로 분리한다.
- **예시 데이터**: 타이머 값(`00:00:19`/`총 00:00:22`, `00:00:12`/`총 00:00:22`, `00:25:08`/`총 00:27:48`, `00:00:20`/`총 00:00:23`)은 시안 예시다. 실시간 카운터로 대체하되 **G2의 "순공 < 총" 관계와 스텝별 타이머 색(위 타이머 색 실측표)은 유지**한다 — 값과 색 둘 다 시연 장치다.
- **Pretendard 미적용**: Figma는 설치 전까지 Inter 임시 적용 중이다(`design.md`). 폰트 교체는 담당자(선규)가 반영 예정이므로 이 화면에서 폰트를 임의 교체하지 않는다.
- **진입 경로 B·C가 아직 없다**: S6 설정(MG4)은 구현 전이고, S1 홈의 가이드 카드 핸들러는 현재 TODO로 비어 있다(`apps/mobile/app/(tabs)/index.tsx:208-212`). 가이드 라우트가 생기면 홈의 TODO를 연결하고, 설정은 MG4 빌더가 연결한다.
- **경로 A의 후속 단계가 아직 없다**: 카메라 권한(S2-2/S2-3, MG2)과 세션 화면(S3, WG 계열)이 구현되기 전까지 종료 콜백의 목적지는 TODO로 남는다. 존재하지 않는 라우트로 이동을 시도하지 않는다(`SCR-S1-home.md`와 동일한 방어적 처리).

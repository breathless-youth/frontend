# SCR-S3-3 · S3-4 세션 — 일시정지 / 심플 모드

> 작업 그룹 WG2. 담당 앱 `apps/web`(모바일이 WebView로 로드). 2026-07-26 6차 인터뷰 확정 기준.

## Purpose

싱글룸 공부 세션 화면의 두 가지 프레젠테이션 상태를 정의한다.

**S3-3 일시정지**는 "지금은 시간이 재어지지 않는다"를 사용자가 오해 없이 알아채고, 손실 불안 없이 다시 시작할 수 있게 하는 화면이다. 2026-07-26 확정으로 **수동 일시정지 버튼과 화면 꺼짐·백그라운드 전환이 같은 하나의 상태로 통합**됐다 — 트리거만 다를 뿐 사용자에게 보이는 화면·시간 처리·결과 집계는 완전히 동일하다.

**S3-4 심플 모드**는 카메라 프리뷰를 걷어내고 타이머 숫자만 크게 남기는 저자극 표시 모드다. 세션 상태(집중/비집중/일시정지)와는 **직교(orthogonal)** 하다 — 심플 모드는 "어떻게 보여줄지", 일시정지는 "세션이 어떤 상태인지"를 나타내며, 두 축은 독립적으로 조합된다.

## 일시정지 통합 정책 (2026-07-26 확정) — 이 스펙의 핵심

`.ai/notes/2026-07-26-디자인-반영-인터뷰-6차.md` 원문:

> **화면 꺼짐·백그라운드 재분류**: 비집중 유형이 아니라 **일시정지에 합산** — 시간 처리도 일시정지와 동일(순공·총 모두 정지). 결과·기록에서 '화면 꺼짐' 라벨 제거, '일시정지'로 통합 노출

세션 상태 모델(`mvp-scope.md`) 요약:

| 상태         | 진입 조건                                       | 순공시간 | 총 공부 시간 | 해제                           |
| ------------ | ----------------------------------------------- | -------- | ------------ | ------------------------------ |
| 집중         | 기본 상태                                       | 진행     | 진행         | —                              |
| 비집중       | 감지 3종(자리 이탈·휴대폰 사용·기기 조작)       | 정지     | **진행**     | 감지 해제 시 자동 재개         |
| **일시정지** | ① 일시정지 버튼 ② **화면 꺼짐·백그라운드 전환** | **정지** | **정지**     | ①은 재개 버튼 / ②는 **미확정** |

구현 규칙 (반드시 지킬 것):

1. **트리거는 2개, 상태와 화면은 1개.** 상태는 `PAUSE` 하나이고 S3-3 프레젠테이션도 하나다. "수동 일시정지 화면"과 "화면 꺼짐 화면"을 따로 만들지 않는다. 트리거 출처는 이미 출하된 `PauseTrigger`(`"MANUAL" | "BACKGROUND"`)로 **내부에만** 기록하고, **화면·문구·시간 처리·서버 전송에는 아무 차이도 두지 않는다**(서버로는 둘 다 `PAUSE` 하나로 나간다).
   ⚠️ 상태 이름은 **`PAUSE`**다. `PAUSED`는 `frontend/docs/domain-glossary.md`와 ADR 0002가 명시 폐기한 이름이니(2026-07-25 리셋 이전 상상 계약의 잔재) 쓰지 않는다.
2. **순공시간·총 공부 시간이 모두 멈춘다.** 비집중(순공만 정지)과 혼동 금지.
3. **일시정지 구간은 벽시계 기준으로 별도 집계**한다 → S4 결과·S5 기록에 "일시정지 N회 · 시간"(회색)으로 표기. 그래서 결과의 `HH:MM – HH:MM` 시각 범위와 총 공부 시간은 서로 다를 수 있다.
4. **일시정지 상태가 N분 유지되면 세션 자동 종료 + 기록 저장**(S3-8). 수동·화면 꺼짐 **동일 규칙, 감시 로직은 하나**다 — 트리거별로 타이머를 2개 만들지 않는다. N값은 튜닝 파라미터(아래 "미정" 참조).
5. **'화면 꺼짐' 라벨을 UI에 쓰지 않는다.** 사용자 노출 표기는 언제나 "일시정지"다(`glossary.md`). 유일한 예외는 S3-8 자동 종료 안내의 확정 문구인데, 그건 WG4 범위이고 이 화면에서는 쓰지 않는다.

## Ownership Boundary

- 이 화면은 **세션 프레젠테이션과 세션 상태 머신까지만** 담당한다.
- 하지 않는 것: 카메라 스트림 획득 구현, Vision 감지 추론(비집중 판정), LiveKit/WebRTC, 모바일 네이티브 화면, S4 결과 화면(WG5), S3-7/S3-8 다이얼로그·안내 화면(WG4).
- 비집중 상태(S3-2)의 프레젠테이션은 WG1 소유다. 이 문서는 "일시정지는 비집중과 어떻게 다른가"만 정의한다.
- 가로 모드(S3-5/S3-6)는 WG3 소유 — 여기서 가로 레이아웃을 만들지 않는다. 단, 세로에서 만든 컴포넌트를 WG3가 그대로 재사용할 수 있게 설계한다.
- **V1.0에 멀티룸 화면은 없다**(`design.md` 화면 인벤토리 — S7~~S11은 V1.2~~V1.4). 이 화면은 싱글룸 전용이며 참가자 그리드·타일·소셜 요소를 넣지 않는다. `frontend/CLAUDE.md`·`apps/web/CLAUDE.md`·ADR 0001/0002가 멀티룸을 현재형으로 서술하지만 그건 아키텍처 방침 설명이다 — 거기서 멀티룸 문구를 끌어오지 않는다.

## Data Contract

### 이미 존재하는 타입 — 그대로 재사용한다 (`@focuson/types`)

```ts
// packages/types/src/index.ts — 백엔드 Swagger 기준, 상상 계약 아님
export type StudyEventStatus = "PHONE" | "DEVICE" | "AWAY" | "PAUSE";

export interface StatusEventPayload {
  status: StudyEventStatus;
  startedAt: string; // UTC ISO-8601
  endedAt: string; // UTC ISO-8601
}
```

**일시정지는 이미 서버 계약에 있다** — `PAUSE`. 타입 주석도 "PAUSE=일시정지(총공부 타이머까지 정지 — 나머지 셋은 순공 타이머만 정지)"로 6차 확정 정책과 일치한다. 새 이벤트 타입을 만들지 않는다.

계약이 강제하는 제약(반드시 지킬 것):

- `StudySessionCreateRequest.studySec`: `0 ≤ studySec ≤ (endedAt − startedAt) − PAUSE 시간 합`
  → **일시정지 구간을 총 공부 시간에서 빼지 않으면 서버 검증에 걸린다.**
- `focusSec`: `0 ≤ focusSec ≤ studySec`
- `events`: 세션 구간 안 · **서로 겹침 불가** · **0초 불가**
  → 비집중 이벤트와 일시정지 이벤트가 시간적으로 겹치지 않게 상태 머신에서 보장해야 한다(일시정지 진입 시 진행 중인 비집중 이벤트를 먼저 닫는다). **`sessionTimeline.transition`이 이미 이렇게 동작하고 테스트로 고정돼 있다** — WG2가 다시 구현하지 않는다.
  → 1초 미만의 매우 짧은 일시정지(더블탭 등)는 0초 이벤트가 될 수 있는데, `toStatusEvents`가 `MIN_EVENT_MS = 1000` 미만 구간을 **버리는** 방식으로 이미 처리한다(이벤트 사이에 빈틈이 생기지만 겹치지는 않는다). 남은 확인거리는 "버리는 게 맞는지 vs 1초로 올림인지"라는 제품 판단뿐이다.

### 이 화면에서 이미 만들어진 것 (WG1이 출하, 재사용할 것 — 새로 선언하지 않는다)

> ⚠️ **스펙 정정(2026-07-26, WG1 QA에서 발견)**: 이 문서가 원래 예시로 들었던 `SessionPhase`/`PAUSED`/`PauseReason`/`"manual"|"system"`은 WG1이 실제로 출하한 타입명과 어긋난다. WG1이 이미 `apps/web/src/features/study-session/sessionState.ts`에 아래 타입을 구현·테스트까지 마쳐 놓았으므로, WG2는 이걸 그대로 import해서 쓴다 — 새 타입을 선언하지 않는다.

```ts
// apps/web/src/features/study-session/sessionState.ts (WG1 기 구현, import해서 재사용)
export type DistractionTrigger = "AWAY" | "PHONE" | "DEVICE";
export type PauseTrigger = "MANUAL" | "BACKGROUND";

export type SessionState =
  | { kind: "FOCUS" }
  | { kind: "DISTRACTION"; trigger: DistractionTrigger }
  | { kind: "PAUSE"; trigger: PauseTrigger };
// ⚠️ trigger(MANUAL/BACKGROUND)는 내부 계측/디버깅용이다. 화면·문구·서버 전송에 반영하지 않는다
//    (6차 확정: 두 트리거를 '일시정지' 하나로 통합 노출).
```

같은 파일의 헬퍼도 그대로 쓴다: `pauseState(trigger)` · `FOCUS_STATE` · `isSameSessionState` · `toEventStatus`(FOCUS는 `null` = 이벤트 미기록) · `isFocusRunning` · `isStudyRunning`.

**세션 상태 모델을 두 갈래로 만들지 않는다.** `sessionTimeline.ts`의 `transition`/`toStatusEvents`/`computeSessionTotals`가 전부 `SessionState`를 받는다 — 평행 타입을 새로 선언하면 변환 계층을 짜거나 WG1 로직을 우회하게 된다.

**심플 모드용 표시 모드 타입도 새로 만들지 않는다.** `RoomPage.tsx`에 이미 `const [simpleMode, setSimpleMode] = useState(false)`가 있고, "심플 모드는 상태가 아니라 프레젠테이션 토글이다 — `SessionState`에 넣지 않는다"는 주석까지 붙어 있다(SCR-S3-1·S3-2 지정). WG2는 이 boolean을 그대로 쓰고 `DisplayMode` 유니온을 별도로 도입하지 않는다.

### 백엔드 계약 미확인 — 상상 계약 금지

- **일시정지 트리거 구분(수동/시스템)을 서버에 보낼 필드가 없다.** 현재 계약은 `PAUSE` 하나뿐이며, 6차 확정상 구분해서 노출할 필요도 없다. 나중에 구분 집계가 필요해지면 백엔드와 먼저 계약을 정한다 — 임의 필드를 만들지 않는다.
- **일시정지 "시간 합" 필드가 응답에 없다.** `StudySessionSummary.eventCounts.PAUSE`로 **횟수**는 얻지만, "일시정지 N회 · **시간**" 표기의 시간은 `StudySessionResponse.events`를 직접 합산해야 얻는다. 목록 응답(`StudySessionListResponse.sessions`)에는 `events`가 없어 시간 합을 만들 수 없다 — S4/S5에서 이 표기가 필요하면 **백엔드 계약 미확인 — 상상 계약 금지: 세션별 일시정지 시간 합계 필드**. (WG5·MG3 범위이지만 여기서 발견해 기록해 둔다.)
- **자동 종료로 끝난 세션임을 서버에 표시하는 필드가 없다** — 필요 여부는 WG4와 함께 확인.

## Interaction Contract

### 일시정지 진입

| 트리거                              | 처리                                            |
| ----------------------------------- | ----------------------------------------------- |
| 컨트롤 바 첫 번째 버튼(일시정지) 탭 | `{ kind: "PAUSE", trigger: "MANUAL" }` 진입     |
| 화면 꺼짐 / 앱 백그라운드 전환      | `{ kind: "PAUSE", trigger: "BACKGROUND" }` 진입 |

- 두 경로 모두 **동일한 함수 하나**로 들어간다 — `useStudyRoomSession`이 이미 노출하는 `pause(trigger: PauseTrigger = "MANUAL")`(내부에서 `pauseState(trigger)` → `applyState`). 진입 후 화면·시간 처리·이벤트 기록에 차이가 없다. 새 진입 함수를 만들지 않는다.
- 진입 즉시: 순공 타이머 정지 · 총 공부 타이머 정지 · 벽시계 기준 일시정지 시작 시각 기록 · 진행 중인 비집중 이벤트가 있으면 먼저 종료.
- 진입 시 상태 필이 Paused로, 컨트롤 바 첫 버튼이 파란 재개(`#3182F6` + play 아이콘)로 교체된다.
- 시스템 트리거 감지 수단: 웹(WebView) 표준은 Page Visibility API(`visibilitychange`) + `pagehide`. **WKWebView에서 화면 잠금 시 이벤트가 실제로 발화하는지는 실기기 검증 전까지 확정 불가** — 감지 소스를 어댑터 한 곳(`createSystemPauseSource()`)으로 격리하고, 네이티브 브리지가 필요해지면 그 어댑터만 교체할 수 있게 만든다.

### 일시정지 해제

| 경로                                     | 처리                                                       |
| ---------------------------------------- | ---------------------------------------------------------- |
| 재개 버튼 탭(수동 트리거였던 경우)       | 직전 표시 모드로 복귀, 두 타이머 재개, `PAUSE` 이벤트 확정 |
| **화면 꺼짐·백그라운드에서 복귀했을 때** | **미정 — 리더/사용자 확인 필요**                           |

> `.ai/product/design.md` 백로그 6번: "화면 꺼짐·백그라운드 복귀 시 재개 방식 (자동 vs 수동) — **구현 시 결정**"
> `.ai/product/mvp-scope.md` 미확정 항목: "**AI 에이전트는 이 값들을 임의로 확정하지 말고**, 구현 시 팀에 확인하거나 설정 가능한 파라미터로 열어둘 것."
> 6차 인터뷰 노트 "보류" 섹션: "복귀 시 재개 방식 — 자동 재개 vs 일시정지 화면에서 수동 재개 (구현 시 결정, **임의 확정 금지**)"

**빌더 지시 (이 항목만은 반드시 그대로 따를 것):**

1. 복귀 이벤트를 받는 진입점은 **WG1이 이미 만들어 뒀다** — `useStudyRoomSession`의 `onReturnFromBackground()`(현재 의도적 no-op + TODO 주석). 이름이 다른 함수를 새로 만들지 말고 이걸 쓴다.
2. 그 함수 본문은 **비워 둔 채로** 두고, TODO 주석(`design.md` 백로그 6번 참조)을 지우지 않는다.
3. 결과적으로 복귀 시 화면은 S3-3에 머문다. **이것은 "수동 재개로 확정"이 아니라 "미구현"이다** — 코드·주석·PR 설명 어디에도 "수동 재개로 확정됐다"고 쓰지 않는다. (WG1 코드 주석의 "임시 기본값은 수동 재개"라는 표현도 *잠정 동작*을 뜻하며 정책 확정이 아니다.)
4. 자동 재개로 결정되면 이 함수 **한 곳만** 고치면 되도록 다른 곳에 복귀 로직을 흩뿌리지 않는다.
5. 이 항목은 리더 에스컬레이션 대상이다 — 스스로 결정하지 말고, 빌드 중 막히면 즉시 질문한다.

### 일시정지 자동 종료

- 규칙: **일시정지 상태가 N분 유지되면 세션 자동 종료 + 그때까지 기록 저장** → S3-8 안내 → S4 결과 (`mvp-scope.md`, `policies.md`, 6차 노트 모두 동일).
- **N값: 확정값 미정 — WG4(종료 플로우) 스펙과 함께 확인 필요.** `mvp-scope.md` 미확정 항목에 "일시정지 자동 종료 대기 시간 N분의 값 (수동 일시정지·화면 꺼짐 공용)"으로 명시돼 있고, wiki 어디에도 숫자가 없다. 하드코딩하지 말고 설정 파라미터(예: `SESSION_AUTO_END_PAUSE_MINUTES`)로 열어 두고 기본값에 TODO 주석을 단다.
- **감시 로직은 하나만 만든다.** 수동/시스템 트리거가 같은 타이머를 공유한다(`screen-groups.md` WG4 항목과 동일 지시).
- 자동 종료 안내 문구는 이 화면이 아니라 S3-8(WG4)가 그린다. 다만 **수동 일시정지 방치로 자동 종료될 때의 문구는 아직 없다**:
  > `voice-tone.md`: 자동 종료 안내(수동 일시정지 방치) — ⚠️ 미정 — 위 문구는 화면 꺼짐 전제. 수동 일시정지 장시간 방치로 자동 종료될 때의 변형 문구는 작성 필요
  > → 이 화면에서 임의 문구를 만들지 않는다. WG4와 함께 확인.

### 심플 모드 토글 (S3-4)

- **진입/복귀**: 화면 탭. **컨트롤 바 영역은 제외**한다(`design.md`: "화면 탭 전환(바 영역 제외, 대칭 복귀)"). Figma도 프레임 전체가 탭 타깃이고 컨트롤 바 버튼 핫스팟이 그 위에 겹쳐 있어 서로 먹지 않는다.
- **대칭 복귀**: 심플 모드에서 한 번 더 탭하면 프리뷰로 돌아온다. 별도 닫기 버튼을 만들지 않는다.
- 전환 모션: **Smart Animate 300ms · ease-out**, 타이머 숫자의 위치·크기 연속성 유지(52pt 중앙 정렬 기준) — Spec 페이지 `14:7` 실측.
- 상태 필 전환(집중↔비집중↔일시정지): 배경·보더·도트 컬러 **크로스페이드 200ms**, **레이아웃 시프트 없음**(필 폭 변화는 좌우 균등 확장).
- 심플 모드에서도 **상태 필과 컨트롤 바는 유지**된다(`design.md` 확정).
- 심플 모드에서 타이머 색 = **상태 컬러**(`design.md`) → 집중 `#4593FC` · 비집중 `#FF9E1B` · 일시정지 `#8B95A1`.
- 표시 모드는 세션 상태와 독립적으로 보존된다 — 심플 모드에서 일시정지했다가 재개하면 **심플 모드로 돌아온다**(모드가 임의로 리셋되지 않는다).

## Implementation Notes For AI Agents

1. **읽는 순서**: 이 문서 → `frontend/docs/screen-ownership.md` → `apps/web/CLAUDE.md` → `packages/types/src/index.ts` → 기존 `RoomPage.tsx` / `useStudyRoomSession.ts`. 그 다음 Figma 노드 `59:355`·`60:404`를 `get_design_context`로 직접 재확인한다(`figma:figma-design-to-code` 스킬 선행 호출 필수).
2. **기존 로직을 버리지 않는다.** `RoomPage.tsx`에는 "디자인 확정 시 이 파일만 새 화면으로 교체한다"는 주석이 있고, 타이머·제출·멱등 종료 처리는 `useStudyRoomSession`에 이미 분리돼 있다. 프레젠테이션을 교체하고 훅을 **확장**한다(재작성 금지).
3. **타이머 표기는 이미 해결됐다 — 다시 만들지 않는다.** `formatDuration.ts`의 `formatElapsed`가 시(hour)까지 zero-pad한 `HH:MM:SS`를 반환한다(구 `1:24:08` 버그는 WG1이 수정 완료). 스크린리더용 `toKoreanDuration`도 같은 파일에 있다. 숫자는 `tabular-nums`로 렌더한다(voice-tone §2).
4. **`studySec`의 일시정지 차감도 이미 해결됐다 — 다시 만들지 않는다.** `computeSessionTotals`가 `studySec`(일시정지 제외)·`focusSec`(비집중·일시정지 제외)·`pauseSec`(벽시계 별도 집계)을 2축으로 계산하고, `endAndSubmit`이 그 값으로 제출한다. 훅 밖에서 시간을 다시 계산하지 않는다(`apps/web/CLAUDE.md`: 공부 상태·집중률 계산을 화면 컴포넌트에서 직접 구현하지 않는다).
5. **이벤트 겹침·0초 금지도 이미 보장된다 — 다시 만들지 않는다.** `sessionTimeline.transition`이 상태 전이 시 직전 구간을 닫아 겹침을 원천 차단하고(테스트 있음), `toStatusEvents`가 `MIN_EVENT_MS = 1000` 미만 구간을 버린다. WG2는 `pause()`/`resume()`를 호출하기만 하면 된다.
6. **트리거는 2개, 화면·상태·이벤트는 1개.** 화면 꺼짐용 별도 컴포넌트/상태/문구를 만들면 이 스펙 위반이다.
7. **미정 항목을 코드에서 확정하지 않는다** — 화면 꺼짐 복귀 방식, 자동 종료 N분 값, 수동 방치 자동 종료 문구. 전부 TODO + 파라미터로 남긴다.

9. **V1.2+ 페이지(node `14:8`)의 화면은 만들지 않는다.**
10. **아이콘은 Figma에서 내보낸 에셋을 쓴다** — `icon/play`·`icon/pause`·`icon/camera-flip`·`icon/exit`. SVG path를 손으로 그리지 않는다. SVG로 내보내되 캔버스 배경 `<rect>`는 제외한다(PNG로 내보내면 배경이 합성돼 흰 네모가 된다 — MG1에서 실제로 발생한 이슈).
11. **카메라 프리뷰 줄무늬 목업을 프로덕션에 넣지 않는다.** 그 자리는 실제 카메라 피드 영역이다(카메라 어댑터는 아직 없으므로, 연결 전까지의 플레이스홀더로만 허용하고 그렇게 주석을 단다).

## Accessibility Requirements

- **터치 타겟**: 컨트롤 바 버튼 50×50px — 44px 최소 기준 충족(세로). 가로 모드는 44×44(WG3)로 경계선상이니 그룹 간 축소 금지.
- **색 단독 전달 금지**(`design.md` 상태 컬러 보조 규칙 ①: "항상 점+텍스트"). 일시정지를 회색으로만 표현하지 말고 상태 필 텍스트 `측정을 일시정지했어요`를 항상 함께 노출한다 — **심플 모드에서도 상태 필을 유지하는 이유가 이것이다.**
- **아이콘 전용 버튼의 접근 가능한 이름 — `aria-label`도 voice-tone 대조 대상이다.** 화면에 보이는 텍스트만 문구 검증하고 `aria-label`을 빠뜨리면 정책 위반이 그대로 통과한다(2026-07-26 WG1에서 실제로 발생: 재개 버튼이 금지어 "재개"를 쓰고 있었고 1차 QA가 놓쳤다). 아래 4개를 그대로 쓴다:

  | 버튼                      | 접근 가능한 이름 | 근거                                                                                           |
  | ------------------------- | ---------------- | ---------------------------------------------------------------------------------------------- |
  | 첫 번째 버튼(일시정지 중) | `다시 시작`      | voice-tone §1 — **"재개"는 금지어**, 쉬운 우리말로 치환                                        |
  | 첫 번째 버튼(진행 중)     | `일시정지`       | glossary 노출 표기                                                                             |
  | 종료                      | `공부 종료`      | voice-tone §4 S3-7 다이얼로그 버튼 확정 문구와 일치시킨다                                      |
  | 카메라 전환               | `카메라 전환`    | 확정 문구 아님 — 토스트 `카메라를 전환했어요`(voice-tone §4)에서 파생. 확정 카피가 생기면 교체 |

  **경계 — voice-tone §1은 "사용자 노출 문자열" 한정 규칙이다.** 금지 대상은 **화면에 나가는 문자열**(가시 텍스트 + `aria-label`·`alt` 등 접근성 이름)뿐이고, 주석·테스트 제목·변수/함수명 같은 **내부 식별자에서 `재개`를 쓰는 건 위반이 아니다.** 근거: `mvp-scope.md`의 세션 상태 모델 표 자체가 내부 명세 산문에서 `감지 해제 시 **자동 재개**`라고 쓴다. 훅의 `resume()`·`onReturnFromBackground()`도 그대로 둔다 — **코드베이스에서 `재개`를 일괄 치환하려 들지 말 것.**

- **상태 변화 알림**: 상태 필 영역을 `aria-live="polite"`로 두어 집중↔비집중↔일시정지 전환이 스크린리더로 전달되게 한다. 단, 소리·진동은 쓰지 않는다(`mvp-scope.md`).
- **심플 모드 토글의 대체 경로**: "화면 전체 탭"만으로는 스크린리더·키보드 사용자가 모드를 바꿀 수 없다. 탭 영역에 접근 가능한 이름을 가진 버튼 역할(role/label)을 부여하고 키보드로도 토글 가능하게 한다.
- **모션 민감성**: 심플 모드 숫자 발광 루프(제안값 2.4s 무한 왕복)와 전환 애니메이션은 `prefers-reduced-motion: reduce`에서 정지/축소한다. _(문서 근거 없음 — 일반 접근성 기준에 따른 권장. 디자인 확인 시 스펙에 반영한다.)_
- **대비**: 일시정지 타이머 `#8B95A1` on `#0B0F14`/`#1A2029`는 52px 대형 텍스트라 WCAG 대형 텍스트(3:1) 기준을 적용한다. 총 공부 병기(15px, white 42%)와 캡션(12px, white 55%)은 소형 텍스트라 **실측 대비 검증이 필요하다**(QA 항목).
- **폰트 확대**: 상태 필은 폭 고정이 아니라 문구 길이에 따라 좌우 균등 확장 — 확대 시에도 잘리지 않아야 한다.

7. **1초 미만 일시정지는 이벤트에서 통째로 사라진다 — "미세한 오차"가 아니다.** (2026-07-26 qa-WG1이 실측 재현, 리더 결정 대기 중)
   - 원인: `toStatusEvents`는 `MIN_EVENT_MS = 1000` 미만 구간을 **버리는데**(서버가 0초 이벤트를 금지하므로), `computeSessionTotals`는 **그 구간까지 집계에 넣는다**. 두 함수의 기준이 다르다.
   - 실측(900ms 일시정지 3회 / 세션 20초): `pauseSec = 2`(클라 집계) · **전송 PAUSE 이벤트 0건** · 이벤트 시간 합 0 · `studySec = 17`.
   - **서버 검증 위험은 없다** — 이벤트를 덜 보낼수록 상한 `(endedAt−startedAt) − PAUSE 합`이 커지므로 400이 날 수 없다(qa-WG1 2차 테스트로 확인). 방향이 안전한 쪽이다.
   - **실제 타격은 "시간"보다 "횟수"다.** `eventCounts.PAUSE`는 서버가 받은 이벤트로 세므로 위 사례에서 **`일시정지 0회`**로 내려온다 — 사용자는 3번 눌렀는데. S4는 "0건이면 일시정지 행을 렌더하지 않고", S5는 "0이면 칩을 그리지 않는다"고 각자 스펙에 지정돼 있어, **결과 화면에서 일시정지의 흔적이 완전히 사라진다.** 그런데 `studySec`은 이미 그만큼 줄어 있어서 "총 공부 < 시각 범위"인데 그 차이를 설명해 줄 행이 화면에 없는 상태가 된다.
   - **이 하향 편차는 `PAUSE` 전용이 아니다**(spec-MG3 제보, 2026-07-26 spec-WG2 실측 확인). `toStatusEvents`는 `toEventStatus`가 null이 아닌 **모든 상태**에 같은 필터를 적용하므로 `AWAY`·`PHONE`·`DEVICE`도 같은 방식으로 사라진다. 실측 재현 3종:
     - **비집중 진입 300ms 후 일시정지** → PHONE 이벤트 소멸(`studySec 13 / focusSec 13`). **WG2가 직접 만드는 경로다** — 일시정지 버튼을 비집중 직후에 누르면 그 비집중이 기록에서 지워진다.
     - **트리거 전환(AWAY→PHONE) 후 뒤쪽 구간 200ms** → PHONE 이벤트만 소멸, 오렌지 시간은 `distractionSec`에 그대로 남음.
     - **세션 종료 500ms 전 비집중 진입** → 이벤트 0건인데 `focusSec 19 / studySec 20`. S4가 "집중률 95%"를 띄우면서 동시에 비집중 0 문구(`비집중 없이 이어간 공부예요`, voice-tone §4)를 띄우는 **자기모순 화면**이 된다.
   - **WG2는 이 동작을 임의로 바꾸지 않는다.** 정책 결정 사항이라 리더 보고로 올라가 있다(선택지: ⓐ 버림 유지 + S4/S5는 서버 값만 신뢰 ⓑ 1초로 올림 — **단순 구현은 계약 위반 확인됨, 경계 처리 설계 선행 필요** ⓒ 입력단 디바운스로 짧은 일시정지 자체를 차단 ⓓ 집계·이벤트의 임계값 일치). 결정 전까지 `MIN_EVENT_MS`를 건드리지 않는다.
   - **결정 범위는 `PAUSE` 단독이 아니라 `StudyEventStatus` 4종 전체다.** ⓑ를 PAUSE에만 적용하면 나머지 3종이 남고, ⓒ(디바운스)는 사용자 입력인 PAUSE에만 유효하고 감지 신호(AWAY/PHONE/DEVICE)에는 적용되지 않아 단독으로는 불충분하다(qa-WG1 분석).
   - **⚠️ ⓑ는 "1초로 올림"을 그대로 구현하면 서버 계약을 위반한다 — 실측 확인(2026-07-26 spec-WG2).** 짧은 구간의 `endedAt`을 1초로 늘리면:
     - `PHONE 300ms → 즉시 PAUSE` = PHONE이 PAUSE 시작을 **700ms 침범** → "서로 겹침 불가" 위반
     - `종료 500ms 전 DEVICE 진입` = 이벤트가 세션 종료를 **500ms 초과** → "세션 구간 안" 위반
     - (충분히 긴 구간만 있는 대조군은 위반 없음 — 올림 대상이 생길 때만 깨진다)
       즉 ⓑ를 채택하려면 **경계 처리 설계가 선행돼야 한다**(뒤로 늘리기 대신 앞으로 늘리기 / 인접 동일 status 이벤트에 흡수 / 이웃 구간 경계 동시 이동 등). 어느 변형이든 "겹침 불가·0초 불가·세션 구간 안" 세 제약을 동시에 만족하는지 재검증이 필요하다.
   - **ⓓ(신규 후보 — 리더 판단용): 두 함수의 임계값을 일치시킨다.** 근본 원인은 `toStatusEvents`(1초 미만 버림)와 `computeSessionTotals`(전 구간 집계)가 **서로 다른 기준**을 쓴다는 것이다. 집계 쪽도 같은 임계값을 적용해 1초 미만 구간을 주변 상태에 흡수시키면 `studySec − focusSec`이 "살아남은 비집중 시간"과 정확히 일치하게 되어, 게이트가 확률이 아니라 **정확히** 동작하고 계약 위반도 생기지 않는다. 대신 1초 미만 비집중이 순공시간으로 계산된다.
     **어느 확정 규칙과 부딪히는지 정확히 짚으면**: 직접 충돌 대상은 `mvp-scope.md` **세션 상태 모델 표**이고, **3행 중 2행이 깨진다**(세션 10초 · 문제 구간 900ms 실측):

     | 표의 규정(확정)                        | 기대               | ⓓ 실측                  |                         |
     | -------------------------------------- | ------------------ | ----------------------- | ----------------------- |
     | 비집중 → 순공 **정지** / 총 공부 진행  | study 10 / focus 9 | study 10 / **focus 10** | ❌ 비집중이 순공에 포함 |
     | 일시정지 → 순공·총 공부 **둘 다 정지** | study 9 / focus 9  | **study 10 / focus 10** | ❌ 양쪽 모두에 포함     |

     짧은 `PAUSE` 구간도 똑같이 흡수되기 때문이다. `policies.md:30` 측정 대원칙("측정할 수 **없는** 시간은 집중으로 인정하지 않는다", 2026-07-23 확정)은 _감지 불가_ 시간을 다루므로 이 케이스(감지는 됐고 기록 임계값에만 못 미친 시간)에 문자 그대로 적용되지 않는다 — **보조 근거로만 병기한다**(이걸 주근거로 들면 "감지 불가가 아니니 해당 없음"으로 반박된다). **즉 ⓓ는 "검토"가 아니라 세션 상태 모델 2개 행의 예외 승인이 있어야 채택 가능하고, 개정 대상 문서는 `mvp-scope.md`다.**
     **WG2가 채택을 제안하는 것이 아니라 선택지로 올리는 것이다 — 판단은 리더 몫.**

   - **ⓐ와 함께 거론되는 완화안(비집중 0 문구를 `focusSec == studySec`일 때만 노출)은 부분 대책일 뿐이며, 실패율이 정량화된다.** 게이트는 `floor(studyMs/1000) ≠ floor(focusMs/1000)`일 때만 반응하는데 두 값의 차이가 곧 **버려진 비집중 시간의 합 D**다. 따라서 구간 `[focusMs, focusMs+D)`가 정수 초 경계를 넘을 때만 검출되고, 검출 확률은 정확히 `D/1000`이다.

     | 버려진 비집중 합 D  | 100ms | 300ms | 500ms | 700ms | 900ms | ≥1000ms |
     | ------------------- | ----- | ----- | ----- | ----- | ----- | ------- |
     | 게이트 **미**검출률 | 90%   | 70%   | 50%   | 30%   | 10%   | 0%      |

     (qa-WG1 스윕과 spec-WG2 재현이 이론값과 소수점까지 일치.) **짧을수록 더 안 잡히는 구조**라 가장 흔한 수백 ms 케이스에서 가장 무력하다. 단, D는 **개별 구간이 아니라 버려진 구간들의 합**이므로 짧은 비집중이 여러 번이면 검출률이 올라간다(300ms×3 = 900ms → 90% 검출). 합이 1초를 넘으면 항상 검출된다.
     ⚠️ **최악의 경우는 표의 값이 아니라 100%다** — 집중 시간이 정확히 정수 초에 떨어지면(위상 0) D<1000인 한 절대 검출되지 않는다. 라운드 넘버로 짠 단위 테스트가 바로 이 위상에 걸리므로, 테스트 결과가 0%나 100% 어느 쪽으로도 치우쳐 나올 수 있다 — 이 완화안을 검증할 땐 위상을 흔들어 테스트해야 한다.
8. **가로 모드(S3-5/S3-6)의 일시정지·심플 조합은 이 문서 범위 밖**이다(WG3). 다만 가로 컨트롤 바는 218×68 · 버튼 44 · gap 20 · 핸들 28×3으로 치수가 다르다 — 세로 값을 하드코딩하지 말고 프롭으로 열어 둘 것.

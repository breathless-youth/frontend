# 소셜룸 얼굴 가림 합성 성능 비교

## 조건

| 조건      | 커밋       | 설명               |
| --------- | ---------- | ------------------ |
| 가림 없음 | `d66660b5` | 작업 전 dev        |
| 2D 캔버스 | `29421f32` | `drawImage`로 합성 |
| WebGL     | `13f71ea1` | 영상 텍스처로 합성 |

## 지표

- 보내는 영상 fps: 합성기 `fps`(초당 그린 수)와 받는 쪽 `inbound-rtp`의 `framesPerSecond`.
- 한 프레임 합성의 메인 스레드 시간: `videoMs` + `stickerMs`.
- CPU 사용률: adb `top`의 웹뷰 렌더러 프로세스.
- 발열: 20분 동안의 배터리 온도 변화와 최고 발열 단계(`dumpsys thermalservice`).
- 소비 전력: `current_now`·`voltage_now`로 계산한 20분 평균(mW). iPhone은 Performance Trace의 에너지 영향.
- 조건마다 보낸 프레임 하나당 값(전력 ÷ fps)을 함께 적는다.

## 환경 고정

- 측정 중 충전하지 않는다.
- 시작 온도를 조건마다 같게 맞춘다(직전 측정 뒤 기기를 식힌다).
- 화면 밝기, 배터리 잔량대(50~90%), 장소, 네트워크를 같게 둔다.

## 시나리오

1. Galaxy A23(보내는 쪽)과 iPhone 13 mini(받는 쪽)로 같은 소셜룸에 들어간다.
2. 보내는 쪽 카메라를 켜고 얼굴 가리기를 켠다(가림 없음 조건은 dev 빌드).
3. 정면 공부 자세로 20분 측정한다. 10분째에 1분 동안 자리를 비운다.
4. iPhone이 보내는 쪽일 때도 같은 순서로 반복한다.

## 실행

- A23: `node apps/web/scripts/perf/measure-face-mask-a23.mjs <라벨> 20`
- iPhone: 설정 > 개발자 > Performance Trace로 20분 기록 → Mac Instruments로 열어 Power Profiler 확인.

## H1 확인 (2D 캔버스가 느린 이유)

- A23 Chrome `chrome://gpu`의 Canvas 항목: 아직 확인하지 않았다.
- 기본 2D / `willReadFrequently` 2D / `ImageBitmap` 그리기 시간: 아직 재지 않았다.
- 간접 근거: 2D는 한 장에 89.0ms가 걸렸고 웹뷰 CPU가 169.8%였다. WebGL로 바꾸자 웹뷰 CPU가 100.1%로 내려갔다. 합성이 CPU에서 돌았다는 가설과 맞지만, 위 두 항목을 확인해야 확정된다.

## 실제 측정 조건 (2026-11-01, A23)

- 보내는 쪽은 Galaxy A23(무선 adb, 충전 안 함), 받는 쪽은 Galaxy Note10(카메라 켬)이었다.
- 받는 쪽도 카메라를 켰다. 소셜룸은 카메라를 끄면 일시정지로 처리되고 20분 뒤 세션이 끝나기 때문이다.
- 조건별 워크트리의 운영 빌드를 `vite preview`로 띄웠고, `reports/BY-1092/overnight/run-overnight.mjs`가 조건 전환, 재입장, 카메라 켜기, 1분마다 상태 확인, 조건 사이 식히기를 맡았다.
- 순서는 가림 없음 → WebGL → 2D였고, 조건마다 60분을 쟀다. 10분째 자리 비우기는 하지 않았다.
- 전력은 `dumpsys battery`의 잔량 카운터 차이로 구했다. A23은 sysfs 전류 파일을 셸 권한으로 읽을 수 없다. 10초마다 찍은 순간 전류 평균은 잔량 카운터보다 약 20% 낮게 나왔고, 조건 사이 순서는 같았다.
- 프레임당 mJ는 평균 전력을 합성 fps로 나눈 값이다.

### 해석과 한계

- 2D와 WebGL은 출발 온도와 장면(실제 사람)이 같아 바로 비교할 수 있다. WebGL은 60분 내내 15fps를 지켰고(14fps 미만 0회), 2D는 한 번도 15fps를 채우지 못했다. 보낸 한 장당 에너지는 42% 줄었고, 단계 4(위험) 발열이 없어졌다.
- 가림 없음과 WebGL은 장면이 달랐다(가림 없음은 Mac 화면 속 녹화 영상, WebGL은 실제 사람). 출발 온도도 1.3℃ 차이가 났다. 그래서 이 둘의 차이(전력 +12%, AP 끝 온도 +6.0℃, 단계 +1)는 WebGL만의 비용으로 단정할 수 없고, 같은 조건으로 다시 재야 한다.
- 2D는 배터리 41%에서 23%까지 내려간 상태에서 쟀다. 측정 기준(50~90%)보다 낮다.
- 받는 쪽 수신 fps(`inbound-rtp`)는 이번 측정에서 기록하지 않았다.
- iPhone 13 mini는 측정하지 않았다.

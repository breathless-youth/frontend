# 프론트엔드 코드 채점

push 승인을 요청하기 전에 다른 LLM에게 변경사항 전체를 아래 채점표로 채점받고 결과와 조치 여부를 보고한다. 어떤 LLM을 쓸지는 사용자가 선택한다 (기본: codex — `/codex review`).

채점표 (100점 만점):

| 항목 | 배점 | 채점 기준 |
|---|---|---|
| 동작 정확성 | 25 | 티켓 완료 조건과 스펙 충족. 경계 케이스와 실패 경로(네트워크 실패, 저장소 실패 등)가 의도한 방향(fail-closed 등)으로 처리되는가 |
| 테스트 품질 | 20 | 새 동작마다 테스트가 있고, 실패 경로를 커버하며, 구현 세부가 아니라 동작을 검증하는가. 테스트가 없으면 이 항목 0점 |
| 아키텍처 경계 | 15 | CLAUDE.md 경계 준수: 게이트/프레젠테이션 분리, 공유 패키지에 RN·DOM·MediaPipe·LiveKit 의존 금지, Swagger에 없는 명세를 임의로 만든 타입 금지 |
| 컨벤션 | 15 | TS strict에서 `any` 없음, `import type` 사용, Conventional Commits, lint·typecheck 통과, pnpm 고정 |
| 단순성 | 15 | 과도한 추상화·죽은 유연성·중복 구현이 없는가. 기존 헬퍼/패턴을 두고 재구현하지 않았는가 |
| UI 충실도·접근성 | 10 | 디자인 토큰과 기존 화면 관례 사용, Figma 대조(가능할 때), aria 속성 |

운영 규칙:
- 지적은 파일:라인 근거 필수. 근거 없는 지적은 감점에 반영하지 않는다.
- 합격선: 총점 85 이상이면서 모든 항목이 배점의 60% 이상. 미달이면 지적을 반영하거나
  미반영 사유를 정리해 재채점을 받고, 그 결과를 Push 승인 요청에 첨부한다.
- 채점 결과는 표(항목·점수·근거)와 필수 수정 목록으로 보고한다.
- UI 변경이 없는 작업은 "UI 충실도·접근성" 배점을 "동작 정확성"에 더해 채점한다.
- **지적 반영 시 불필요한 주석은 최소화한다** — 리뷰 지적 출처("codex 리뷰 지적" 등)를 코드 주석으로 남기지 않는다. 주석은 코드만으로 알 수 없는 제약을 설명할 때만 쓴다.
- **반영 결과는 표로 제시한다**: 수정 파일 링크(경로:라인), 수정한 부분, 수정 이유(어떤 지적에 대한 것인지)를 한 행씩 — 사용자가 에디터에서 바로 열어 확인할 수 있게 한다.
